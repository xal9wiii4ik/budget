# meta-review.md — scope `mcp-decorators`, ревью S1+S2 (`review-s1-s2.md`)

Вердикт лида: с ревью согласен по существу; все MAJOR/MINOR закрыты PM напрямую

## MAJOR-1 — 3xx от хранилища как «успех» (`upload_receipt.py`)
**Согласен, находка настоящая и единственная с потерей данных.** Мой diff-гейт её
пропустил: я отметил «3xx → "not JSON", минор» для `_fetch_json`, но не довёл ту же мысль
до PUT в хранилище, где 3xx превращается в «чек загружен» без объекта. Урок для гейта:
семантика `is_error` (4xx/5xx) ≠ `response.ok` (2xx) — проверять у КАЖДОГО статус-чека,
а не у первого. Фикс PM (`not is_success` ×2 + тест с 302, проверен мутацией) — принят.
`follow_redirects` оставить выключенным сознательно (presigned PUT, ушедший на редирект,
подписан на другой хост — следовать ему нельзя); комментарий рядом с проверкой уже есть.

## MINOR-2 — цена `mcp` как основной зависимости
**Согласен с ревьюером и с изменением решения PM.** Architecture §3.3 отвергла extra из-за
`uv run`-синхронизации — довод верный для dev-машины, но ревью показало цену для
прод-образа (второй мажор httpx, SSE-сервер, jsonschema ради процесса, который в проде
не стартует). В S3: `[project.optional-dependencies] mcp = ["mcp>=2.2,<3"]`, запуск
`uv run --frozen --extra mcp --directory … python -m budget_api.mcp`, Dockerfile без
extra + проверка сборки образа. Тесты `test_mcp_server.py`, импортирующие SDK, обязаны
жить под `pytest.importorskip("mcp")` ИЛИ dev-группа тянет extra — решить в S3 так,
чтобы общий pytest-гейт оставался сторожем (предпочтение: dev-группа включает `mcp`).
