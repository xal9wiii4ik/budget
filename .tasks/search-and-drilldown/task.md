# Scope: search-and-drilldown

Три пользовательских замечания после работы в приложении (2026-08-23). Мобилка ИСКЛЮЧЕНА (отдельная очередь).

## 1. Клик по категории → её операции
С строки категории на /categories попасть в список операций этой категории.
База — текущий месяц, с возможностью расширить диапазон.

## 2. Поиск категорий
Клиентский фильтр по названию на /categories (18 системных + пользовательские).
Серверных изменений нет.

## 3. Поиск/фильтры/сортировка операций
`GET /transactions` сегодня: `from, to, category_id, kind, account_id, limit, offset`.
Добавить: текстовый поиск (ru/en вперемешку), фильтр по `country` (поле есть с S2,
индекса и фильтра нет), выбор сортировки (дата/сумма). Минимальный UI, закрывающий
сценарии: «сколько потратил на еду в июле», «что покупал в Польше», «найти трату на 200$».

## Что УЖЕ готово и переиспользуется (рекогносцировка)
- Бэк: фильтры `category_id`/`from`/`to` есть; `from`/`to` ОБА опциональны →
  «за всё время» не требует сервера. Сортировка зашита: occurred_at desc, created_at desc, id.
- Модель: `merchant` (String 255), `note` (Text), `country` (String 2, «no filter reads it yet»),
  индекс `(user_id, occurred_at)`. SUPPORTED_CURRENCIES — все с экспонентой 2.
- Веб: URL-фильтры `?month=` (MonthPicker) + `?account=` (AccountFilter, UUID-валидация) —
  готовый паттерн для `?category=`. `TxListFilters` УЖЕ несёт опциональные `category_id`/`kind`
  (данные-в-ключе). Экспорт написан «на вырост»: ExportFilters = Omit<TxListFilters,'limit'>.
- Категории на вебе: единый archived-inclusive кэш, системные имена переводятся в
  `useCategories.select` → клиентский поиск фильтрует уже ПЕРЕВЕДЁННЫЕ имена.
- mcp-server: `list_transactions` в `packages/mcp-server/src/allowlist.ts` с кураторскими
  описаниями параметров; дрифт-тесты в allowlist.test.ts. Контракт имеет 4 потребителей
  (web, mobile-frozen, api-client, mcp-server) — политика 2026-08-23.
- Селект страны: логика Intl.DisplayNames живёт в TransactionFormModal — переиспользовать
  построение опций для фильтра.

## Разбиение
- S1 `category-drilldown` — web-only, STANDARD. Стартует сразу.
- S2 `category-search` — web-only, FAST. Стартует сразу, параллельно S1.
- S3 `tx-filters-search-sort` — api + контракт + web, FULL (смена API-контракта → по таблице тиров).
  Бэк первым; веб может планировать против контракта из плана.

Ограничения: QA ≤ 12–15 сценариев на скоуп; полный live-QA — один раз в конце скоупа
(mid-scope только STOP-пробы, но интеграционных границ тут нет — вся работа внутри
имеющихся швов, STOP-пробы не требуются).
