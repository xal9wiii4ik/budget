## The `.mjs`-import-under-tsc problem — chosen solution (SOLVED IN PLAN)

**Problem.** `src/drift.test.ts` lives under `include: ["src"]`, so it is in the
`tsc --noEmit` program and the `vitest --typecheck` program. It must import the
*same* `generateSchema()` that the `generate` script runs — which architecture D3/D5
pins as `scripts/generate.mjs` (plain JS, run by plain `node`, no build step).
`scripts/` is outside `include`, and `tsconfig.base.json` has `allowJs: false`, so
tsc resolving `import { generateSchema } from "../scripts/generate.mjs"` finds no
declaration and errors.

**Options evaluated:**

| Option | Verdict |
| --- | --- |
| **A. Co-located ambient declaration `scripts/generate.d.mts`** | **CHOSEN.** tsc/vites-typecheck resolve the `.mjs` import to the adjacent `.d.mts` (declaration files for imported modules are resolved regardless of `include`; with `allowJs:false` the `.mjs` itself is never added to the program, so it is never typechecked — exactly what we want for a node-only script). `generate` stays `node scripts/generate.mjs` (plain node, no build). The shared writer/checker function survives verbatim. This is the standard "ship a `.d.ts` next to untyped JS" pattern and is fully compatible with binding D3/D5. |
| B. Convert wrapper to `.mts` run via `node --experimental-strip-types`/`tsx` | Rejected. Deviates from binding D3/D5 (`generate.mjs`, `node scripts/generate.mjs`); relies on an experimental flag on Node 22 (repo `engines: >=22`) or adds `tsx` (a tool not in the project). Fragile for zero benefit. |
| C. vitest-only alias | Rejected. An alias fixes vitest runtime resolution only. The failure is in the `tsc --noEmit` **typecheck** task (and vitest's own typecheck pass), which does not read vitest aliases. Insufficient. |
| D. Move the shared function into `src/` (typed), leave `scripts/` a shim | Rejected. To be typechecked in `src/` the function must be a `.ts` file; the `scripts/` shim run by plain `node` then has to import a `.ts` module — impossible without a build step or `--experimental-strip-types`, violating the "plain node, no build step" constraint. D re-creates problem B from the other end. |

**Chosen: A.** `scripts/generate.d.mts` declares exactly:

```ts
export function generateSchema(): Promise<string>;
```

Risk: hand-written declaration can drift from `generate.mjs`. Mitigation — the
module's entire public surface is this one function; keep it that way. (If it ever
grows, revisit D via a build.)

### F2 — `packages/api-client/scripts/generate.mjs` (new)
Plain ESM JS (`type: module` already set), Node APIs only. Shape:

```js
import { readFileSync, writeFileSync } from "node:fs";
import openapiTS, { astToString } from "openapi-typescript";

const SCHEMA_URL = new URL("../../../apps/api/openapi.json", import.meta.url); // repo-root/apps/api/openapi.json
const OUT_URL    = new URL("../src/generated/schema.d.ts", import.meta.url);
const HEADER = `/**\n * AUTO-GENERATED by \`pnpm openapi\`. DO NOT EDIT BY HAND.\n * Source: apps/api/openapi.json\n */\n`;

export async function generateSchema() {
  const ast = await openapiTS(SCHEMA_URL);      // reads local file:// URL, resolves $refs, no network
  return HEADER + "\n" + astToString(ast);      // fixed, byte-stable composition (shared writer+checker)
}

// script mode: write the file
if (import.meta.url === `file://${process.argv[1]}`) {
  writeFileSync(OUT_URL, await generateSchema());
}
```

Notes for reviewer:
- The relative schema path is **three** `../` from `scripts/generate.mjs`
  (`scripts/` → `api-client/` → `packages/` → repo root). Resolved via
  `import.meta.url`, so it is cwd-independent (drift test and CLI agree).
- `generateSchema()` is the single source of bytes: the CLI writer and the drift
  checker both call it → they cannot disagree (mirrors the Python canonical
  serializer, D1/D4).
- The returned string (header + trailing-newline'd AST) is written *as-is*; drift
  compares committed-file bytes to this string.
- Uses `openapi-typescript` **Node API** (`openapiTS` + `astToString`), not the CLI
  (D3).

### F5 — `packages/api-client/src/contract.test.ts` + `src/drift.test.ts`
`contract.test.ts` (type-level, the executable form of amendment A5):
```ts
import { describe, it, expectTypeOf } from "vitest";
import type { paths } from "./generated/schema";

type Health200 = paths["/health"]["get"]["responses"][200]["content"]["application/json"];
type Health503 = paths["/health"]["get"]["responses"][503]["content"]["application/json"];
type Shape = { status: "ok" | "degraded"; database: "ok" | "unavailable" };

describe("GET /health contract", () => {
  it("declares both 200 and 503 with the HealthResponse shape", () => {
    expectTypeOf<Health200>().toEqualTypeOf<Shape>();
    expectTypeOf<Health503>().toEqualTypeOf<Shape>();
  });
});
```
Non-vacuous because the drift tests only prove code→schema→TS *consistency*; deleting
the A5 `503` declaration and regenerating leaves every drift check green — only this
test goes red. (The `[200]`/`[503]` index access itself fails to compile if either
status is absent, which is the pin.)

`drift.test.ts` (runtime, edge-2 D4):
```ts
import { describe, it, expect } from "vitest";
import { readFileSync } from "node:fs";
import { generateSchema } from "../scripts/generate.mjs";

describe("generated client is not stale", () => {
  it("matches a fresh regeneration of apps/api/openapi.json", async () => {
    const committed = readFileSync(new URL("./generated/schema.d.ts", import.meta.url), "utf8");
    const fresh = await generateSchema();

```
Failure message (via `expect(...).toBe` custom message or a wrapping assertion):
"schema.d.ts is out of date — run `pnpm openapi` and commit apps/api/openapi.json +
packages/api-client/src/generated/schema.d.ts".

### F6 — `packages/api-client/vitest.config.ts` (new; required for `--typecheck` to see the type test)
Reason: with `--typecheck`, vitest's typecheck project defaults to
`typecheck.include = ['**/*.{test,spec}-d.?(c|m)[jt]s?(x)']` — i.e. only `*.test-d.ts`
files. `contract.test.ts` would therefore run only at *runtime*, where `expectTypeOf`
is a **no-op** and can never fail. To keep the architect's named artifact
`contract.test.ts` and still have its assertions gate the run, add:
```ts
import { defineConfig } from "vitest/config";
export default defineConfig({
  test: {
    include: ["src/**/*.test.ts"],
    typecheck: {
      enabled: true,
      tsconfig: "./tsconfig.json",
      include: ["src/**/*.test.ts"],
    },
  },
});
```
This makes `contract.test.ts` a typecheck source (assertions checked by tsc) while
`drift.test.ts` remains a runtime test (and also typechecks cleanly). See Open
Question 1 for the zero-config `*.test-d.ts` alternative.

## tsconfig — does `include: ["src"]` change? No.

- `src/generated/schema.d.ts` is under `src`, already covered. **No tsconfig edit.**
- **`skipLibCheck: true` nuance (senior point 3):** with `skipLibCheck` on, tsc does
  *not* error-check the internal contents of `.d.ts` files — including
  `schema.d.ts`. So "the generated file passes `tsc --noEmit`" is guaranteed almost
  by construction (its declarations aren't internally validated), while its types are
  still fully **resolved and consumed** by `client.ts`, `index.ts`, and
  `contract.test.ts`. The real correctness gate on the generated shapes is therefore
  the type-level `contract.test.ts` (which is a `.test.ts`, not a `.d.ts`, so it is
  NOT skipped), plus the drift test. Syntax errors in the generated file would still
  fail tsc; `openapi-typescript` emits valid syntax. Net: `include: ["src"]` is
  correct and unchanged.
- `scripts/` stays outside `include`; `generate.mjs` is never typechecked (desired,
  it's a node script); `scripts/generate.d.mts` is pulled in only via import
  resolution to type the drift test.

## Acceptance criteria (exact commands + expected outcomes)

Positive (all green):
1. `pnpm --filter @budget/api-client typecheck` → passes (drift test's `.mjs`
   import resolves via `generate.d.mts`; generated file consumed; no `any`/`as`).
2. `pnpm --filter @budget/api-client lint` → passes (generated file ignored by
   root config; scripts lint clean).
3. `pnpm --filter @budget/api-client test` → passes; runs both the runtime drift
   test and the typecheck project containing `contract.test.ts`.
4. Idempotency: `pnpm openapi` twice in a row → `git status` clean (no diff on the
   second run). D1/D2 determinism.

Negative (must FAIL — proves the tests aren't vacuous; verified during
implementation, then reverted):
5. **Drift edge:** perturb `apps/api/openapi.json` (e.g. add a description or a
   field on a scratch copy) WITHOUT regenerating → `pnpm --filter @budget/api-client
   test` fails in `drift.test.ts` with the "run `pnpm openapi`" message.
6. **Contract 503:** on a scratch copy of `src/generated/schema.d.ts`, delete the
   `503` entry from `paths["/health"]["get"]["responses"]` →
   `pnpm --filter @budget/api-client typecheck` and `... test --typecheck` fail in
   `contract.test.ts` (the `[503]` index access / `expectTypeOf` no longer compiles).
   Confirms the contract test pins A5 independently of drift.
7. **`--typecheck` actually bites:** temporarily change a `contract.test.ts`
   assertion to a wrong shape (e.g. `status: "ok"` only) → `pnpm ... test` reports a
   FAILED typecheck test (not a silent pass). This is the explicit verification that
   `expectTypeOf` failures fail the `test` task; revert after confirming. If for any
   reason vitest's typecheck does not flag it, the fallback gate is
   `pnpm ... typecheck` (`tsc --noEmit`), which fails on the same file regardless.

## Risks
- **`vitest run --typecheck` unproven in this repo.** Mitigation: acceptance
  criterion 7 verifies it bites by deliberately breaking an assertion; fallback gate
  is `tsc --noEmit` which fails on the same contract file. (Architecture risk log
  agrees.)
- **Hand-written `generate.d.mts` drifts from `generate.mjs`.** Mitigation: keep the
  module's public surface to the single `generateSchema()` export.
- **`openapi-typescript` output formatting changes on version bump** → drift test
  goes red on the bump PR (designed behavior; regenerate in the same commit). Exact
  pin prevents floating-version surprise.
- **`components["schemas"]["HealthResponse"]` name assumption.** If FastAPI/generator
  names the schema differently, the `HealthResponse` alias in `index.ts` fails to
  compile — caught immediately by `typecheck`; adjust the alias to the emitted name
  (verify against generated `schema.d.ts`, do not hand-edit the generated file).
- **eslint on `.d.mts`** (Cross-slice dep 2) — flagged; low risk.
- **Sequencing:** `apps/api/openapi.json` must land first (B1/B2). If not present,
  block and report — never mock the schema.
