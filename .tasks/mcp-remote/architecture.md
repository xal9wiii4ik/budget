# Architecture Plan: mcp-remote — Claude connector over OAuth (PLAN 5.6b)

## Context
The stdio MCP server is a local process fed a PAT. The brief wants `https://<SITE_DOMAIN>/mcp` usable from claude.ai / Desktop / mobile / Claude Code, with per-user consent and a mode (`read` | `full`), while the stdio path, the PAT allowlist, the audit log and the no-oracle rules stay exactly as they are. The architectural question is therefore not "how to do OAuth" (the installed `mcp` 2.2 SDK ships the AS handlers) but **how an OAuth-issued credential becomes a `PatContext` so that the ONE enforcement pipeline (`pat_auth` → allowlist → scope → audit) runs unchanged**, and how the URL topology (Caddy → nginx → api, `/api/` prefix) is expressed to a client that discovers everything from two well-known documents.

## Decisions (each with the alternative rejected)
1. **In the API process, one container.** `mcp` moves from `[project.optional-dependencies]` to `dependencies`; the `mcp = ["mcp>=2.2,<3"]` extra STAYS as a no-op alias so the documented launch line `uv run --frozen --extra mcp … python -m budget_api.mcp` (and the owner's existing Claude Desktop config) keep working; the dev group drops its `budget-api[mcp]` self-reference. Dockerfile unchanged (`uv sync --frozen --no-dev` now picks the SDK up). Rejected: separate container — needs an AS↔RS introspection contract, a second DB client, more RAM on a 3.8 GB VPS, for zero isolation gain (the AS needs the users table anyway).
2. **Transport: `StreamableHTTPSessionManager(stateless=True, json_response=True)`**, mounted as `Route("/mcp", endpoint=<ASGI chain>, methods=["GET","POST","DELETE"])`. A Starlette `Route` with an ASGI-callable endpoint is served raw (no `request_response` wrapping) and matches `/mcp` exactly — a `Mount("/mcp")` compiles to `^/mcp/…` and the router's `redirect_slashes` would 307 `/mcp` → `/mcp/`, which is precisely the "Authorization dropped on redirect" failure in the troubleshooting doc. `mcp/exposure.py` needs NO change: `Route` is already its second branch, an ASGI object has no marker (`exposure_of` → None), so the three `/mcp` pairs appear in `walk()` and never in `collect()`; the `TypeError` stays as the tripwire against a `Mount` sneaking in. `TransportSecuritySettings` left at the SDK default (host validation off): DNS rebinding targets plaintext localhost servers; ours is a TLS host behind Caddy and the credential is a bearer a browser cannot attach cross-site. The chain is SDK-standard: `AuthenticationMiddleware(BearerAuthBackend(verifier, resource_server_url=<resource>))` → `RequireAuthMiddleware(required_scopes=[], resource_metadata_url=<PRM url>)` → `StreamableHTTPASGIApp` — it emits the exact `401` + `WWW-Authenticate: Bearer error="invalid_token", …, resource_metadata="…"` Claude requires, for a missing, expired or revoked token alike (Claude refreshes on 401).
3. **Grants are rows in `personal_access_tokens`** (shape a). A consent produces a row with `token_hash NULL`, `oauth_client_id` set, `name` = the client's self-declared name snapshot, `scope` = the mode the user picked. Access/refresh tokens live in their own tables keyed by that row. `pat_auth` grows a second bearer prefix and resolves it to the SAME `PatContext(id=grant.id, user_id, scope)` — rate limit, allowlist, scope gate, `last_used_at`, and `pat_audit_log.token_id` FK all work with zero code in `pat_audit.py`. Rejected (b): a separate `oauth_grants` table forces a second nullable FK + CHECK on the audit table, a `kind` on `PatContext`, and a branch in the audit middleware — three places that can disagree. **Decided otherwise vs the lean: the grant is created at CODE EXCHANGE, not at consent.** The consent decision mints only the authorization code (carrying user, mode, client, challenge); `exchange_authorization_code` inserts the grant + first access/refresh pair in one transaction. Reason: a consent whose code is never exchanged (closed tab, Claude timeout) would otherwise leave an orphan "connected app" in Settings. Refresh family = the grant: reuse of a consumed refresh token revokes the grant (`revoked_at`), so no `family` column exists. Replay of a consumed authorization code revokes the grant it produced (RFC 6749 §4.1.2), symmetric with refresh reuse.
4. **Tool execution = an in-process HTTP call through `httpx.ASGITransport(app, raise_app_exceptions=False)`** with `Authorization: Bearer <caller's OAuth access token>`, reusing `mcp/http.py::call_tool` untouched. The audit row, the 429, the 403s and the 404 bodies are produced by the real request path. Pitfalls, all benign: no lifespan runs (the app is already up, `app.state.*` present); `scope["client"]` is httpx's fake `127.0.0.1` and uvicorn's proxy-headers layer sits OUTSIDE the app so `X-Forwarded-For` is not applied — irrelevant because no tool route is IP-limited (PAT limits key on `PatContext.id`); responses are buffered (no tool streams; `/transactions/export` is `# MCP: no`); `raise_app_exceptions=False` is mandatory so an inner 500 becomes `describe_api_error` text instead of an exception inside the JSON-RPC handler; the verifier's DB session is closed before the tool call, so the nested request never nests sessions. ONE `AsyncClient` is built in the lifespan and closed on shutdown. Rejected: loopback `http://127.0.0.1:8000` — a socket per call, a port the app must know, and with `--forwarded-allow-ips='*'` an inner request could forge `X-Forwarded-For`. `on_list_tools` filters per request via the existing `tools_for_scope` (read → 20, full → 35); `upload_receipt` is never offered remotely. The caller's identity reaches the handler through `ServerRequestContext.request` — the SDK attaches the Starlette `Request` to every streamable-HTTP message, and `request.scope["user"]` is the `AuthenticatedUser` whose `.access_token.token` is the raw bearer. No contextvar needed.
5. **URLs: one setting `public_base_url: str = ""`** (a `str` with a validator — scheme http/https, no path, trailing slash stripped — NEVER `AnyHttpUrl`, which renders `https://x/`). Empty = the Starlette OAuth/MCP routes are not registered (dev, pytest, openapi export). Derived in `oauth/urls.py`: issuer = base; resource = `{base}/mcp`; authorize/token/register = `{base}/api/oauth/{authorize,token,register}`; consent = `{base}/oauth/consent?req=`; PRM = `{base}/.well-known/oauth-protected-resource/mcp`. **Issuer has no path**: RFC 8414 lets endpoints live anywhere, while a path-ful issuer (`{base}/api`) needs path-inserted discovery (`/.well-known/oauth-authorization-server/api`), which Claude's docs promise only for the PRM document — riskier for nothing. Metadata is built by us (`OAuthMetadata(...)` + the SDK's `MetadataHandler`), not by `create_auth_routes`/`build_metadata`, whose fixed root paths do not fit the nginx topology. PRM is served at BOTH `/.well-known/oauth-protected-resource/mcp` (tried first) and `/.well-known/oauth-protected-resource`. Internal API paths stay `/oauth/…`; the public `/api/` prefix is the existing nginx `location /api/`. nginx adds only `location = /mcp` and `location /.well-known/oauth-` → `api:8000`.
6. **Consent flow.** `provider.authorize()` requires an explicit `redirect_uri` (`invalid_request` otherwise), validates `resource` if present (must equal the canonical resource, else `invalid_target`), prunes expired pending rows, inserts `oauth_authorization_requests` and returns `{base}/oauth/consent?req=<id>`. SPA: `/oauth/consent` sits under the auth guard (`ProtectedLayout` already redirects to `/login?next=<pathname+search>` url-encoded, so the `req` survives login) → `GET /oauth/requests/{id}` → renders client name (React-escaped, labelled "name declared by the app itself"), redirect host, loopback warning when the host is loopback, mode radio (read-only / full), Allow / Deny → `POST /oauth/requests/{id}/decision` → `{redirect_to}` → `window.location.replace(redirect_to)`. The server composes `redirect_to` from the STORED redirect_uri (never from the client), `construct_redirect_uri(uri, code=…, state=…)` or `error=access_denied&state=…`. Consumption is `UPDATE … SET consumed_at=now() WHERE id=:id AND consumed_at IS NULL AND expires_at > now() RETURNING` — single-use under a race. **Decided otherwise: the pending id is a `uuid4` PK**, not a 256-bit opaque: it is not a credential (holding it shows a client name and lets the HOLDER decide for the holder's own account — the decision binds to the logged-in user, never to the request), 122 random bits make guessing moot, and every other table is uuid-keyed. CSRF: none by construction (bearer in localStorage, no cookies — docs/deploy.md). Clickjacking: `X-Frame-Options: DENY` + `Content-Security-Policy: frame-ancestors 'none'` added in nginx on `location = /index.html` (the block the SPA fallback internally redirects to; nginx `add_header` does not inherit into a block that has its own). All four FastAPI routes are JWT-only (`current_active_user`), carry `# MCP: no — escalation surface`, and join `NEVER_PAT`.
7. **DCR hardening** (`provider.register_client`, pure checks in `oauth/clients.py`): `redirect_uris` 1..10, each EXACTLY `https://claude.ai/api/mcp/auth_callback` or loopback `http://localhost|127.0.0.1|[::1][:port]/…`; `response_types == ["code"]`; `grant_types ⊆ {authorization_code, refresh_token}`; `client_name ≤ 100`; each URI ≤ 2 KB; request body capped at 16 KiB by our own `RequestBodyLimitMiddleware` (the SDK's 4 MiB is for `/mcp`); per-IP `oauth_register_rate_limit = "30/hour"` (raised from 10 at meta-review #3 — the bucket is per deployment behind Anthropic's shared egress) via the same `limiter.limiter.hit` mechanism as `_enforce_rate_limit` (key `{scope}:oauth-register:{ip}`), 429 house envelope. **Decided otherwise: `token_endpoint_auth_method` must be `none`** (public clients only; a missing value — which the SDK defaults to `client_secret_post` — is refused with `invalid_client_metadata`). Reasons: Claude's docs say DCR/CIMD register Claude as a public client; PKCE is the binding; a secret handed to an anonymous registrant protects nothing; and the SDK's `ClientAuthenticator` compares `client.client_secret` in PLAINTEXT, so accepting secrets would mean storing one unhashed — against "everything stored hashed". No `client_uri/logo_uri/tos_uri/policy_uri` are stored (phishing surface on the consent page); no `/revoke` endpoint (not advertised, revocation is Settings). **Loopback match: a `BudgetClient(OAuthClientInformationFull)` subclass overriding `validate_redirect_uri`** — the SDK handler calls that method BEFORE `provider.authorize` (and again in its error path), so normalising inside `authorize` would be too late. `validate_scope` is also overridden to accept anything: the wire `scope` is advisory, the mode is decided at consent. Orphan-client prune: DEFERRED — `created_at` column + an SQL one-liner in `apps/api/MCP.md`, no job. **CIMD: NO** — DCR covers every Claude surface; CIMD means fetching an arbitrary https URL inside `/authorize` (SSRF surface needing the `push_endpoint` guard plus a 10 s budget), and the "too many DCR clients" concern is a directory-scale problem, not a single-domain app's.
8. **Lifetimes:** pending request 600 s; authorization code 60 s; access token 3600 s (Claude refreshes 5 min early → a 1 h token is refreshed ~11×/day, cheap); refresh token 30 d SLIDING (new row, `expires_at = now + 30 d` on each rotation; same figure as the web session's `refresh_token_lifetime_seconds`). **No absolute cap** (decided otherwise): PATs have none, and a connector someone uses daily must not silently die on day 90 with "Authorization failed" as the only symptom; the 30-day idle cut kills abandoned connections and Settings → Revoke is the kill switch. If the lead wants a cap it is one nullable `expires_at` on the grant row and one predicate in `resolve_access_token`.
9. **Audit / rate limits: nothing extra.** Every tool call is a real request under `PatContext.id = grant.id`, so `pat_audit_log` rows, `60/min` read and `20/min` write budgets and the debounced `last_used_at` apply per grant. `tools/list` is not audited (same as stdio). The OAuth endpoints themselves are pre-grant and get per-IP limits only (`oauth_endpoint_rate_limit = "60/minute"` on authorize and token, register as above).
10. **Logging rule for all new code:** log identifiers only (`client_id`, grant id, request id) — never a token, code, verifier, challenge, `state`, or the `Authorization`/form body; `oauth/` modules raise `TokenError/AuthorizeError` with generic descriptions. Accepted exposure: uvicorn's access line shows the `/oauth/authorize` query (challenge = a hash, `state` = a client nonce) and `?req=` (one-time, 10 min); the token endpoint is a form POST, so its body never reaches any log; the SDK logs only the `resource` string on an audience mismatch.

## Database changes — migration `0016_oauth_connector`
### Tables
- `oauth_clients`: `id` (PK uuid — the SDK mints `client_id = str(uuid4())`; a non-uuid `client_id` is answered "unknown" without a query) · `client_name` String(100) null · `redirect_uris` JSONB (list of str) · `created_at` tstz default now().
- `personal_access_tokens` (ALTER): `token_hash` → nullable (the UNIQUE index tolerates NULLs); `+ oauth_client_id` uuid null FK → `oauth_clients.id` ON DELETE RESTRICT (a client with grants can never be pruned from under its audit history); `+ CHECK ck_personal_access_tokens_credential ((token_hash IS NULL) <> (oauth_client_id IS NULL))` — exactly one credential kind per row. Model: `token_hash: Mapped[str | None]`, constraint name byte-identical (`alembic check`).
- `oauth_authorization_requests`: `id` (PK uuid4) · `client_id` FK → `oauth_clients` CASCADE · `redirect_uri` Text · `code_challenge` String(128) · `state` Text null (cap 2 KB at the provider — senior-lead ruling R2; longer → `invalid_request`) · `resource` Text null · `created_at` · `expires_at` tstz · `consumed_at` tstz null. Index `(expires_at)` for the lazy prune.
- `oauth_authorization_codes`: `id` (PK uuid) · `code_hash` String(64) UNIQUE · `user_id` FK → `users` CASCADE · `client_id` FK → `oauth_clients` CASCADE · `scope` String(32) CHECK read|full (same enum-built SQL as PATs) · `redirect_uri` Text · `code_challenge` String(128) · `resource` Text null · `expires_at` · `used_at` tstz null · `grant_id` uuid null FK → `personal_access_tokens` CASCADE (filled at exchange; what a replay revokes).
- `oauth_access_tokens`: `id` (PK uuid) · `grant_id` FK → `personal_access_tokens` CASCADE · `token_hash` String(64) UNIQUE · `created_at` · `expires_at`. Index `(grant_id)`.
- `oauth_refresh_tokens`: `id` (PK uuid) · `grant_id` FK CASCADE · `token_hash` String(64) UNIQUE · `created_at` · `expires_at` · `used_at` tstz null · `replaced_by_id` uuid null FK self. Index `(grant_id)`.
### Migration steps
1. create `oauth_clients`; 2. alter `personal_access_tokens` (nullable hash, FK column, CHECK); 3–6. create requests / codes / access / refresh tables with the indexes above. Pure DDL, no backfill. **Downgrade (symmetric):** drop 6→3; `DELETE FROM personal_access_tokens WHERE oauth_client_id IS NOT NULL` (audit rows cascade — stated, deliberate), drop CHECK + column, `token_hash` back to NOT NULL; drop `oauth_clients`. Expired rows of requests/codes/access/refresh are pruned LAZILY (one `DELETE … WHERE expires_at < now()` at the matching provider call), the `statement_import_ttl_days` precedent — no scheduler job.

## Module structure
New package `apps/api/src/budget_api/oauth/` (framework glue beside `pat_auth.py`, not `services/`):
- `urls.py` — pure: `PublicUrls.from_settings(settings)` (issuer, resource, the three endpoints, consent, PRM) or `None` when `public_base_url` is empty.
- `clients.py` — pure: `redirect_uri_allowed(uri)`, `is_loopback(uri)`, DCR caps, `BudgetClient` (the `validate_redirect_uri` / `validate_scope` overrides; the loopback compare ignores ONLY the port — scheme, host and path must match a registered loopback URI).
- `tokens.py` — prefixes `bgt_oat_` (access), `bgt_ort_` (refresh), `bgt_oac_` (code), `mint()`/`hash_token` reuse, and `resolve_access_token(session, raw) -> (PersonalAccessToken, User) | None` — ONE query joining access token (not expired) → grant (`revoked_at IS NULL`, `oauth_client_id IS NOT NULL`) → active user. Imports models only (no `pat_auth` → no cycle).
- `provider.py` — `BudgetOAuthProvider(OAuthAuthorizationServerProvider)` over `app.state.sessionmaker`: `get_client`, `register_client` (D7), `authorize` (D6), `load_authorization_code`/`exchange_authorization_code` (grant + first pair in one tx; replay → revoke), `load_refresh_token`/`exchange_refresh_token` (rotate: mark old `used_at`, insert new, sliding expiry; reuse → revoke grant → `None` → SDK answers `invalid_grant`), `load_access_token` (→ `AccessToken(token, client_id, scopes=[mode], expires_at, resource=<ours>, subject=user_id)`), `revoke_token` no-op.
- `consent.py` — `read_request(session, id)` and `decide(session, id, user, decision, scope) -> redirect_to` (the UPDATE…RETURNING consumption, code mint, `construct_redirect_uri`).
- `routes.py` — `oauth_routes(app, settings) -> list[Route]`: AS metadata, PRM ×2, `/oauth/authorize`, `/oauth/token`, `/oauth/register` (SDK handlers `AuthorizationHandler`, `TokenHandler(provider, ClientAuthenticator(provider))`, `RegistrationHandler(provider, ClientRegistrationOptions(enabled=True))` wrapped by our body cap + per-IP limiter), and the `/mcp` route from `mcp/remote.py`. No CORS wrappers (Claude's clients are not browsers; MCP Inspector support is not a requirement).
- `routers/oauth.py` (FastAPI, in the contract) — the four JWT-only routes below.
Under `mcp/`:
- `server.py` — `build_server(tools, *, credential: Callable[[ServerRequestContext], ToolCredential | None], upload)` where `ToolCredential = (client, ApiConfig, scope)`; `on_list_tools` filters by the credential's scope per request; stdio's `serve()` passes a constant credential (so `tests/test_mcp_server.py` changes only its call sites). Tool table building stays in `tools.py`.
- `remote.py` — `build_remote(app, urls) -> (Server, StreamableHTTPSessionManager)`: tools from THE RUNNING APP (`parse_document(json.loads(openapi_json(app)))` + `tool_specs(app)` — same bytes as the committed contract, no second app instance), credential = `ctx.request.scope["user"]`, the ASGITransport client on `app.state`, `manager.run()` entered in the lifespan.
Existing files, what changes: `pat_auth.py` — `_pat_from_request` accepts both prefixes; the branch dispatches on prefix to the PAT hash lookup or `oauth.tokens.resolve_access_token`; everything after the `PatContext` stash is untouched (5-line fragment: `if raw.startswith(OAT_PREFIX): resolved = await resolve_access_token(session, raw) else: resolved = <existing query>`). `pat_audit.py` — no change. `mcp/exposure.py` — no change (D2). `app.py` — append `oauth_routes(app, resolved)` BEFORE the `pat_allowlist` line when `PublicUrls` is not None; lifespan enters `manager.run()` and builds/closes the ASGITransport client. `config.py` — `public_base_url`, `oauth_access_token_lifetime_seconds=3600`, `oauth_refresh_token_lifetime_seconds=2_592_000`, `oauth_authorization_code_lifetime_seconds=60`, `oauth_request_lifetime_seconds=600`, `oauth_register_rate_limit="30/hour"` (meta-review #3), `oauth_endpoint_rate_limit="60/minute"` (lifetimes as fields so tests shrink them — the `access_token_lifetime_seconds` precedent). `routers/tokens.py` — list and revoke add `oauth_client_id IS NULL` (a grant id on `DELETE /tokens/{id}` → the same 404; a PAT id on `DELETE /oauth/apps/{id}` → the same 404 — no cross-listing). `models/personal_access_token.py` + four new model modules, registered in `models/__init__.py`. `pyproject.toml` — D1. `Dockerfile` — none. `apps/web/nginx.conf` — the two locations (`proxy_http_version 1.1`, `proxy_set_header Connection ""`, `proxy_buffering off`, `proxy_read_timeout 300s`, `client_max_body_size 4m`, no `sub_filter`) + the two anti-framing headers on `location = /index.html`. `docker-compose.prod.yml` — api env `PUBLIC_BASE_URL: ${PUBLIC_BASE_URL:-https://${SITE_DOMAIN}}`. `.env.prod.example` — a comment only (derived, nothing to set; the QA stand's scratch env sets `PUBLIC_BASE_URL=https://localhost:8443` because compose cannot know the port). `docker-compose.yml`, `.env` — untouched (no `PUBLIC_BASE_URL` → remote off; the shared nginx image's new locations proxy to a 404). Web: route `/oauth/consent` + `features/oauth/ConsentPage`, Settings section `ConnectedAppsSection` (`data/oauthApps.ts`, new disjoint key root `['oauth-apps','list']`), RU+EN keys.

The `/mcp` route's inner call uses internal paths (`/transactions`, …) with `base_url="http://budget.internal"` — the host is a placeholder for ASGITransport, never resolved.

Metadata the server publishes (the one dict worth spelling out):
```
issuer=base · authorization_endpoint=base/api/oauth/authorize · token_endpoint=base/api/oauth/token
registration_endpoint=base/api/oauth/register · response_types_supported=["code"]
grant_types_supported=["authorization_code","refresh_token"] · token_endpoint_auth_methods_supported=["none"]
code_challenge_methods_supported=["S256"]   # no scopes_supported, no CIMD flag, no revocation_endpoint
```
PRM: `resource=base/mcp`, `authorization_servers=[base]`, `bearer_methods_supported=["header"]`, NO `scopes_supported` — Claude then sends no `scope`, and the token response's `scope` carries the mode the user chose (an AS may narrow). Token response: `access_token, token_type=Bearer, expires_in=3600, scope=<mode>, refresh_token`.

## Contract (openapi.json + schema.d.ts, one commit)
FastAPI, tag `oauth`, all `current_active_user` (JWT-only), all `# MCP: no — escalation surface`, four new `NEVER_PAT` pairs:
- `GET /oauth/requests/{request_id}` → `OAuthRequestRead {client_name: str|null, redirect_host: str, loopback: bool, expires_at}`; 404 `OAUTH_REQUEST_NOT_FOUND` (unknown, expired, consumed — one path). Not user-bound: whoever is logged in decides for themselves.
- `POST /oauth/requests/{request_id}/decision` body `OAuthDecision {decision: "allow"|"deny", scope: PatScope}` → `OAuthDecisionResult {redirect_to: str}`; 404 as above; 422 schema only.
- `GET /oauth/apps` → `OAuthAppList {items: [OAuthAppRead {id, client_name, scope, created_at, last_used_at, revoked_at}]}` — grants only, revoked rows included (the `/tokens` precedent: a revocation is a fact; the web dims them).
- `DELETE /oauth/apps/{grant_id}` → 204; 404 `OAUTH_APP_NOT_FOUND` (foreign, missing, already revoked, or a plain-PAT id — one path). Revocation is immediate: every acceptance path joins `revoked_at IS NULL`.
Deliberately NOT in the contract (Starlette routes, not FastAPI): `/mcp`, `/oauth/{authorize,token,register}`, `/.well-known/oauth-authorization-server`, `/.well-known/oauth-protected-resource[/mcp]` — their shapes are the RFCs', consumed by Claude, never by web/mobile/api-client. The md5 pin of `openapi.json` in `tests/test_mcp_server.py` changes; update it consciously.

## Dependency direction
`routers/oauth.py` → `oauth/consent.py` → `models`; `pat_auth.py` → `oauth/tokens.py` → `models` (tokens never imports `pat_auth`); `app.py` → `oauth/routes.py` → `oauth/provider.py`, `mcp/remote.py` → `mcp/{server,http,tools,exposure}`; `oauth/urls.py`, `oauth/clients.py` are pure; `config.py` still imports nothing internal; `domain/` untouched. No reverse edge: nothing under `oauth/` or `mcp/` imports a router.

## Security checklist → mechanism
- redirect_uri tampering / open redirect: DCR allowlist (D7) + exact-or-loopback match in `BudgetClient.validate_redirect_uri` before `authorize` + the SDK's token-endpoint re-check + `redirect_to` built from the STORED request row, the SPA never composes a URL.
- PKCE downgrade: the SDK's `AuthorizationRequest` is `code_challenge_method: Literal["S256"]` (`plain` → 400) and `code_verifier` is required at `/token`; the challenge is stored on the code row and compared by the SDK.
- Code replay: `used_at` set under UPDATE…RETURNING; replay → `invalid_grant` AND the produced grant is revoked.
- Refresh reuse: `used_at` on the refresh row; reuse → grant revoked → `invalid_grant` (RFC 6749 code, as Claude requires).
- CSRF on consent: no cookies anywhere (bearer in localStorage) — no cookie CSRF surface; stated in docs/deploy.md already.
- Clickjacking: `X-Frame-Options: DENY` + `frame-ancestors 'none'` on `index.html` (nginx).
- Token leakage in logs: D10; only SHA-256 hashes are stored; tokens carry greppable prefixes.
- Scope escalation read→full: the mode lives on the GRANT row; the wire `scope` (authorize, DCR, refresh) is ignored; writes are gated by METHOD in `pat_auth`; a refresh asking for a wider scope is refused by the SDK (`invalid_scope`) and ignored by us anyway.
- Revoked token accepted anywhere: ONE resolver (`resolve_access_token`) used by both `pat_auth` and the `/mcp` verifier; JWT-only routes never parse a `bgt_` bearer at all.
- No-oracle: `OAUTH_REQUEST_NOT_FOUND`, `OAUTH_APP_NOT_FOUND`, `TOKEN_NOT_FOUND` single-path 404s; `TOKEN_INVALID` one 401; `/token` answers `invalid_grant` for every code/refresh failure (SDK behaviour).
- DCR abuse: 30/hour per IP (per deployment in practice — meta-review #3), 16 KiB body, ≤10 URIs, name ≤100, no stored URI fields, no outbound fetch (no CIMD → no SSRF), orphan prune deferred with a documented query.
- Audience: `resource` validated at authorize (`invalid_target`); `AccessToken.resource` = ours; `BearerAuthBackend(resource_server_url=…)` refuses anything else.

## Owner-side env / compose
Nothing to add to the server's `.env`: `docker-compose.prod.yml` derives `PUBLIC_BASE_URL` from `SITE_DOMAIN`. After `deploy/update.sh`, the connector URL is `https://<SITE_DOMAIN>/mcp`. Switching domain (docs/deploy.md) now also means re-adding the connector in Claude — the brief accepts this.
