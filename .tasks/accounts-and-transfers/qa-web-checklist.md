# QA Web Checklist: амендмент A — зеркалирование сумм в TransferFormModal

## Scope
Браузерные проверки поверх коммитов `f8e47a0` (зеркало при одинаковых валютах) и
`ca89238` (переключение ноги на другую валюту снимает зеркало). Логика самого
зеркала покрыта vitest фронтенд-инженера (252 web-теста) и здесь НЕ переигрывается.
Здесь — только то, что навязывает браузер: реальное состояние полей формы при
открытии существующей строки, валидация на сабмите, наличие/отсутствие PATCH.

Данные готовятся curl'ом (`docs/infra.md`), кликами по формам фикстуры не создаются.

- Веб: `vite` из ТЕКУЩИХ исходников. Контейнер `budget-web-1` на :5173 собран в
  09:59, то есть ДО `ca89238` (12:44) — на нём проверять фикс нельзя.

  а порт 5173 занят контейнером. Временный конфиг удалён после прогона.
- Пользователь: `qa-rdi-a@budgetqa.dev` (LOGIN ONCE, curl; пара токенов
  подложена в `localStorage.budget.auth`, пароль в браузер не вводился).

## Test cases

### A4: открытие СУЩЕСТВУЮЩЕГО кросс-валютного перевода на редактирование
- **Precondition**: перевод `2b908c7c…` (USD→BYN, суммы ног разные), список
  операций за август 2026.
- **Steps**:
  1. Открыть `/transactions`, кликнуть строку «Перевод: QA A4 USD → QA A4 BYN».
  2. Зафиксировать содержимое поля «Сумма зачисления (BYN)» сразу после открытия.
  3. Не трогая ничего, нажать «Сохранить».
  4. Переоткрыть, изменить ТОЛЬКО заметку, нажать «Сохранить».
- **Expected**: поле содержит сохранённые 330,50; правка одной заметки уходит
  PATCH'ем и сохраняется.
- **Actual**:
  1. Поле «Сумма зачисления (BYN)» ПУСТОЕ. Прямо прочитать value через
     accessibility-tree нельзя, поэтому пустота доказана поведением: сабмит без
     единого касания формы даёт ошибку валидации `alert "Enter an amount."`,
     привязанную именно к «Сумма зачисления (BYN)» (соседнее поле «Сумма
     отправления (USD)» проходит валидацию — свои 100,00 оно сохранило).
     Строка курса при этом честно показывает «Курс на тот момент: 3.305 BYN за 1 USD»,
     то есть модалка знает сохранённые данные — их стирает эффект зеркала.
  2. Правка одной заметки НЕ сохраняется: тот же `Enter an amount.`, PATCH
     `/transactions/{id}` в сетевом логе ОТСУТСТВУЕТ, в БД заметка осталась
     `QA A4 cross`. Отредактировать кросс-валютный перевод невозможно, пока
     пользователь заново не наберёт сумму зачисления руками.
  3. Контроль (маскировка): одновалютный `6f957a98…` открыт и сохранён без
     единой правки — модалка закрылась штатно, ошибки нет, PATCH не нужен.
     Дефект на одинаковых валютах не виден, потому что зеркало тут же
     переписывает поле суммой отправления.
- **Root cause (по коду, не догадка)**: `apps/web/src/features/transfers/TransferFormModal.tsx:198-207`
  — эффект зеркала не смотрит на `isEdit`. При открытии формы редактирования
  `counterTouched === false`, а `sameCurrency === false`, поэтому
  `setValue('counter_amount', '')` затирает значение из `defaultValues`.
  Гипотеза senior-lead подтверждена полностью.
- **Побочный эффект того же эффекта**: на первом рендере счета ещё не загружены,
  `sourceCurrency === undefined` → `sameCurrency === false` → поле чистится и на
  ОДНОВАЛЮТНОМ переводе тоже, просто следующий проход зеркала возвращает туда
  сумму отправления. Для одновалютных ног это безвредно ровно потому, что суммы
  совпадают.
- **Severity**: данные молча НЕ портятся (валидация не пускает пустую сумму, PATCH
  не уходит), но любая правка кросс-валютного перевода — даты, заметки, счёта —
  требует вслепую перенабрать сумму зачисления; ошибётся пользователь в цифре —
  курс операции изменится молча.
- **Status**: ❌ FAIL

## Сопутствующие наблюдения (не A4, не чинить в этом амендменте)
- Сообщения валидации сумм приходят по-английски («Enter an amount.»,
  «Enter a valid amount.») на русском интерфейсе — это известный разрыв,
  записанный в `docs/web.md` (zod-сообщения в `@budget/shared/schemas.ts`).
- Guard несохранённых изменений работает: Escape после правки заметки поднимает
  «Продолжить ввод / Отменить изменения». Само затирание суммы форму «грязной»
  не делает (`shouldDirty: false`) — то есть закрыть модалку без предупреждения
  можно, а сохранить нельзя.
- Консоль на прогоне чистая (единственные ошибки в логе — CORS-отбивки :5174→:8010
  из подготовительного захода ДО поднятия прокси, к продукту отношения не имеют).
