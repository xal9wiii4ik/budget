# Follow-ups скоупа mcp-server

Найдено финальным QA. По политике новый круг имплементации НЕ открывали.

1. **Фокус после закрытия панели с токеном (a11y, минорный).** После «Done»
   фокус падает на `<body>`, а не возвращается на кнопку «New token». Причина —
   `TokenFormModal.tsx` рендерит два разных `<Modal>`, и второй запоминает уже
   исчезающий элемент. Обычные модалки фокус возвращают корректно.
2. **Даты в ru-локали при английском интерфейсе.** «19 авг. 2026 г.» в списке
   токенов. Решить единообразно по всему приложению, не точечно.
3. **`receipt_id` виден модели в `create_transaction`.** Скрыть можно только
   расширением механизма managed-полей (нужен вид «просто убрать из схемы»).
   Риск низкий: сервер проверяет принадлежность чека.
4. **Rate limit на `POST /tokens` живой сессией (MINOR-2 из ревью S1).** Трогает
   четыре файла, включая монтирование роутера — не влезает в закрывающий круг.

## Продуктовое ограничение, НЕ дефект

- Валюты вне шести отслеживаемых пар (проверено на JPY) сохраняются точно, но
  не конвертируются в базовую и честно попадают в счётчик несконвертированных.
  Через MCP это значит: операция запишется, но в агрегаты не войдёт. Решение за
  пользователем — добавить валюту в ежедневный сбор курсов либо перечислить
  поддерживаемые валюты в описании инструмента.

## Ограничение прогона

- Клавиатурная проверка формы (Tab/стрелки) не проведена: браузерный инструмент
  не доставляет эти события фокусированному элементу. Ограничение инструмента,
  не приложения.
