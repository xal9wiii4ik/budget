# bank-format-from-server

Скоуп поверх закрытого statement-import. Тир STANDARD. Мобилка и второй парсер — вне скоупа.

## Суть
Перечень поддерживаемых форматов выписок отдаёт СЕРВЕР (реестр `PARSERS` —
единственный источник правды). Веб показывает поле «Банк» в окне загрузки и
узнаёт о новом банке без правки клиента. Названия — на клиенте (ru/en),
неизвестный идентификатор показывается как есть, не прячется.

## Контракт (зафиксирован до имплементации, бэк и веб пишутся параллельно)
- `GET /statement-imports/formats` → 200 `{"formats": ["priorbank_csv_v1", ...]}`
  (порядок = порядок реестра). Response model `StatementFormatsRead`.
- Аутентификация — как у остальных маршрутов импорта. В PAT-allowlist НЕ
  добавлять (импорт целиком вне MCP, fail-closed).
- Маршрут объявляется ДО `/{import_id}` (route-order landmine, см. docs/backend.md).
- Ключи реестра не переименовывать: они хранятся в `source_format` сессий.

## Веб
- Поле «Банк» в `ImportUploadModal` рядом с выбором счёта; значение → существующее
  поле `format` запроса. Единственный формат предвыбран (ноль лишних кликов).
- Имена банков: словарный ключ на известные id; неизвестный id рендерится самим
  идентификатором (не скрывается, не роняет окно).
- `PRIORBANK_FORMAT` из `data/imports.ts` убрать, если больше ничего не держит.

## Тесты (только то, что может сломаться)
- API: список ответа == ключи `PARSERS` (сравнение с реестром, не второй
  захардкоженный список); неизвестный `format` в POST по-прежнему 422
  `STATEMENT_FORMAT_UNKNOWN` (если уже покрыто — не дублировать).
- Веб: неизвестный идентификатор формата отображается и не роняет окно (pure-модуль).
