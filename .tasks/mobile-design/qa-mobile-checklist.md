## Оформление, кадры, бюджет доказательств

- Флип: `xcrun simctl ui 97EA8741-3A57-4056-89BA-A88651C0EFD0 appearance dark|light`.
  **Каждый экранный TC снимается дважды**: `<tc>-light.png` / `<tc>-dark.png`;
  при явном выборе, отличном от ОС, добавляется `-oslight` / `-osdark`.
- Текст, состояние, навигация, рамки — только `idb describe-ui` и логи Metro/API.
- Цвет проверяется **пиксельной выборкой из PNG** (`python3` + координаты рамки из
  `describe-ui`): кадр снимается, но изображением в контекст НЕ читается. Так
  закрываются «нет белой вспышки», «рамка видна», «overlay поверх фона», «цвет по
  смыслу», контраст.
- Изображением читаются ≤12 кадров (компоновка, клиппинг, safe area, форма глифов):
  пары A-11, A-12, A-16, A-19a + по кадру A-8 и A-10. Если senior-lead требует
  жёсткие ~15 СНЯТЫХ кадров — несжимаемый минимум 7 пар: A-11, A-12, A-16, A-18,
  A-19a, A-20, A-22, остальные экраны по одной паре координат.

## Повторные прогоны (политика гоночных дефектов)

Гоночные: **A-2** (смена ОС на живом экране), **A-4** (первый кадр после холодного

## Секция A — симулятор (выполняет mobile-qa). Статус у всех: ⏸ pending

### A-1 Дефолт = «Система» на чистой установке
Приложение удалено (AsyncStorage стёрт), ОС = dark → запустить, войти, «Ещё».
**Критерий**: сегмент на «Система», экраны тёмные; после `appearance light` + рестарта
светлые; ключа `budget.theme` до явного выбора нет.

### A-2 Смена оформления ОС при открытом приложении (×3)
Preference = «Система», экран «Операции», приложение не трогаем — только `appearance
dark`, затем обратно. **Критерий**: тема меняется без перезапуска и без перемонтирования
(месяц, скролл, фильтры на месте по `describe-ui`); фон, карточки, шапка и таб-бар — в
новой схеме. Три прогона совпадают.

### A-3 Явный выбор побеждает ОС
ОС = light → «Ещё» → «Тёмная». **Критерий**: весь UI тёмный при светлой ОС; уход на
другую вкладку и возврат выбор не сбрасывают.

### A-4 Явный выбор переживает холодный старт, без чужого первого кадра (×3)
ОС = light, preference = «Тёмная» → terminate → запуск, серия кадров ~150 мс от
исчезновения splash. **Критерий**: НИ одного светлого кадра между splash и первым
экраном (пиксель фона ≈ `bg` тёмной палитры). Вспышка хотя бы в одном из трёх
прогонов = дефект, даже если два чистые.

### A-5 «Система» возвращает следование ОС
Из явной «Тёмной» → «Система» при ОС = light. **Критерий**: UI немедленно светлеет,
последующий `appearance dark` снова подхватывается (проверка снятия
`Appearance.setColorScheme(null)`).

### A-6 Статус-бар при явном выборе, отличном от ОС
ОС = light + тема «Тёмная», и симметрично. **Критерий**: глифы статус-бара читаемы
на фоне шапки (светлые на тёмной, тёмные на светлой) — пиксельная выборка по глифу
часов; совпадение цвета глифа с фоном = дефект.

### A-7 Нативные поверхности при явном выборе ≠ ОС (запись, не приговор)
ОС = light, тема «Тёмная». Записать таблицей 4 строки: **Alert** (`confirmAction` на
удалении операции), **DateTimePicker** (`themeVariant`, «Дата»), **клавиатура**
(`keyboardAppearance` на поле суммы), **шапка Stack + таб-бар**. **Критерий**: каждая
помечается `follows-app` (тёмная — целевой исход) или `follows-OS` (светлая —
**зафиксированная деградация Expo Go по R2, не провал**). Провал — только если
поверхность не следует НИ ОС, НИ приложению, либо нечитаема (тёмное на тёмном).

### A-8 Inter действительно отрисован
**Критерий, решающий**: строка `Font.loadAsync` из `src/theme/fonts.ts` в логе Metro —
семейства загружены, строки-фолбэка («идём на системном») нет.
**Вспомогательный** (сам по себе не приговор): один читаемый кадр «Ещё» — у Inter «1»
с плоским горизонтальным флагом без нижней засечки и двухэтажная «a» с прямым
стеблем, у SF флаг «1» скошен. Расхождение вспомогательного без расхождения лога = N-*.

### A-9 Веса различимы
**Критерий**: на одном кадре заголовок карточки (600) плотнее строки тела (400);
подтверждение — пиксельная насыщенность штриха по обеим строкам. Одинаковые веса =
`applyTypeface` не отобразил `fontWeight` в семейство (дефект).

### A-10 Табличные цифры
Сводка месяца и список сумм разной разрядности. **Критерий**: правые края сумм
совпадают, одинаковые разряды стоят друг под другом (`x` рамок из `describe-ui` +
вертикальная выборка). «Пляшущие» цифры = `t.tnum` не проставлен.

### A-11 Вкладка «Операции», обе темы
**Критерий**: фон/поверхность/рамка из нужной палитры; строки окрашены ПО ВИДУ
(`expense` / `income` / `transfer`); выбранный чип = `accentSoft + accentSoftFg`, не
заливка акцентом; у поля поиска рамка видна на обеих поверхностях, плейсхолдер отличим
от текста (≥ 3); виджеты на той же поверхности, что карточки; текст не обрезан.

### A-12 Шторка фильтров (RN `Modal`), обе темы
**Критерий**: при открытии в тёмной НЕТ белой вспышки (серия ~150 мс, пиксель фона);
подложка = `overlay`, шторка = `surfaceRaised` и отличается по цвету от фона;
«Готово» целиком ниже статус-бара (рамка из `describe-ui` — регресс D-1 catch-up 3)
и закрывает шторку с первого тапа.

### A-13 Операции категории (pushed), обе темы
**Критерий**: шапка (фон/тайтл/«назад») в схеме приложения; заголовок-сумма нейтральным
`text`; строка про несконвертированные — `textMuted`, не danger.

### A-14 Вкладка «Категории», обе темы
**Критерий**: строки в одной `Card`, хайрлайн-разделители видны в обеих темах; бейдж
«в архиве» нейтрального тона; hex в `HexSwatch` остаётся собой, пустой = `surfaceMuted`.

### A-15 Вкладка «Счета», обе темы
**Критерий**: балансы нейтральные (`text`), не зелёные; архивный счёт — `Badge` neutral;
карточки на `surface`, рамка видна.

### A-16 Цели + `goal-plan`, обе темы
**Критерий**: `FreeBalanceSummary` читаем; выбранный сегмент «Пункты плана / История» =
`accentSoft`; дерево читаемо на обоих уровнях; `ItemMoveSheet` (нативный `Modal`) =
`surfaceRaised` + `overlay`, без белой вспышки в тёмной.

### A-17 Регулярные + виджет ближайших списаний, обе темы
**Критерий**: `Badge` «на паузе» / «завершён» — warning / neutral, НЕ danger; суммы
окрашены по виду шаблона; виджет на вкладке «Операции» — та же поверхность.

### A-18 «Ещё», обе темы
**Критерий**: четыре секции (Язык, **Тема**, Базовая валюта, Заявленный доход); в
сегменте темы выбранный элемент = `accentSoft + accentSoftFg`, невыбранные читаемы;
`accessibilityRole="tab"` виден в `describe-ui`.

### A-19 Формы-модалки, обе темы
`a` операция, `b` перевод, `c` категория, `d` счёт, `e` регулярный, `f` цель,
`g` стоимость цели, `h` пункт плана, `i` взнос. **Критерий на каждую**: (1) в тёмной за
`presentation: 'modal'` нет белого листа — серия кадров + пиксель фона (R4); (2) рамка
инпута (`borderStrong`) видна и на `surface`, и на `bg`; (3) плейсхолдер = `textSubtle`,
отличим от введённого текста; (4) ошибка валидации цветом `danger`, читаема в обеих
темах (вызвать пустой суммой/именем); (5) футер `KeyboardAwareForm` на своей
поверхности, не просвечивает и не добавляет второй нижний inset.

### A-20 memo-строки перерисовываются на смене темы (×3, R5)
Загруженный список ≥12 строк, не скроллить → переключить тему (сегментом и отдельно
сменой ОС). **Критерий**: ни одной строки в старой схеме — выборка фона и текста в
первой, средней и последней видимой строке. Три прогона совпадают.

### A-21 Цвет по смыслу
**Критерий** (все три — выборкой с сопоставлением значению из
`packages/shared/src/palette.ts`): (1) нейтральный итог месяца и баланс счёта = `text`,
не зелёный и не красный даже при положительном значении; (2) предупреждение о
реалистичности цели = `warning`, не `expense`; (3) строка перевода = `transfer`,
отличается и от `expense`, и от `income`.

### A-22 Контраст, точечная проверка по тёмному кадру
Три пары, выборка цвета текста и фона под ним, расчёт WCAG: (1) `text` на `bg` —
заголовок «Операции»; (2) `textMuted` на `surface` — подпись категории в строке;
(3) `accentSoftFg` на `accentSoft` — выбранный чип. **Критерий: каждая ≥ 4.5**;
бонус — `borderStrong` рамки инпута к `surface` ≥ 3. Ниже порога = дефект: палитра
пришпилена юнит-тестом в shared, значит на экране применён не тот токен.

### A-23 Регресс-смоук (3 записи; скоуп логику не трогает)
(1) создать операцию → строка появилась, сводка обновилась; (2) переименовать категорию
→ список и счётчик обновились; (3) язык RU→EN→RU в «Ещё» → применилось без рестарта.
**Критерий**: три записи прошли, в логах Metro нет ошибок и красных экранов. Это НЕ
повтор прогона catch-up 3.

## Формат дефекта

`D-n — формулировка (экран, файл)`: шаги, ожидание, факт, пара кадров `<tc>-light.png` /
`<tc>-dark.png` (или серия при вспышке) + строка лога. Косметика без потери читаемости
и без деградации R2/R7 — `N-n`, не `D-n`. QA код не чинит, отдаёт senior-lead.
