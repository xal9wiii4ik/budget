   `goal_item_id` уже own-проверенного узла — файл чужого узла (даже своего юзера)
   неотличим от несуществующего. Тест `test_files_of_a_foreign_item_are_404`
   сравнивает `content` байт-в-байт.
2. **Подписанные URL и логи** — OK. Оба пути логирования (`goal_item_files.py:319`,
   `object_cleanup.py:47/55/62`) пишут только `type(exc).__name__` либо статус-код;
   URL нигде не попадает в message. Урок a8b75e4 учтён явными комментариями.
3. **view_url только при uploaded** — OK. `_view_url` возвращает None до подтверждения;
   в схеме `view_url` обязательный nullable (честный null, не omit). Тест 1 держит
   контраст в одном тесте.
4. **Удаление файла** — OK. Строка удаляется и КОММИТИТСЯ до планирования sweep;
   провал коммита = провал запроса (204 не маскирует); провал стораджа в
   background — только warning.
5. **Каскад пункта** — OK. `subtree_item_ids` (корень включён, рекурсия по FK той же
   цели) собирает пути ДО `session.delete`; sweep — после commit через
   `BackgroundTasks`. Позитивный тест доказывает, что ключ файла РЕБЁНКА попал в sweep.
6. **Лимиты** — OK. Один новый ключ `goal_item_files_max_per_item: int = 10`; размер —
   существующий `receipt_max_bytes` (5_000_000), второго size-ключа нет (grep чист).
7. **Тесты** — OK. Ровно закрытый список §3 (6) + позитивный каскадный; HEAD/DELETE
   мокаются патчем `httpx.AsyncClient` на границе процесса в двух модулях;
   `Storage` подменён детерминированным стендом на `app.state` (прецедент receipts,
   задокументировано). Два delete-теста не дублируют друг друга (разные арм:
   какие ключи vs устойчивость к падению стораджа).
8. **Контракт** — OK. Все 4 маршрута и 3 схемы (`GoalItemFileCreated/Read/Error`)
   в `openapi.json`, 422 — raw anyOf [GoalItemFileError, HTTPValidationError],
   confirm несёт 409/503; `schema.d.ts` содержит те же имена. PAT-пар файловых
   маршрутов НЕТ ни в `pat_auth.py`, ни в `allowlist.ts` (fail-closed 403).

## Находки

- **NIT** `routers/goal_item_files.py:341` — отсутствующий `content-length` в HEAD
  трактуется как 0 (confirm проходит без доказанного размера), кривое значение даст
  ValueError → 500. Байт-в-байт повтор прецедента `receipts.py:363` — консистентность
  сохранена, фиксирую для протокола, не для правки в B3.
- **NIT** `services/object_cleanup.py:39-62` — внешний `except Exception` обрывает
  остаток батча при не-httpx ошибке на одном ключе (единственный реальный источник —
  чисто локальный `presign_delete`); per-key guard ловит только `httpx.HTTPError`.
  Влияние пренебрежимо (best-effort, утечка диска).
- **NIT** `routers/goal_item_files.py:306-311` — no-op-ретрай confirm уже
  подтверждённого файла срезается 422 `GOAL_ARCHIVED`, если цель заархивировали между
  попытками (архив-гард стоит до short-circuit). Решение задокументировано в
  `_reject_archived` («confirm — это write»), поведение защитимо; фиксирую асимметрию.
