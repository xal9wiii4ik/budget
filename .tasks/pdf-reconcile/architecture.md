# Architecture Plan: pdf-reconcile — Alfa PDF via LLM, balance reconciliation, reconcile agent

## Context
Three features ride one existing flow (`/statement-imports` session → preview → apply/replace) and one existing seam (`llm/`, whose tool-use shape is declared but unimplemented). The questions with structural weight: (1) a parser that needs an async provider in a registry of sync pure parsers; (2) a statement that is parsed but must not be applied — a new gate between `parsed` and apply; (3) the first real tool loop over `llm/` and what the fake/replay store must learn for it; (4) one migration adding three independent families of columns to `statement_imports`. Every "would have been a buried default" below is numbered `D-*` with a recommendation; the engineer may argue any of them in the plan.

## Proposed approach
1. `services/statement_import/alfa_pdf.py` — an async EXTRACTOR (bytes + provider → `ParsedStatement`): pypdf text → deterministic header anchors (regex) + operation lines → LLM rows (chunked, `structured()`) → server-side money conversion → self-check against the anchors. Self-check failure is DATA on the statement, not an exception.
2. `ParsedStatement` gains balance anchors + a self-check result; Credo exposes what it already proves, Priorbank answers "not available".
3. Apply/replace gain two things in the same DB transaction: the refusal of a failed self-check and the post-import balance check (account balance as of `period_to` vs closing).
4. `services/reconcile.py` — pure: deterministic pre-match (`matching.match_rows`) then a bounded tool loop; the router owns DB, claim and storage. `POST /{id}/reconcile` + `GET /{id}/reconciliation`.
5. `llm/` implements `tools`/`tool_choice`/`ToolUseBlock`/`ToolResultPart` in all three providers; the replay key grows WITHOUT moving existing keys.
6. Evals: two new runners + a seeded generator; regression test extended.

## 1. Alfa extractor (`alfa_pdf.py`, `FORMAT_ID = "alfa_pdf_v1"`)
- **D-E1 pypdf.** Runtime dependency `pypdf>=6` (pure Python, BSD, maintained, no system binaries). pdfplumber would pull pdfminer.six + pypdfium2 (binary wheel) and truncates cells (sample-structure.md); plain `extract_text()` already yields one line per operation. Size gate: the existing 1 MB `STATEMENT_TOO_LARGE` stays (a 12-month text PDF is well under it); page count is not a knob.
- **D-E2 Two seams inside the module:** `text_lines(data: bytes) -> list[str]` (pypdf only) and `async extract_from_text(lines, provider, config, *, user_id) -> ParsedStatement`; `extract(data, provider, config, *, user_id)` composes them. Tests and the evals drive TEXT; exactly one test and the QA stand touch a PDF. pypdf failure (encrypted, not a PDF, zero text) → `StatementParseError` → the existing 422 `STATEMENT_PARSE_FAILED`.
- **D-E3 Anchors deterministic, rows by LLM (adopt lead (a)).** Regex over the joined text for exactly: `Валюта счёта`, `Период`, `Баланс на начало периода` (label may wrap), `Баланс на конец периода`, `Приход`, `Расход`. Any anchor missing/unparseable → `StatementParseError` (no LLM call made, no token spent). Numbers: decimal point, optional sign, trailing zeros dropped → `domain/money` at the statement exponent.
- **D-E4 PII cut (adopt (b)).** Operation lines = lines AFTER the first table header (`Дата … Примечание …`) whose text starts with `dd.mm.yyyy `. Nothing else ever reaches a prompt, a log or the DB; `raw = {"line": <that line>}`. Residual: a description may itself quote a name (a P2P credit) — that is the bank's line and is stored like every other format's description.
- **D-E5 Schema.** Per chunk, user message = ONE JSON document `{"currency": "BYN", "lines": [{"key": "l1", "text": "..."}]}` (the fake parses it; the replay key hashes it). Response schema: `{rows: [{key: enum(l*), date: string, amount: string, currency: string, original_amount: string|null, original_currency: string|null, merchant: string|null}]}`, `additionalProperties: false`. Amounts are STRINGS in major units with sign (adopt (c)); the model does no arithmetic and returns no description — see D-E8. `PROMPT_VERSION = "extract-alfa-v1"` + `PROMPT_FINGERPRINTS` pinned by test, the categorize pattern.
- **D-E6 Server conversion + structural validity.** For each line: `Decimal(amount)` → minor at `currency`'s exponent; refuse more decimals than the exponent, a non-`^[A-Z]{3}$` code, `currency != header currency`, an unparseable date, a key not in the chunk, a missing key, an `original_*` half-pair. ANY structurally unusable row → the extraction is unusable → `StatementExtractionError("invalid_output")` → 422 `STATEMENT_EXTRACTION_FAILED` (a half-row cannot become a `ParsedRow`; nothing is stored). `kind` from the sign; `amount_minor` = magnitude; `merchant` = stripped name ≤255 or `""` (sentence-shaped format, the Credo rule — NEVER `None`); `possible_transfer` = server regex on the line (`Перевод`); `section = card`, `txn_date = booked_date = date`, `txn_time = None`, `bank_category = None`, `fee_minor = 0`.
- **D-E7 Self-check = data, in this ORDER, first failure wins:** `balance` (opening + Σsigned == closing), `income_total` (Σincome == Приход), `expense_total` (Σexpense == |Расход|), `date_range` (every date in `Период`). Result `SelfCheck(status: passed|failed, failed: str|None, expected_minor: int|None, actual_minor: int|None)` — `date_range` carries NULL numbers. The statement IS returned (session created, preview shows the difference); only apply/replace refuse it (§3). Rationale: an arithmetic mismatch is a complete, displayable statement with one line misread or missed — the user needs to SEE the rows to tell us which; a structurally broken row is not displayable at all (D-E6).
- **D-E8 Fingerprint canon `alfa:v1`** (adopt (e)); `FINGERPRINT_VERSIONS` keys must equal the published format ids (test updated to the union, D-E10). `ParsedRow.description` for Alfa = the raw line with the leading date and the trailing `<amt> <CCY> <amt> <CCY>` block cut by SERVER regex (deterministic from pypdf, never from the model) — the canon's `description` field must not depend on how the model paraphrases, or a re-upload would re-import the history as new. The numeric canon fields do come from the model; the self-check bounds the damage, `occ_index` handles true duplicates. Preview `description` = that same string; apply files `display_name(merchant, description)`.
- **D-E9 Chunking.** Lines in file order cut into `extract_lines_per_call` chunks, `asyncio.Semaphore(extract_concurrency)`, whole gather under `asyncio.timeout(extract_time_budget_seconds)`; `max_tokens = max(1024, 80 × lines)`. Validation runs over the UNION; any chunk lost (`invalid_output`/`truncated` after one retry of that chunk only, `unavailable`, budget) = extraction failed — a statement with a hole cannot pass a sum check and must not be stored half-read. `extract_max_lines` cap → 422 `STATEMENT_TOO_LARGE` (reuse). Quota: limiter hit `<scope>:extract:<user_id>` with `cost=lines` from `extract_daily_line_quota`, the categorize closure pattern; refused → 429 `RATE_LIMITED` before the first call.
- **D-E10 Registry (lead (d)): a SECOND mapping, not a widened entry.** `__init__.py`: `PARSERS` byte-identical; new `EXTRACTORS: Mapping[str, AsyncExtractor]` where `class AsyncExtractor(Protocol): async def __call__(self, data: bytes, provider: LLMProvider, config: ExtractConfig, *, user_id: str | None = None) -> ParsedStatement`; `FORMAT_IDS: tuple[str, ...] = (*PARSERS, *EXTRACTORS)` is what `GET /formats` publishes and what `FINGERPRINT_VERSIONS` is pinned against. Membership IS `needs_llm` — no boolean to keep in sync, no `None` arms in one dataclass, Priorbank/Credo modules untouched. Router gate order: account → size → format (`FORMAT_IDS`) → **provider** (`app.state.llm is None` → 503 `AI_NOT_CONFIGURED`, D-C1) → extraction quota → extract/parse → currency → … unchanged. The extractor runs BEFORE the write like the categorize pass, so the IntegrityError retry re-files the same statement.
- **D-E11 Settings** (defaults; explicit `Settings(...)` sites unaffected): `extract_lines_per_call=60`, `extract_concurrency=4`, `extract_time_budget_seconds=60`, `extract_max_lines=2000`, `extract_daily_line_quota="3000/day"`. NO model knob: `app.state.llm` is ONE provider with ONE model; a per-task model would be a second provider instance — speculative. `ExtractConfig(lines_per_call, concurrency, time_budget_seconds, max_lines)` frozen dataclass.
- **D-E12 Fake "extract" arm (adopt (f)).** `FakeProvider` dispatches on the data document: `"operations"` → categorize, `"lines"` → extract (regex `^(dd.mm.yyyy) (.+?) (-?\d+(?:\.\d+)?) ([A-Z]{3}) (-?\d+(?:\.\d+)?) ([A-Z]{3})$`, merchant = tail after `Покупка товара / получение услуг `, else null); `LLMFAIL` in any line → `unavailable`. A fake answering a known layout, not a second extractor.

## 2. Balance anchors + post-import check (all formats)
- `ParsedStatement` + `opening_balance_minor: int | None`, `closing_balance_minor: int | None`, `self_check: SelfCheck | None` (defaults None — Priorbank untouched). Credo: both balances + `SelfCheck(passed)` (its chain already raised on failure; that behaviour stays).
- **D-B1 Computed at apply/replace only, never at upload** (agree with lead): the pre-apply number describes a ledger the apply is about to change. `services/account_balances.py` + `account_balance_as_of(session, user_id, account_id, as_of: date) -> int` = starting + the SAME union-of-legs sum with `occurred_at <= as_of` (transfers both legs, debt movements included — it is the account balance, as `GET /accounts` defines it). Called in `apply_import`/`replace_import` after `_create_transactions`, before `commit()` (apply.py already owns DB). Stored: `app_balance_minor_at_end`, `balance_diff_minor = app − closing`, `balance_check ∈ not_available|match|mismatch` (`not_available` when `closing_balance_minor` is NULL). Informational: never blocks. Known honest mismatches the agent (§4) explains: app rows dated inside the period but posted by the bank after `period_to`; rows the user skipped.

## 3. Apply/replace gate
- `apply_import`/`replace_import` (after `_load_target`): `self_check_status == 'failed'` → `StatementApplyError("STATEMENT_BALANCE_MISMATCH")` → 422. Row PATCH, bulk-decision, replace-preview (a GET) and DELETE stay allowed. `_load_live` is NOT the place: the refusal must sit next to the write, in the retried procedure.

## 4. Reconcile agent (`services/reconcile.py`, pure: `llm`, `domain`, `enums`, `matching`, stdlib)
- Inputs (frozen): `RowFact(id, txn_date, booked_date, kind, amount_minor, currency, original_amount_minor, original_currency, description, merchant)`, `TxFact(id, occurred_at, kind, amount_minor, currency, merchant, note, is_transfer, is_debt_movement)`, `ReconcileConfig(max_steps, max_total_tokens, time_budget_seconds, max_items_per_side)`. The router builds them: rows of the session; transactions of the account in `[period_from−3d, period_to+3d]` EITHER leg (refactor `_candidate_window` to take dates; the transfer counter-leg view of `_load_candidates` reused). Pre-match needs `ParsedRow`s: a `row_to_parsed(StatementImportRow) -> ParsedRow` helper (fields are 1:1) + the stored `client_id`s.
- **D-R1 Pre-match first, server settles `exact`.** `prematch(rows, client_ids, candidates) -> Prematch(settled: list[(row_id, tx_id)], open_rows, open_txs, pairs)`; `similar` verdicts are NOT settled — they become pre-computed `pairs` `(row_id, tx_id, amount_delta_minor, date_delta_days)` handed to the model as facts. Also for every open row: all open txs of the same kind within ±3 days as pairs. The model classifies and explains; it never subtracts.
- **D-R2 Three tools, not four.** `list_unmatched_statement_rows` (no args → open rows, each with its `pairs` embedded), `list_unmatched_app_transactions` (no args → open txs, flags included), terminal `report_discrepancies({items: [{kind, row_id|null, transaction_id|null, explanation}], summary})`. `find_similar` dropped: the pairs are embedded, so the model has nothing to ask for. `tool_choice="auto"` (anthropic.py already records that `any` is refused by the newest families); the system prompt demands ending with the terminal tool; a loop that ends in text, or exhausts `max_steps`, is `invalid_output`.
- **D-R3 Budgets:** `reconcile_max_steps=8`, `reconcile_max_total_tokens=60000` (Σ in+out over the loop), `reconcile_time_budget_seconds=60` (`asyncio.timeout`), `reconcile_max_items_per_side=300` — beyond it 422 `RECONCILIATION_TOO_LARGE` before any call (an unbounded list in a prompt is the one thing a budget cannot fix). `ReconcileOutcome(report: Report | None, calls: list[Usage], steps: int, aborted_reason: str | None)` — never raises; `aborted_reason ∈ unavailable|request_rejected|invalid_output|truncated|steps|tokens|time_budget|error`.
- **D-R4 Validation of the terminal call:** `kind ∈ DiscrepancyKind (missing_in_app|extra_in_app|amount_differs|date_differs|fx_difference)`; `missing_in_app` ⇒ row_id ∈ open rows, tx null; `extra_in_app` ⇒ tx ∈ open txs, row null; the three `*_differs` ⇒ both ids, from the open sets; explanation stripped ≤300; one item per (row, tx) pair, first wins; invalid items dropped (count in the log line). `Report(version="reconcile-v1", settled_exact, open_rows, open_transactions, items, counts_by_kind, unmentioned_rows, unmentioned_transactions, summary)`. `PROMPT_VERSION = "reconcile-v1"`, fingerprint pinned.
- **D-R5 Storage + concurrency: claim, not last-writer-wins.** Route: JWT-only (`current_active_user`), `Depends(require_llm_provider)` → 503, `user_rl_key("reconcile")` + `reconcile_rate_limit="3/min;10/day"`, status ∈ `parsed|applied|replaced`. Claim = `UPDATE statement_imports SET reconciliation_status='running', reconciliation_started_at=now() WHERE id=? AND user_id=? AND (reconciliation_status != 'running' OR reconciliation_started_at < now() − 2×time_budget) RETURNING id`, COMMITTED before the loop (the receipts claim precedent, stale re-claim after 2× the budget); zero rows → 409 `RECONCILIATION_RUNNING`. After the loop, one more short transaction writes the outcome: `ok` + `reconciliation` JSONB (the whole `Report` + `usage {steps, input_tokens, output_tokens, cost_usd}`) + `reconciled_at` + the `reconcile_provider/model/prompt_version` trio; or `failed` + JSONB NULL + the trio, and the POST answers 503 `AI_UNAVAILABLE` (`unavailable`) or 422 `RECONCILIATION_FAILED` (everything else). A later run overwrites. `GET /{id}` carries `reconciliation_status`, `reconciled_at`, `reconciliation_counts` (by kind, null unless `ok`). `GET /{id}/reconciliation` → the full `StatementReconciliationRead`; its only 404 is `IMPORT_NOT_FOUND` (no-oracle); a session never reconciled answers 200 with `status='none'` and `items: []` — a second 404 for "no report yet" would be a second code path for one resource. The POST answers the same full read.
- **D-R6 MCP: none in v1** (agree with lead). The import family is off-token by construction (statement-import architecture §6); a read tool cannot obtain a session id without a `list_statement_imports` tool, and adding that tool is a separate exposure decision. Follow-up recorded: `mcp-statement-reconciliation`.

## 5. `llm/` tool-use
- `tool_choice: str | None` grammar: `None`/`"auto"`, `"any"`, `"tool:<name>"`. `ToolSpec` canonical JSON `{"name", "description", "input_schema"}`; `ToolUseBlock` `{"type": "tool_use", "id", "name", "input"}`; `TextBlock` `{"type": "text", "text"}`.
- Anthropic: `tools=[{name, description, input_schema}]`, `tool_choice={"type": "auto"|"any"|"tool","name"}`, `stop_reason` passed through (`"tool_use"`); `_message_param` already emits `tool_result`. Ollama: `tools=[{"type":"function","function":{name, description, parameters}}]`, `message.tool_calls[i].function.{name, arguments}` → `ToolUseBlock(id=f"ollama-{i}")` (deterministic per response — the next request's `ToolResultPart` keys the replay hash); a `ToolResultPart` goes out as a `{"role":"tool","content"}` message; `tool_choice` silently ignored (Ollama has none; the prompt carries the instruction) — documented, not `unsupported`; `stop_reason="tool_use"` when `tool_calls` non-empty.
- **D-L1 Replay key grows only when used:** `request_key` adds `"tools"` and `"tool_choice"` ONLY when `tools` is non-empty — every existing categorize fixture keeps its hash. `_response_json`/`_response_from_json` serialize `ToolUseBlock`s (today dropped silently — a bug the loop would hit).
- **D-L2 Fake scripted arm** (adopt (f)): on `tools` non-empty it reads the reconcile document (`{"reconcile": {...}}` in the first user message) and the tool results present in `messages`: none → call `list_unmatched_statement_rows`; one → `list_unmatched_app_transactions`; two → `report_discrepancies` with every open row `missing_in_app` and every open tx `extra_in_app`; `LLMFAIL` in any description → `unavailable`. Deterministic, so a QA stand with `LLM_PROVIDER=fake` runs the whole flow.
- `errors.py`: no new codes (`unsupported` stays for shapes still missing, e.g. `ImagePart`). `log_call` gains nothing: one line per CALL, `batch_size` = lines (extract) or step index (reconcile).

## 6. Database changes — `0019_pdf_reconcile.py` (`statement_imports` only, no backfill)
### Columns (CHECKs hand-written, byte-identical to what the model renders from the enums; the 0018 rule)
- Anchors: `opening_balance_minor` BigInteger NULL, `closing_balance_minor` BigInteger NULL.
- Self-check (**D-M1 typed columns, not JSONB**: apply's gate reads one column, the preview renders two integers without parsing JSON, and a fixed 4-field shape is not "flexible"): `self_check_status` String(16) NOT NULL server_default `'not_available'` CHECK `self_check_status_valid` (`not_available|passed|failed`); `self_check_failed` String(16) NULL CHECK `self_check_failed_valid` (`balance|income_total|expense_total|date_range`); `self_check_expected_minor`, `self_check_actual_minor` BigInteger NULL; CHECK `self_check_detail`: `(self_check_status = 'failed') = (self_check_failed IS NOT NULL)`.
- Post-import: `balance_check` String(16) NOT NULL server_default `'not_available'` CHECK (`not_available|match|mismatch`); `app_balance_minor_at_end`, `balance_diff_minor` BigInteger NULL; CHECK `balance_check_pair`: `(balance_check = 'not_available') = (app_balance_minor_at_end IS NULL) AND (app_balance_minor_at_end IS NULL) = (balance_diff_minor IS NULL)`.
- Agent: `reconciliation_status` String(16) NOT NULL server_default `'none'` CHECK (`none|running|ok|failed`); `reconciliation_started_at`, `reconciled_at` DateTime(tz) NULL; `reconciliation` JSONB NULL; `reconcile_provider` String(32), `reconcile_model` String(64), `reconcile_prompt_version` String(32) NULL; CHECK `reconciliation_present`: `(reconciliation_status = 'ok') = (reconciliation IS NOT NULL)`.
- `source_format` String(32) fits `alfa_pdf_v1`; no index (every read is by PK or the existing `(user_id, account_id)`).
### Migration steps
1. ADD the 2 anchor columns. 2. ADD the 4 self-check columns + 3 CHECKs. 3. ADD the 3 balance columns + 2 CHECKs. 4. ADD the 7 agent columns + 2 CHECKs. 5. Downgrade symmetric: drop CHECKs then columns in reverse; KEEPS every row — an `alfa_pdf_v1` session survives as a journal row whose format the old registry no longer names (reads fine, cannot be re-applied: it is `applied`/`replaced` or a stale preview the TTL sweep removes). Settings in §1/§4 + `reconcile_rate_limit`.
- `enums.py` appended: `StatementSelfCheckStatus`, `StatementSelfCheckFailure`, `StatementBalanceCheck`, `StatementReconciliationStatus`, `DiscrepancyKind` — definition order load-bearing, pinned by the existing enum/CHECK test.

## 7. Contract (`openapi.json` + `schema.d.ts`, one commit)
- `StatementImportRead` + `opening_balance_minor`, `closing_balance_minor`, `self_check_status`, `self_check_failed`, `self_check_expected_minor`, `self_check_actual_minor`, `balance_check`, `app_balance_minor_at_end`, `balance_diff_minor`, `reconciliation_status`, `reconciled_at`, `reconciliation_counts: DiscrepancyCounts | null`.
- New: `StatementReconciliationRead {import_id, status, reconciled_at, provider, model, prompt_version, settled_exact, open_rows, open_transactions, counts: DiscrepancyCounts, unmentioned_rows, unmentioned_transactions, items: [StatementDiscrepancy {kind, row_id, transaction_id, explanation}], summary}`; `DiscrepancyCounts` (five ints). `GET /formats` publishes `FORMAT_IDS`.
- **D-C1 Error codes.** 503 `AI_NOT_CONFIGURED` — upload of an `EXTRACTORS` format / reconcile with `app.state.llm is None`; NEW gate `ai_gate.require_llm_provider` (the existing `require_ai_configured` checks `anthropic_api_key`, which is empty under `LLM_PROVIDER=fake|ollama`), same code so the web's copy applies. 503 `AI_UNAVAILABLE` (new) — a provider outage mid-extraction/mid-loop: a 422 would tell the user the FILE is bad and make them re-upload a good one. 422 `STATEMENT_EXTRACTION_FAILED` (unusable model output / lost chunk), `STATEMENT_BALANCE_MISMATCH` (apply/replace on a failed self-check — the numbers are on the session read, the body stays bare), `RECONCILIATION_FAILED`, `RECONCILIATION_TOO_LARGE`; 409 `RECONCILIATION_RUNNING`. `STATEMENT_TOO_LARGE` reused for the line cap. All on `StatementImportError`'s `anyOf`.

## 8. Evals (`apps/api/evals/`)
- `common.py` (provider building, `replay_file`, percentiles, report writing lifted out of `run.py` — `run.py` keeps its CLI and public names so the existing test is untouched), `gen_alfa.py --seed --statements N` → `dataset/synthetic-alfa-v1/statements.jsonl` (`{id, currency, period, opening_minor, closing_minor, income_minor, expense_minor, lines: [...], gold_rows: [{date, kind, amount_minor, original_amount_minor, original_currency, merchant}]}`) + `pdfs/` (D-E13 below), `extract.py` (text → `extract_from_text` → per-field accuracy date/amount/currency/merchant, row-count exact rate, self-check pass rate; report `reports/extract-<provider>-<model>-extract-alfa-v1.{md,json}`), `gen_reconcile.py` → `dataset/synthetic-reconcile-v1.jsonl` (`{id, rows, transactions, gold: [{kind, row_id, transaction_id}]}` with seeded perturbations: drop/add/amount/date/fx), `reconcile.py` (precision/recall per kind over `(kind, row_id, transaction_id)` triples + settled count; report `reports/reconcile-…`). Replay stores `replay/<provider>-<model>-<prompt_version>.jsonl`; every report says `synthetic: true` for the fake. `tests/test_evals_regression.py` + two replay runs with floors calibrated on the fake (extract = the regex → 100%; reconcile = all-missing/all-extra → recall 100% on those two kinds, precision low; floors a hair below, re-set after the first live run).
- **D-E13 Fixture PDFs:** the generator writes real PDFs with a pure-Python DEV dependency (engineer picks; constraint: Cyrillic must survive `pypdf.extract_text` as one line per operation, ≤ 50 KB each, 3 files committed under `tests/fixtures/alfa/`) — the QA stand needs an actual upload; everything else drives text.

## Module structure
```
services/statement_import/alfa_pdf.py        (extractor; imports llm, domain, types, stdlib, pypdf)
services/statement_import/__init__.py        (+EXTRACTORS, FORMAT_IDS)   types.py (+anchors, SelfCheck)
services/statement_import/fingerprint.py     (+alfa:v1)                  apply.py (+gate, +balance stamp)
services/statement_import/matching.py        (untouched; reused by reconcile)
services/reconcile.py                        (pure loop)                  services/account_balances.py (+as_of)
llm/{types,anthropic,ollama,fake}.py          (tool-use; replay key)      ai_gate.py (+require_llm_provider)
routers/statement_imports.py                 (gate order, reconcile POST/GET, claim)   schemas, enums, models
alembic/versions/0019_pdf_reconcile.py       evals/{common,extract,reconcile,gen_alfa,gen_reconcile}.py
```
Dependency direction: routers → services → (llm | domain | models). `llm/` imports `config`, `httpx`, `anthropic`, stdlib. `alfa_pdf.py` and `reconcile.py` never import `models`/`db`/`fastapi`/the limiter; the router passes `app.state.llm`, the quota closure and the facts. `apply.py` owns the write-side DB as today.

## Trade-offs considered
- **Separate `EXTRACTORS` vs one widened registry entry:** separate — no optional arms, no boolean to mirror, the sync parsers' modules and the registry test stay byte-identical; the cost is one union tuple.
- **Self-check as data vs `StatementParseError`:** data for Alfa (the user must see the rows to locate the misread); Credo keeps raising (its rows are read deterministically — a failed chain there means mis-read COLUMNS, not a model slip).
- **LLM returns description vs server keeps the line:** server (D-E8) — fingerprint determinism beats a nicer preview string.
- **Claim vs last-writer-wins for reconcile:** claim — a double click must not burn two loops; the stale re-claim keeps a crash from wedging the session.
- **Report embedded in `GET /{id}` vs separate GET:** counts embedded, list separate — the session read stays small for the list screen.
- **`AI_UNAVAILABLE` as a new 503 vs folding into 422:** new — honest HTTP semantics for "try later" vs "fix your file".

## Test seams
1. `extract_from_text` with `FakeProvider("fake")`: happy path; anchors missing → parse error, zero calls; mismatch → `self_check.failed='balance'` with the two numbers; unusable row → extraction error; chunk boundary (61 lines → 2 calls, union validated); `LLMFAIL` → `unavailable`. One pypdf test over a fixture PDF.
2. Router: `alfa_pdf_v1` with `app.state.llm=None` → 503, CSV unaffected; failed self-check → session 201, apply/replace 422 `STATEMENT_BALANCE_MISMATCH`, PATCH still 200; `FORMAT_IDS == FINGERPRINT_VERSIONS.keys()` pin.
3. Apply/replace stamp `balance_check` (match with an exact ledger, mismatch with one extra tx dated in the period, `not_available` for Priorbank) — same transaction, visible after commit.
4. `services/reconcile`: pre-match settles `exact`; fake loop → all missing/extra; terminal item with a foreign id dropped; `max_steps` exhausted → `invalid_output`; token/time budget → aborted.
