# QA Web Checklist: pdf-reconcile — Alfa PDF, сверка остатков, агент сверки (apps/web)

## Scope

Браузерные user-journeys ТОЛЬКО по тому, что скоуп добавляет на веб-поверхность
`/accounts` → `ImportUploadModal` → `/imports/:id`:

- банк `alfa_pdf_v1` в пикере + подсказка «строки читает ИИ» + `.pdf` в `accept`;
- self-check выписки: «сходится» с остатками vs warning-баннер с названием провалившейся
  проверки и двумя числами, и ГЕЙТ apply/replace на провале;
- строка сверки остатка после apply/replace («✓ сходится с банком» / «расхождение N»)
  и её ХРАНИМОСТЬ (не пересчёт при каждом открытии);
- агент сверки: кнопка, running-состояние, отчёт (counts + summary + сгруппированные
  items с деталями строки/транзакции), 409 «уже идёт», выживание после F5;
- копии двух 503 (`AI_NOT_CONFIGURED` / `AI_UNAVAILABLE`) и 422 извлечения;
- RU/EN, деньги/даты через хелперы, тёмная тема, 375 px, клавиатура/фокус,
  `role="status"` на warning-армах, консоль/сеть.

### НЕ покрывается здесь (и чем закрыто)

- Арифметика и ПОРЯДОК self-check (balance → income_total → expense_total → date_range),
  `account_balance_as_of` и его cutoff `< as_of+1d` (A1), pre-match, валидация терминального
  tool-call, claim/stale-claim, CHECK'и миграции, квоты/429, no-oracle 404, `FORMAT_IDS ==
  FINGERPRINT_VERSIONS.keys()` — pytest бэкенда (architecture «Test seams» 1–6).
- Коды/тела ответов, скоупинг по user_id, `GET /{id}/reconciliation` при `status='none'`,
  `RECONCILIATION_TOO_LARGE`, `STATEMENT_TOO_LARGE` на line cap — curl у qa-engineer.
- Чистые веб-хелперы (`statementFormatLabel` для нового id, строка self-check/баланса,
  если она выделена в модуль) — vitest фронтенд-инженера; в браузере проверяется РЕНДЕР.
- Путь multipart-загрузки как таковой доказан вживую в
  `.tasks/statement-import/qa-web-checklist.md` (WJ-1). НОВОЕ здесь — формат `alfa_pdf_v1`,
  `.pdf` и НОВЫЙ роут `POST /{id}/reconcile`: на каждый новый метод/роут обязателен
  минимум один вызов ИЗ приложения (урок CORS 2026-08-18) — это TC-2 и TC-8.
- Подготовка состояния (пользователь, счёт, транзакции внутри периода, вторая сессия) —
  curl, не клики по формам.

в репо не нужна — генерируется в scratchpad тем же скриптом; если её нет, TC-7b = ⏸.

**Ограничение инструмента** (переносится из S4): QA-инструмент не умеет заполнять
`<input type=file>` — файл подаётся через same-origin iframe-харнесс, но сам upload
делает КОД ПРИЛОЖЕНИЯ (сгенерированный клиент, FormData, байты файла). `accept`
проверяется чтением DOM, а не диалогом ОС.

**Доказательства**: `<scratchpad>/pdf-reconcile-evidence/TC-<n>-<slug>.{png,txt}` — скриншоты
только там, где проверка ВИЗУАЛЬНАЯ (тёмная тема, 375 px, баннер), остальное через
`read_page`/`get_page_text`/`read_network_requests`. В репо не кладём; в Summary ниже —
цитаты копий, числа и ссылки на запросы.

## Копии: что здесь обязательно

`plan-web.md` на момент груминга ещё нет, поэтому ниже — ПРЕДЛАГАЕМЫЕ ключи и формулировки.
Обязательна (binding) не буква, а СМЫСЛ и названные факты: какая проверка провалилась,
оба числа, направление расхождения, почему кнопка недоступна. Если план ввёл другие
ключи/слова — чеклист идёт за планом, и это не дефект.

| ключ | RU | EN |
|---|---|---|
| `imports.formatAlfaPdfV1` | Альфа-Банк — выписка PDF | Alfa-Bank — PDF statement |
| `imports.uploadFormatAiHint` | Операции из PDF распознаёт ИИ: это дольше и он может ошибиться — проверьте строки перед применением. | Lines in a PDF are read by AI: it takes longer and it can misread — check the rows before you apply. |
| `imports.selfCheckPassed` | Выписка сходится: остаток на начало + операции = остаток на конец. | The statement adds up: opening balance + operations = closing balance. |
| `imports.balanceOpening` / `…Closing` | Остаток на начало: X · на конец: Y | Opening balance: X · closing: Y |
| `imports.selfCheckFailedBalance` | Выписка не сходится: по операциям выходит X, а в выписке конечный остаток Y. | The statement doesn't add up: the operations give X, the statement's closing balance is Y. |
| `imports.applyBlockedSelfCheck` | Пока выписка не сходится, применить её нельзя — найдите пропущенную или неверно прочитанную строку. | While the statement doesn't add up it cannot be applied — find the line that was missed or misread. |
| `imports.balanceMatches` | ✓ Сходится с банком | ✓ Matches the bank |
| `imports.balanceDiffMore` / `…Less` | В приложении на N больше, чем в выписке / на N меньше | The app is N more than the statement / N less |
| `imports.reconcileRun` | Сверить с учётом (ИИ) | Compare with the app (AI) |
| `imports.reconcileRunning` | ИИ сверяет выписку с учётом… | AI is comparing the statement with your records… |
| `imports.reconcileRunningElsewhere` (409) | Сверка уже идёт — дождитесь результата. | A comparison is already running — wait for the result. |
| `imports.discrepancy*` (5 видов) | Нет в учёте / Лишняя в учёте / Другая сумма / Другая дата | Missing in the app / Not in the statement / Amount differs / Date differs |
| `imports.discrepancyFxDifference` | Разница из-за курса | FX difference |
| 503 `AI_NOT_CONFIGURED` | ИИ на этом сервере не настроен — PDF прочитать нечем; загрузите CSV/Excel. | AI is not configured on this server — nothing can read a PDF; upload CSV/Excel instead. |
| 503 `AI_UNAVAILABLE` | ИИ сейчас недоступен, попробуйте позже — файл в порядке. | AI is unavailable right now, try again later — your file is fine. |
| 422 `STATEMENT_EXTRACTION_FAILED` | Не удалось разобрать операции из этого PDF. | Couldn't read the operations out of this PDF. |

## Test cases

STOP-пробы (первый bring-up, до полного прогона; падение любой = стоп и доклад
senior-lead): **TC-1, TC-2, TC-3, TC-7a, TC-8**. Остальные — полный прогон в конце скоупа.

### TC-2 [STOP]: `.pdf` принимается, сходящаяся выписка → предпросмотр с остатками
- **Precondition**: TC-1; счёт `BYN-ok`; фикстура «сходящаяся».
- **Шаги**: прочитать `accept` инпута; загрузить фикстуру (харнесс) с форматом Альфа →
  дождаться навигации на `/imports/:id` → прочитать шапку, строку self-check, остатки,
  список строк, AI-строку `ai-layer`.
- **Ожидаемое**: `accept` содержит `.pdf` (и прежние `.csv`/`.xlsx` не потеряны);
  `POST` → 201 (preflight OPTIONS 200), навигация на сессию; на экране **«Выписка
  сходится…»** в тихом тоне (БЕЗ `role="status"` — это не новость), остаток на начало и
  на конец — реальные числа фикстуры, отформатированы хелпером при валюте выписки
  (BYN, два знака, `tnum`); строки операций есть, их число = `rows_total`; apply/replace/
  cancel доступны; AI-строка категоризации (второй проход, A3) присутствует и не
  противоречит self-check.
- **Network/console**: один multipart POST, затем `GET /{id}` + `GET /{id}/rows`;
  ноль JS-ошибок; никакого поллинга (извлечение синхронно в POST).
- **Status**: ✅ PASS — `accept=.csv,text/csv,.xlsx,…,.pdf,application/pdf` (прочитан из DOM харнессом); OPTIONS 200 → POST 201 → `/imports/5981b325…`; «Собственные суммы выписки сходятся…» БЕЗ `role` (generic), «Банк указывает: 1 000,00 BYN … 1 761,64 BYN», 24 строки = `rows_total`, AI-строка «24 строки стоит проверить.»; сеть: POST + GET session + GET rows, поллинга нет.

### TC-3 [STOP]: несходящаяся выписка — предупреждение с числами и гейт apply/replace
- **Precondition**: счёт `BYN-mismatch`; фикстура «несходящаяся».
- **Шаги**: загрузить → прочитать баннер (узел, тон, `role`), обе кнопки apply/replace и
  их причину; открыть пикер категории на одной строке и сменить категорию; затем cancel.
- **Ожидаемое**: сессия СОЗДАНА (201, не 422) и показана; баннер — warning, с
  `role="status"`, НАЗЫВАЕТ провалившуюся проверку (баланс / приход / расход / даты) и
  печатает ОБА числа (`expected` и `actual`) деньгами, а для `date_range` — без чисел, но
  с человеческой причиной; apply и replace НЕДОСТУПНЫ и рядом с ними написано ПОЧЕМУ
  (`applyBlockedSelfCheck`), а не «не нажимается молча»; PATCH категории на строке
  РАБОТАЕТ (200, категория встала — архитектура §3 разрешает); cancel открывает
  ConfirmDialog, подтверждение уводит на `/accounts` и сессия исчезает.
- **Network**: ни одного `POST /{id}/apply` и `/{id}/replace` за сценарий (кнопки
  действительно гейт, а не косметика); 422 `STATEMENT_BALANCE_MISMATCH` из UI
  недостижим — если он всё же ушёл, его копия обязана быть человеческой, не кодом.
- **Status**: ✅ PASS — сессия создана (201) и показана; баннер `status` называет проверку и оба числа («остаток на конец … 1 774,14 BYN, а её же операции дают 1 761,64 BYN»; БД: expected 177414 / actual 176164); клики по «Выполнить решения» и «Заменить с даты…» НЕ дали ни одного `apply`/`replace-preview` запроса, рядом текст-причина; PATCH категории строки → 200 и чип «Проверьте категорию» ушёл; cancel → ConfirmDialog → `/accounts`, строки в БД больше нет.

### TC-4: apply → строка сверки «✓ сходится с банком» без перезагрузки
- **Precondition**: сессия TC-2 (сходящаяся, счёт `BYN-ok`), в учёте нет своих операций
  периода → остаток приложения после импорта обязан совпасть с конечным.
- **Шаги**: apply → прочитать отчёт и строку сверки остатка на том же экране; перейти в
  `/transactions` по ссылке отчёта и на `/accounts`.
- **Ожидаемое**: отчёт apply как раньше; НОВОЕ — строка «✓ Сходится с банком» с остатком
  приложения на конец периода, появившаяся БЕЗ F5 (инвалидация `['imports', id]`);
  экран стал read-only, строка сверки осталась; в `/transactions` появились операции,
  баланс счёта на `/accounts` пересчитан сервером (инвалидация accounts).
- **Network**: один `POST /{id}/apply`; после него рефетчи `GET /{id}`, транзакций,
  сумм, stats, limits, accounts — и НИ одного запроса к deposits.
- **Status**: ✅ PASS — на счёте без остатка на начало строка честно сказала расхождение, поэтому арм «сходится» снят на отдельном счёте `BYN-ok2` с засеянным остатком 1 000,00: после apply БЕЗ F5 появилось «На счёте теперь 1 761,64 BYN — ровно тот остаток, который указал банк» (generic, без `role`), `/accounts` показал новый баланс; сеть: один `POST /apply` → рефетч accounts + session + rows, ни одного запроса к deposits.

### TC-5: строка сверки ХРАНИМАЯ, а не пересчитываемая
- **Precondition**: TC-4 применён.
- **Шаги**: curl'ом создать одну транзакцию на `BYN-ok` с датой ВНУТРИ периода выписки
  (сумма заметная, напр. −100,00 BYN) → F5 на `/imports/:id`.
- **Ожидаемое**: строка сверки говорит ТО ЖЕ, что в момент apply («✓ сходится»), с теми же
  числами: это запись о моменте применения, а не живой пересчёт. Если после F5 она
  превратилась в «расхождение» — ❌ (нарушен D-B1: значение стало вычисляемым на чтении).
- **Network**: только `GET /{id}` + rows; никакого запроса балансов со страницы импорта.
- **Status**: ✅ PASS — после curl-транзакции −100,00 BYN от 12.09 внутри периода и F5 строка осталась «ровно тот остаток … 1 761,64 BYN» (значение хранимое, D-B1 цел); сеть после F5: session + rows + справочники, запроса балансов нет.

### TC-6: новый replace после расхождения — «расхождение N» с правильным знаком
- **Precondition**: счёт `BYN-drift`; та же сходящаяся фикстура; curl'ом заранее создана
  одна «лишняя» транзакция внутри периода, которой в выписке нет.
- **Шаги**: загрузить фикстуру на `BYN-drift` → путь replace (дата внутри периода, ввод
  `deleted_total`) → подтвердить → прочитать строку сверки.
- **Ожидаемое**: после replace строка говорит «расхождение» и НАЗЫВАЕТ направление:
  в приложении больше/меньше, чем в выписке, на конкретную сумму (знак `balance_diff_minor`
  не теряется и не показывается голым минусом); число — деньгами через хелпер; тон
  предупреждающий, но действия не блокируются (информационно, D-B1); `role="status"`.
- **Status**: ✅ PASS — после replace с 20.09: «На счёте теперь 1 149,08 BYN — это на 612,56 BYN МЕНЬШЕ, чем 1 761,64 BYN…» + предложение с честными причинами; БД `balance_diff_minor=-61256` → знак не потерян и голого минуса на экране нет; арм в `role="status"`, действия не блокируются.

### TC-7a [STOP]: стенд без ИИ — честная копия, и CSV по-прежнему грузится
- **Precondition**: веб `:5198` → API `:8022` (`app.state.llm is None`), логин на этом origin.
- **Шаги**: открыть модалку импорта → проверить, предложена ли Альфа → попытаться
  загрузить PDF-фикстуру → прочитать сообщение; затем в том же окне загрузить
  Приорбанк-CSV на счёт `BYN-csv` и применить.
- **Ожидаемое**: 503 `AI_NOT_CONFIGURED` отрендерен копией «ИИ не настроен… загрузите
  CSV/Excel» (не кодом, не «попробуйте позже» — это конфигурация, а не сбой); модалка
  осталась рабочей (инпут и кнопка живые), сессии-призрака нет; следом CSV проходит
  до предпросмотра и apply, а у его сессии строка self-check = «проверка недоступна»

**D-1 — повторная сверка той же сессии падает с 500 (функциональный, причина API).**
Кнопка «Сверить снова» (и любой второй запуск, который груминг явно разрешил — «the user may

3) тот же POST ещё раз → 500 (воспроизведено и кликом в UI, и curl'ом на двух разных сессиях:
`95999d24…` replaced и `e10ea7a1…` applied).
Причина из лога API (`<scratchpad>/pdfrec/api-8021.log`): клейм ставит
`reconciliation_status='running'`, не обнуляя `reconciliation`, и ломает CHECK миграции 0019 —
`ck_statement_imports_reconciliation_present` = `((status='ok') = (reconciliation IS NOT NULL))`:
`asyncpg.exceptions.CheckViolationError … violates check constraint
"ck_statement_imports_reconciliation_present"`. Транзакция откатывается, строка остаётся `ok`
(зависшего `running` нет), отчёт на экране цел, UI показывает «Не удалось связаться с сервером…»
— то есть веб деградирует корректно, чинить надо серверный клейм (обнулять `reconciliation`
вместе с переводом в `running`, в одном UPDATE).
Веб-замечание к той же истории: 500 без CORS-заголовков превращает любую серверную ошибку в
«нет сети» — копия про недоступный сервер честна, но причина пользователю не видна.
