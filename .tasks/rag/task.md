# RAG: поиск по смыслу в операциях + ответы со ссылками

Скоуп `rag` (портфолио, пункт 9 из `.tasks/ai-portfolio.md`). PLAN 8.5.

## Зачем
Фильтры (дата/счёт/категория/продавец) не отвечают на вопросы по смыслу: «сколько ушло на Польшу в сентябре», «всё про машину», «подарки». Нужен поиск по смыслу и ответы, которые ссылаются на конкретные операции.

## Как должно работать
- Эмбеддинги — **локальная мультиязычная модель внутри нашего API** (RU/PL/EN, без ключей, данные никуда не уходят), работает на проде (VPS 4 GB, 2 vCPU, без GPU).
- Каждая операция индексируется (текст: продавец/описание, категория, страна, счёт — без сумм в тексте эмбеддинга по решению архитектора); новые/изменённые операции индексируются автоматически, удалённые — пропадают из индекса; есть переиндексация.
- **MCP:** инструмент поиска по смыслу (read) — возвращает операции с id, датой, суммой, категорией, оценкой близости + итог в базовой валюте с сервера; Claude в чате отвечает со ссылками.
- **Веб:** в «Операциях» режим поиска по смыслу; результаты + итог суммы с сервера.
- **AI-советник:** вопрос → поиск → ответ модели со ссылками на найденные операции (кликабельно). Без ключа Anthropic/Ollama — честное «не настроено», поиск в вебе и MCP работают и без него.
- **Evals:** recall@k / MRR на наборе вопросов с эталонными операциями (синтетика + обезличенные данные владельца, как в 8.1); проверка «ответ ссылается только на найденные операции» (без выдумок); replay в CI.

## Решения владельца
- Эмбеддинги — локальная модель на сервере.
- Где: MCP, поиск в вебе, вопрос-ответ в советнике — все три.
