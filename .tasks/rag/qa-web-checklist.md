# QA Web Checklist: rag — поиск «по смыслу» на /transactions и вопрос-ответ на /advisor

## Scope

Браузерные journeys ТОЛЬКО по веб-поверхности скоупа (A5): режим «по смыслу» в поисковой области
/transactions (результаты вместо списка, серверный `total` вместо шапки-сводки, строка `pending_count`,
503-арм) и ВТОРАЯ секция на /advisor рядом со стриминговым чатом (вопрос → дословный ответ + кликабельные
цитаты, `dropped_citations`, `answer null`, два 503, 429). Плюс RU/EN, деньги/даты, клавиатура, 375 px,
F5, консоль/сеть.

### НЕ покрывается здесь (и чем закрыто)

- Ранжирование как математика, `min_score`, бакеты `total`, `pending_count` после массового импорта,
  no-oracle, `SEARCH_QUERY_BLANK`, `kind=transfer` → пусто, `QA_CITE_FOREIGN` → `dropped_citations == 1`,
  ноль хитов без вызова LLM, `LLMFAIL` → 503, PAT → 401, лимитеры 30/min и 5/min;30/day — pytest
  (architecture «Test seams» 3–4). Здесь проверяются РЕНДЕР и КОПИЯ этих армов, не их логика.
- Коды/тела, скоупинг по user_id, фильтры на уровне API, MCP-инструмент — curl у qa-engineer; тут curl
  только засевает и ОДИН раз сверяет числа (TC-4). Качество выдачи (recall@k/MRR) — evals S3.
- Чистые веб-модули (относительная шкала score, ссылка цитаты, выбор копии по коду, разбор режима из URL)
  — vitest фронтенд-инженера.
- НОВЫЕ роут и метод (`GET /transactions/search`, `POST /advisor/qa`) обязаны быть вызваны ИЗ приложения
  хотя бы раз — урок CORS 2026-08-18: это TC-2 и TC-10 [STOP].

## Стенд (bring-up)

Своя БД `budget_qa_rag`, два API, два vite (`VITE_API_URL` вшивается в бандл — арм «недоступно» требует
второго origin, прецедент pdf-reconcile).

```sh
# 0. артефакт модели, один раз (A3; apps/api/models/ gitignored)
cd apps/api && uv run python -I scripts/fetch_model.py --manifest model_manifest.json \
  --dest models/multilingual-e5-small
# 1. CREATE DATABASE budget_qa_rag (psql в budget-postgres-1 на 5443) + alembic upgrade head
# 2. :8021 EMBEDDINGS_PROVIDER=onnx LLM_PROVIDER=fake   # всё включено
# 3. :8022 EMBEDDINGS_PROVIDER=off  LLM_PROVIDER=off    # оба 503-арма, ТА ЖЕ БД
#    обоим: CORS_ORIGINS='["http://localhost:5199","http://localhost:5198"]' и ЧЕТЫРЕ гейта false:
#    FX_/RECURRING_/PUSH_/EMBEDDINGS_SCHEDULER_ENABLED (A3)
# 4. VITE_API_URL=http://localhost:8021 pnpm --filter @budget/web dev --port 5199 --strictPort
#    (и 8022 → 5198; `--` не ставить — pnpm его съедает)
```

**Выключенная сметка — рычаг, а не помеха**: без неё нет ни boot-бэкфилла, ни сметки, индексирует только
поиск, по ≤ `search_max_refresh = 64` строк (D-I3c). Основной засев (≤ 60 строк) встаёт первым же
поиском, а «пачка на 80» даёт честный `pending_count > 0` для TC-5.

**Пользователь** `qa-web-rag-1@budgetqa.dev` / `Qa!Test1234` (регистрация curl'ом на :8021). Логин ОДИН
раз на origin; второй вход на `:5198` — единственный допустимый за прогон.

**Засев — только curl, не клики по формам.** Счёт в базовой валюте + счёт в чужой; ~55 операций по темам
из `evidence.md` (Автосервис, Shell Mińsk, Uber / Apteka Gemini, Аптека 36.6 / Biedronka, Евроопт, Lidl
Berlin, Kaufland / Allegro prezent, Подарок маме / Starbucks, Bazyliszek) со странами PL/BY/DE,
категориями и заметками; **одна FX-строка** со снапшотом курса (бакет «снапшот» в `total`) и **одна
строка в валюте без курса** (`unconverted_count > 0`). Пачка из 80 строк заливается ПЕРЕД TC-5, не
раньше. Данных владельца в прогоне нет.

**Доказательства** `<scratchpad>/rag-evidence/TC-<n>.{png,txt}`; скриншот только там, где проверка
визуальная (шкала score, 375 px, две секции /advisor рядом), остальное — `read_page`/`get_page_text`/
`read_network_requests`.

## Копии: binding — смысл, не буква

`plan-web.md` ещё нет; ключи ПРЕДЛАГАЕМЫЕ, чеклист идёт за планом. Обязательные факты: это поиск по
смыслу; оценка ОТНОСИТЕЛЬНАЯ; часть строк ещё не проиндексирована (с числом); почему недоступно
(артефакт ≠ ключ ИИ); цитата ведёт на операцию; лимит — про частоту, не «ошибка сервера».

| ключ | RU | EN |
|---|---|---|
| `tx.searchModeMeaning` / `…Hint` | По смыслу · Опишите словами и нажмите Enter. | By meaning · Describe what you're after, press Enter. |
| `tx.searchScoreTop` | Ближе всего к запросу | Closest match |
| `tx.searchPending` | Часть недавних операций ещё индексируется (N) — повторите через минуту. | N recent operations are still being indexed — search again in a minute. |
| `tx.searchEmpty` | По смыслу ничего не нашлось — попробуйте другие слова или обычный поиск. | Nothing matched by meaning — try other words or the plain search. |
| 503 `EMBEDDINGS_NOT_AVAILABLE` | Поиск по смыслу на этом сервере недоступен — обычный поиск и фильтры работают. | Search by meaning is unavailable here — plain search and filters still work. |
| `advisor.qaTitle` / `qaThinking` | Вопрос по операциям · Ищу операции и готовлю ответ… | Ask about your operations · Finding operations and writing an answer… |
| `advisor.qaCitations` / `qaDropped` | Ответ опирается на эти операции: · N ссылок модели отброшено — они не из найденных. | The answer relies on these operations: · N citations dropped — not among the retrieved. |
| `advisor.qaNothingFound` | По этому вопросу операций не нашлось — ответа не будет. | No operations matched this question, so there is no answer. |
| 503 `AI_NOT_CONFIGURED` (Q&A) | ИИ на этом сервере не настроен — отвечать некому. | AI is not configured on this server — nothing can answer. |
| 429 | Слишком много вопросов подряд — подождите минуту. | Too many questions in a row — wait a minute. |

Тумблер = `role="group" aria-label="Режим поиска"` из двух кнопок со СЛОВАМИ «По словам» / «По смыслу» и `aria-pressed`; активная подсвечена. ### TC-3: ранжирование и ОТНОСИТЕЛЬНАЯ оценка
- **Шаги**: «всё про машину», «подарки», «apteka» (пробы из `evidence.md`) → порядок и чем показан score.
- **Ожидаемое**: сверху авто / подарки / аптеки; оценка ОТНОСИТЕЛЬНАЯ (шкала от лучшего или словесная ступень), **не процент и не голое `0.8412`** — абсолют живёт в 0.78–0.87 и «84 %» соврёт о точности (D-R3); у первого метка «ближе всего»; при единственном результате шкала не вырождается (Q-3); строки рисует прежний рендерер, клик открывает ту же форму. **✅** — «всё про машину» → сверху Автосервис замена масла 0,85 / Автосервис развал-схождение 0,84 / Мойка автомобиля 0,84 / Автосервис диагностика 0,84; «подарки» → Allegro prezent 0,87 / Ozon подарочная упаковка 0,86 / Подарок маме 0,86 / Подарок коллеге 0,86; «apteka» → три Apteka + Аптека 36.6 (0,87…0,84). Оценка — приглушённый бейдж «близость 0,85» (2 знака, `aria-label` «Близость к запросу: 0,85 из 1»), ни процента, ни полосы; относительность сказана ОДИН раз в шапке: «Близость сравнивает найденное между собой — с другим запросом эти числа не сопоставимы» (решение Q-3: метки «ближе всего» нет — так и руллинг). При 2 и 4 результатах бейдж тот же. Строки рисует прежний рендерер, клик открывает ту же форму правки.

### TC-4 [STOP]: серверный total вместо сводки, сверенный с телом API
- **Шаги**: поиск, покрывающий FX-строку и строку без курса → прочитать шапку → тем же `q`+фильтрами дёрнуть `GET /transactions/search` curl'ом и сверить числа.
- **Ожидаемое**: на месте месячной сводки `income/expense/net` ИЗ ОТВЕТА, хелпером в базовой валюте, байт-в-байт как в curl; клиент ничего не складывает; `unconverted_count > 0` сказан строкой, а не проглочен; сказано, что итог — по найденным операциям, а не за месяц (Q-4). **✅** — «кофе в Варшаве злотыми», `range=all`. Экран: «Итог по найденным операциям» вместо месячной сводки, Доход 0,00 ₽ · Расход 79 532,00 ₽ · Итог −79 532,00 ₽ и отдельной строкой «Для 1 операции нет курса, она не вошла в эти итоги.» curl тем же `q`: `{"currency":"RUB","income_minor":0,"expense_minor":7953200,"net_minor":-7953200,"unconverted_count":1}` — совпадает; `candidates:54` и `model` на экран не выводятся. FX-строка показана как `-125,00 PLN ≈ -2 800,00 ₽`.

### TC-5: `pending_count` — честная строка про недоиндексированное
- **Шаги**: залить пачку 80 строк → сразу поиск по слову из пачки → повторить 2–3 раза.
- **Ожидаемое**: при `> 0` ОДНА тихая строка с числом (не баннер, не блокировка); часть новых строк уже в выдаче (refresh ≤ 64 сработал); с повторами число падает и строка исчезает; при `0` строки нет (Q-6). **✅** — 80 строк «Веломагазин №N» залиты curl'ом, первый же поиск «велосипед»: одна тихая строка `role="status"` «16 недавних операций ещё индексируются и могли не попасть в результаты.» (80 − 64 = refresh сработал), новые строки уже в выдаче, блокировки нет. После следующих поисков строки нет (curl подтверждает `pending_count:0`, `candidates:134`). Наблюдение для бэкенда (не веб-дефект): на ВТОРОМ поиске строка ещё показывала 16, хотя тот поиск доиндексировал остаток — число, похоже, отстаёт на один запрос. «Показать больше» → 50 результатов, «Это 50 самых близких операций, а не всё, что есть.»

### TC-6: фильтры составляются с поиском по смыслу
- **Шаги**: «подарки» → наложить период, счёт, категорию, страну → снять по одному.
- **Ожидаемое**: каждый фильтр СУЖАЕТ выдачу и меняет `total` (уходит в тот же запрос, а не режется на клиенте); чипы как в обычном списке и снимаются; `kind=transfer` даёт честный пустой экран с объяснением (переводы не индексируются, D-T4), а не «ничего не нашлось»; виджеты дедлайнов/платежей ведут себя как при суженном списке. **✅ (арм `kind=transfer` — N/A)** — «подарки» + категория «Подарки» → 4 строки, итог 7 930,00 ₽, чип «Категория: Подарки ×»; + страна «Польша» → 2 строки, итог 5 480,00 ₽, два чипа; снятие чипа возвращает прежнюю выдачу. Фильтры уходят НА СЕРВЕР: `…?q=подарки&category_id=…&country=PL&limit=20`, один запрос на изменение. Период: «Вернуться к месяцу» (октябрь 2026) → честная пустая выдача. Сортировка в режиме скрыта с ПРИЧИНОЙ текстом: «Результаты по смыслу упорядочены по близости, поэтому сортировка ждёт поиска по словам.» Виджеты дедлайнов/платежей скрыты при `q` (narrowed). `kind=transfer` недостижим из UI: `parseTxFilters` вообще не разбирает `?kind=` (предсуществующая грамматика экрана), запрос уходит без него; честность про переводы несёт пустая копия («Переводы и движения по долгам по смыслу не ищутся никогда»), API-арм закрыт pytest.

### TC-7: пустой запрос и пустая выдача
- **Шаги**: Enter на пустом поле и на пробелах; затем заведомо бессмысленный запрос.
- **Ожидаемое**: пустой/пробельный НЕ уходит на сервер (422 `SEARCH_QUERY_BLANK` из UI недостижим); пустая выдача — копия с выходом (другие слова / обычный поиск), не вечный скелет и не «ошибка»; `total` при пустой выдаче либо нули, либо скрыт — последовательно с правилом «говорим только то, что правда». **✅ (с замечанием)** — Enter на пустом и на «   » НЕ уходит на сервер (0 новых `search`-запросов), `q` просто исчезает из URL и экран возвращается в idle — 422 `SEARCH_QUERY_BLANK` из UI недостижим. Пустая выдача: «По смыслу ничего не нашлось.» + «Попробуйте другие слова или более широкий период, снимите фильтры или вернитесь к поиску по словам. Переводы и движения по долгам по смыслу не ищутся никогда.» и две кнопки выхода («Искать по словам», «Сбросить поиск и фильтры»); `total` показан нулями — последовательно. Замечание: заведомо бессмысленный запрос («вертолёт на Марсе») даёт НЕ пустоту, а 20 строк с близостью 0,79 — отсечки нет по D-R3, так что пустой арм достижим только фильтрами/периодом.

### TC-8: 503 — поиск по смыслу недоступен (:5198)
- **Шаги**: на `:5198` (`EMBEDDINGS_PROVIDER=off`) включить режим и отправить запрос.
- **Ожидаемое**: копия про недоступный ПОИСК, отличная от «ИИ не настроен» (артефакт vs ключ, D-M6); экран не падает, выход из режима работает, обычный `?q=` и фильтры работают сразу; кода ошибки на экране нет. Если режим не предлагается вовсе — допустимо, но это должно быть СКАЗАНО текстом (Q-2). **✅** — `:5198` (`EMBEDDINGS_PROVIDER=off`), `?mode=meaning&q=подарки`: «Search by meaning is unavailable» / «Search by meaning is unavailable on this server — the word search and the filters still work.» + кнопка «Search by words». Ровно ОДИН `GET …/search` → 503 (ретраев нет, `retry:false` соблюдён), кода ошибки на экране нет, тумблер на месте и не задизейблен заранее. Кнопка перевела экран в `?q=` без `mode`, обычный поиск и фильтры работают сразу.
