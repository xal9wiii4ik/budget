## Вердикты

- **MAJOR-1 (matching: value-match крадёт чужой client_id-матч)** — СОГЛАСЕН.
  Находка доказана пробой, ломала обе гарантии §3/§4 сразу (потеря новой
  операции + дубль при apply). Исправлено: глобальный первый проход по
  client_id с резервированием, затем прежний цикл value/similar. Закреплено
  тестом `test_a_fingerprint_hit_outranks_an_earlier_row_s_value_match`
  (красный без правки — проверен откатом).
- **MAJOR-2 (окно кандидатов уже данных)** — СОГЛАСЕН. Банк режет период по
  дате проведения, txn_date легально выходит за period_from; окно по печатному
  периоду гарантировало дубль на границе. Исправлено: `_candidate_window` =
  период ∪ даты строк, ±`SIMILAR_WINDOW` (константа матчера, не локальная
  копия). Тест `test_an_operation_dated_before_the_period_still_finds_its_record`
  (28.05 при периоде с 01.06) — красный без правки.
- **MINOR-3 (молчаливый 201 с нулём строк при дрейфе даты)** — СОГЛАСЕН.
  Принят строгий вариант: нераспознанная непустая строка внутри открытой
  секции → `StatementParseError`; строка из одних `;` узаконена как пустая
  везде. Вариант «ошибка при нуле строк» отклонён обоснованно (не ловит
  частичный дрейф, падал бы на пустом легитимном блоке). В текст ошибки — только
  первая ячейка (не мерчант/сумма пользователя). Тест дрейфа даты добавлен.
- **MINOR-4 (to_minor_units: докстринг «non-negative» vs отрицательные)** —
  СОГЛАСЕН, это честность контракта. Выбор «узаконить знак в докстринге»
  правильный: ROUND_HALF_UP симметричен (ties away from zero), и второй
  вызывающий (receipts) остаётся неотрицательным по своему валидатору.
- **NIT-5 (осиротевший advisor-комментарий в app.py)** — СОГЛАСЕН, прибрано.
- **NIT-6 (уникальность (import_id, row_index))** — СОГЛАСЕН; индекс сделан
  уникальным внутри 0013 (миграция нигде не применена постоянно).
- **NIT-7 (гонка двух POST → два parsed-превью)** — СОГЛАСЕН, и решение шире
  предложенного: частичный уникальный индекс `uq_statement_imports_live_preview
  (user_id, account_id) WHERE status='parsed'` + advisory-lock по прецеденту
  0011 + recovery-arm (rollback + один повтор, B-1). Живая проба: 8 параллельных
  POST — без 500, одна живая сессия.
