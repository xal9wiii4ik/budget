# statement-import — follow-ups

По итогам живого QA-прогона S4 (2026-08-27, 5/5, блокеров и functional нет)
и закрытия скоупа. Ничто из списка не блокирует использование.

## Косметика из прогона

1. **Диалог apply обещает не то число, которое печатает отчёт.** Подтверждение
   строится из `by_decision` («создать 3»), отчёт — из факта («2 создано,
   1 была раньше»): идемпотентный повтор уходит в `already_existed`. Оба числа
   честные (обещание — оценка, отчёт — факт), но пользователю разница не
   объяснена. Вариант: сноска в диалоге «уже существующие будут пропущены» или
   единая формулировка в отчёте.
2. **Отчёт apply/replace печатает нулевые строки** («пропущено: 0»). Счётчики
   сессии нулевые строки прячут — отчёту стоит делать так же.
3. **375 px: липкий футер (Применить / Заменить с даты / Отменить) занимает три
   строки.** Сжать в один ряд или убрать второстепенные действия в меню.

## Известные ограничения v1 (приняты осознанно, не дефекты)

4. **Фильтр строк (чип match_status) сбрасывается при перезагрузке** — локальный
   state, в URL не вынесен.
5. **Отчёт apply/replace живёт только в теле ответа POST** (§10.6): F5 после
   применения теряет его. Сервер копию не хранит; сессия хранит счётчики и
   статус. Экран истории импортов — вне v1 (таблица `statement_imports` готова).
