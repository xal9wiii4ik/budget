# credo-import — второй банк: Credo (Грузия), выписка Excel

Тир: STANDARD (ревью через /review-pr у инженеров; при MAJOR — круг фикса + мета-ревью).
Факты формата и решения пользователя — в брифе оркестратора (2026-08-28), не пересказываются.
Реальный файл: `.tasks/statement-import/real-credo-local.xlsx` — читать для сверки МОЖНО, в тесты класть НЕЛЬЗЯ.

## Архитектура (грумминг senior-lead)

### Backend — одна подзадача
- `services/statement_import/credo.py` — `FORMAT_ID = "credo_xlsx_v1"`, `parse(bytes) -> ParsedStatement`.
  - Зависимость: **openpyxl** (read-only mode). Чистый Python, только чтение, без pandas.
    Инженер обязан сверить с реальным файлом: деньги ожидаются ТЕКСТОВЫМИ ячейками
    ("6,494.98" с запятой) → Decimal из строки; даты — числовые serial (1900-система) → date.
    Если деньги вдруг числовые — стоп и доклад, из float не брать.
  - Знак: заполненность Turnover(DB)/Turnover(Cr); обе или ни одной → StatementParseError.
  - Самопроверка: balance[i] == balance[i-1] − DB + Cr; первая строка — от остатка на начало
    (Account Details); итоги файла — от итогов листа. Расхождение → STATEMENT_PARSE_FAILED.
  - Пара «потрачено» из описания: regex `<amount> <CCY> <dd.mm.yyyy>` в хвосте → original_*.
  - merchant: для card-операций парсер извлекает латинское имя (описание минус префикс минус
    хвост суммы) в НОВОЕ опциональное поле `ParsedRow.merchant`; apply предпочитает его
    описанию (для prior — None, поведение прежнее, срез описания как был).
  - `bank_category` = оригинальная грузинская строка Operation.
  - `possible_transfer=True` для ჩარიცხვა (зачисление) и კონვერტაცია — прецедент CH Debit/P2P.
  - Неизвестная грузинская фраза = данные, НЕ ошибка (обратно правилу Приорбанка).
- `fingerprint.py` — версия канона становится свойством формата: prior остаётся `prior:v1`
  байт-в-байт (пиновый тест), credo — `credo:v1`; канон от ОРИГИНАЛА, txn_time пустой,
  section — фиксированный токен, occ_index как есть.
- `__init__.py` — строка в PARSERS. `/formats` подхватит сам.
- Контракт: НЕ меняется (formats динамический, RowRead без новых wire-полей).
  Если инженеру покажется, что нужно новое поле в RowRead — стоп и доклад (это смена тира).

### Словарь перевода — НЕ таблица БД, клиентский модуль
Обоснование: перевод — отображение, зависит от языка UI; фраз девять и они заморожены;
БД-таблица дала бы контракт+миграцию+админку ради статичного словаря. 
- `apps/web/src/features/imports/bankPhrases.ts`: карта «оригинальная фраза → ключ i18n»
  (4 операции точным совпадением, 6 префиксов описания — по префиксу), переводы ключей
  в dict.en.ts / dict.ru.ts. Хелпер `translateBankText(text, lang)`: заменяет известное,
  латиницу (магазины) не трогает.
- Метка «непереведено» — производная на клиенте: есть грузинский скрипт И нет в словаре →
  бейдж/тултип с оригиналом. Серверного флага нет.
- Применяется: список строк импорта (Operation + Description). Merchant в списке транзакций —
  тем же хелпером, если дёшево; иначе follow-up.

### Web — одна подзадача (параллельно с бэком, контракт не меняется)
- `imports.formatCredoXlsxV1` в ОБА словаря (иначе формат покажется идентификатором).
- accept загрузки: + `.xlsx`.
- bankPhrases.ts + хелпер + бейдж непереведённого.

## Тесты (по брифу — что реально может сломаться)
Бэк: serial-даты; знак из двух колонок; пара из описания; самопроверка остатка ловит сдвиг
колонки; неизвестная фраза не роняет; отпечаток стабилен при повторной загрузке;
пин канона prior:v1 не сдвинулся рефакторингом. Фикстуры — синтетический xlsx, собранный
openpyxl в тесте по образцу реального (числа/структура свои).
Веб: unit на translateBankText (известное/префикс/неизвестное).

## Дополнения после «поехали» (2026-08-28)

### Цена решения «словарь на клиенте» (названа вслух, по требованию оркестратора)
Новая грузинская фраза банка = правка кода и выкладка. В нашем файле один месяц и четыре
вида операций; переводы другому человеку, платежи по счетам, возвраты в него просто не
попали — появятся на второй-третьей выписке. Поэтому бейдж «непереведено» — СИГНАЛ, а не
украшение: заметный, не спрятанный. По его частоте решаем, когда переносить словарь в БД.

### Условия приёмки (оркестратор)
1. **Самопроверка по остатку — без ложных срабатываний.** Прогнать на настоящем файле
   (`.tasks/statement-import/real-credo-local.xlsx`, читать можно, в тесты нельзя) на всех
   73 строках. Округления/сбросы остатка на границах — пережить. Текст ошибки называет
   строку, на которой разошёлся расчёт.
2. **Мерчант без хвоста:** `გადახდა - YANDEX.EDA 56.10 BYN 01.08.2026` → `YANDEX.EDA`.
   Проверить кавычки: `SHOP "SANTA-362" BAPB`, `SHOP "N26 ZHIVINKA"`.
3. **Пин канона prior:v1** — тест, краснеющий при любом сдвиге канона Приорбанка.
   Сдвиг = переимпорт всей истории пользователя как «новой».

### Факты из настоящего файла (извлечены из sharedStrings, senior-lead)
- Виды операций (колонка Operation, ровно 4): `საბარათე ოპერაცია` (card operation),
  `უნაღდო კონვერტაცია` (конвертация), `ბარათზე თანხის ჩარიცხვა` (зачисление на карту),
  `სხვა და სხვა საკომისიო` (прочие комиссии).
- Грузинских префиксов описания ДВА (не шесть): `გადახდა` (оплата), `განაღდება` (снятие
  наличных). Плюс латинский `Currency Exchange` (без мерчанта и пары). Часть описаний пустые.
  Инженеры сверяют по распарсенному листу, а не только по sharedStrings.
- Имя владельца на листе Account Details — грузинское (`ვალერია ბენიაშ`): данные, не словарь.
- Пара «потрачено»: встречаются BYN, USD, CHF. CHF вне SUPPORTED_CURRENCIES — для
  original_currency это допустимо (гейт только на базовую валюту), экспонента по фолбэку 2.
- Случай «валюта пары == валюте счёта» (`გადახდა - WWW.SIMPLEWAY.BY 145.42 USD` на
  USD-счёте): по конвенции prior пара НЕ сохраняется (original_* = None).
- Суммы в паре — без разделителя тысяч (`1000.00 BYN`); суммы в колонках — с запятой
  (`1,000.00`) и текстовыми ячейками (проверить в парсере, из float не брать).
- Заголовки Transactions: Date | Operation | Turnover (DB) | Turnover (Cr) | Balance |
  Description | Beneficiary Name | Beneficiary Account. Account Details: Opening Balance
  15,355.04 / Closing 17,862.22 / Income 6,494.98 / Expenses 3,987.80 / USD /
  период 01.08.2026–28.08.2026.
