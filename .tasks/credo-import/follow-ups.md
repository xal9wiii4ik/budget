# credo-import — хвосты скоупа

## 1. Различимый отказ «банк сменил выгрузку на числовые ячейки» (отложено, PM 2026-08-28)
Сегодня: `credo.py::_money` отказывает с текстом «the bank exported the amounts as
numbers, not as text» + лист/строка/колонка; текст доезжает только до серверного лога
(`routers/statement_imports.py:743`, INFO), клиент видит общий `STATEMENT_PARSE_FAILED`.
Решение PM: отдельный код НЕ заводим, пока случай гипотетический — плохой прецедент
(у парсера десяток внутренних причин отказа).

Рецепт на день, когда Credo реально сменит выгрузку:
- новый доменный код в `_unprocessable`-ветке загрузки (например `STATEMENT_MONEY_NOT_TEXT`),
  поднимать из `StatementParseError`-подтипа или маркера; тело — по образцу
  `STATEMENT_CURRENCY_MISMATCH` (§10.7), если понадобятся детали;
- регенерация контрактной пары (описания в docstring роутера = контракт) + прогон
  четырёх потребителей;
- подпись в `packages/shared/src/i18n/errors.ts` (обе локали): «банк выгрузил суммы
  числами, а не текстом — файл нормальный, чинить нам; пришлите файл в поддержку»;
- тест: числовой xlsx → новый код (сегодняшний тест пинит причину в сообщении исключения —
  переключить на код).

## 2. Перевод merchant в общем списке транзакций
`translateBankText` применяется на экране импорта. После apply мерчант Credo почти всегда
латинский (парсер изолирует имя магазина), но строки без изолированного имени (комиссии
`სხვა და სხვა საკომისიო`, конвертации) уносят грузинский текст в `transactions.merchant`.
Если пользователь пожалуется — прогнать отображение merchant в списке транзакций через
тот же хелпер (`apps/web/src/features/imports/bankPhrases.ts`), он уже принимает `t`.
