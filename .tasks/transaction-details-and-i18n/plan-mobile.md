# Implementation Plan (mobile): transaction-details-and-i18n — S6 (ОТЛОЖЕННАЯ ЛИНИЯ)

Мобилка ЗАМОРОЖЕНА, кода нет. Оценки — агент-минуты: **написание / гейты
(typecheck+lint+vitest) / верификация на симуляторе (idb+Expo Go, вручную, дорого)**.

## Обратная совместимость S1 — ПОДТВЕРЖДАЮ по чтению кода
- Create с мобилки не шлёт `currency` вообще (transaction-form.tsx:357-367) — сервер
  штампует от счёта. Новую пару `original_*` мобилка не шлёт → NULL → сегодняшнее
  поведение. Новые nullable-поля в `TransactionRead` игнорируются, typecheck после
  регенерации `schema.d.ts` не ломается.
- ЕДИНСТВЕННЫЙ риск: если original-пара окажется НЕ-optional в `TransactionCreate/
  Update` — замороженная мобилка ломается на компиляции. Требование к контракту.

## (a) S1-UI — original-сумма + валюта в форме — **60 / 15 / 45**
- Раскрывашка «Потрачено в другой валюте» → LabeledInput + чипы валют. Чипы уже есть
  инлайном в `account-form.tsx:219-260` — вынести в общий `CurrencyChips` (+10 мин).
- Два разных экспонента в одной форме (`amount` по валюте счёта, `original_amount` по
  выбранной) — главный источник багов; поддержать обязана схема в `packages/shared`.
- `buildTransactionPatch` под original-пару правит ВЕБ-линия (`packages/api-client`),
  мобилка её потребляет. Лейбл суммы уже называет валюту в baseline.

## (b) S2 — страна траты — **25 / 10 / 20**
- Одно поле alpha-2, дефолт из `profile.country` (S1). Полный список 240 стран на
  мобилке — вес бандла; рекомендую «недавние + ввод». Маппинг страна→валюта из
  `packages/shared`, не дублировать.

## (c) S3 — фото (image-picker + presigned PUT) — **120 / 25 / 90**
- **Прецедента загрузки в мобилке НЕТ**: в `package.json` нет `expo-image-picker`,
  `expo-image-manipulator`, `expo-file-system`; экранов `receipts/*` нет (в `app/` 14
  файлов). Greenfield + 3 новых нативных модуля → нужно явное одобрение senior-lead.
  В Expo Go все три есть (dev-client не нужен для QA), для standalone — строки
  разрешений в `app.json` + ребилд EAS.
- Работы: разрешения + graceful «denied» с путём в Настройки, сжатие ~1500px,
  presign через apiClient, PUT в MinIO ОБЫЧНЫМ fetch (не authFetch: coordinator.ts:211
  прямо заявляет «JSON or empty — no FormData/stream edge»), attach `receipt_id`,
  миниатюра/просмотр по presigned GET, retry на флаки-сети.
- Верификация: симулятор не даёт камеру (только фотопленка), Android-ветка разрешений
  другая → честная проверка требует физического устройства (сейчас блокер).

## (d) S4 — merchant в формах и в списке — **25 / 10 / 20**
- Поля merchant в форме нет; `initial.merchant` (:241) — только baseline диффа, а
  `buildTransactionPatch` **намеренно НИКОГДА не эмитит merchant**
  (`packages/api-client/src/patch.test.ts:161` — предохранитель, чтобы мобильный edit
  не стирал merchant с чека). S4 = веб снимает предохранитель, мобилка ОБЯЗАНА
  добавить поле в тот же релиз, иначе edit с телефона начнёт стирать merchant.
  **Жёсткая связка: либо оба, либо ни одного.**
- Список: `TransactionRow.tsx:63-73` — merchant главным текстом, note вторичным
  (сейчас главный — имя категории). Строка уже `memo`.

## (e) S5-mobile — i18n RN-слоя — **90 / 20 / 40**
- Механизм: тот же лёгкий словарный слой из `packages/shared`, что выберет веб. Без
  i18next. `expo-localization` УЖЕ в зависимостях (`src/lib/locale.ts` → `APP_LOCALE`) —
  готовый детект языка до логина.
- Объём: ~32 tsx-файла, ~85 строк в JSX/пропсах + `src/data/errors.ts` (199 строк,
  словарь кодов ошибок F6) ≈ **150-200 ключей**.
- Язык из профиля (колонка S1) через Query; до логина — локаль устройства. Ради языка
  добавлять AsyncStorage не стоит (и токены там запрещены) — решение за senior-lead.
- Системные категории: UUID→ключ из `packages/shared`, имя из API как fallback — код
  общий с вебом, мобилка потребитель.

## Риски
- НЕ-optional original-поля в контракте ломают компиляцию замороженной мобилки.
- Рассинхрон S4 web/mobile = тихая потеря merchant при edit с телефона.
- Симулятор не покрывает камеру, Android-разрешения и swipe-back — для S3 нужен
  mobile-qa на устройстве.
