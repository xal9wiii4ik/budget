# Эксперимент: куда уходят токены агентов

Прогнан 2026-08-28. Вопрос был: правда ли, что расход агентов уходит в чтение
крупных исходников, и окупается ли разбиение файлов.

## Метод

Одна и та же задача на понимание — четыре вопроса про операции (исключение
переводов из агрегатов, смена вида операции, повтор по `client_id`, ответ на
чужой ресурс), дословно одинаковая формулировка, свежий агент одного типа
(`backend-engineer`), только чтение, без правок.

Замер А — на роутере в 1529 строк. Замер Б — после переноса четырёх групп
(выгрузка CSV, разбор фильтров, проверки записи, сериализация) в отдельные
модули; роутер 1043 строки.

Плановое «две сопоставимые подзадачи» из карточки заменено на одну и ту же
задачу дважды: две разные задачи различаются сильнее, чем измеряемый эффект.

## Результат

| | А (1529) | Б (1043 + 4 модуля) |
|---|---|---|
| токенов | 42 956 | 52 281 |
| обращений к инструментам | 20 | 18 |
| время | 105 с | 98 с |

**Экономии нет.** Разброс между запусками агента сам по себе даёт ±20%, поэтому
рост на 22% при n=1 читается как «эффекта не видно», а не как «стало хуже».

## Почему

Ни один из прогонов не читал роутер целиком: оба шли через `docs/backend.md` и
точечный поиск. Карточка предполагала ~120 000 токенов на чтение файла — по
факту вся задача уложилась в 43–52 тысячи. Механизм «сначала дока, потом код
точечно» уже съел ту экономию, которую предполагалось получить разбиением.

## Решения

1. Разбиение роутера **оставлено** (коммит `0183dfb`) — но по причине
   поддерживаемости, а не токенов. Контракт байт-в-байт, тесты не тронуты.
2. Файлы ради экономии токенов **больше не режем**.
3. Настоящий рычаг — не исходники, а **окружение QA**: в раскладке аккаунта
   `web-qa` = 17% расхода, и около трети внутри неё уходит на поднятие стенда
   заново в каждом прогоне (свой vite, прокси, страницы входа). Постоянный
   рецепт стенда сэкономит кратно больше любого рефакторинга.
4. Преамбулы агентов считаются арифметикой, а не экспериментом:
   `senior-lead.md` — 254 строки ≈ 6000 токенов на запуск. Сжатие формулировок
   (не правил) даёт порядка 2–3% дневного расхода.

## Что осталось непроверенным

Замер сделан на задаче ПОНИМАНИЯ. Задача с ПРАВКОЙ файла может вести себя
иначе: перед изменением агент чаще читает файл целиком. Если однажды понадобится
— мерить тем же способом, одной задачей дважды.
