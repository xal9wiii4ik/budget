# Скоуп `mcp-receipt-upload` — загрузка чеков через MCP

Запрос пользователя (2026-08-23): «надо дать возможность через mcp загружать чеки».

## Почему этого нет сегодня

Чеки сознательно исключены из allowlist MCP при закрытии скоупа `mcp-server`
с формулировкой «бинарный presigned-flow, бессмысленен через stdio». Причина
была верной для наивной реализации: гонять байты картинки через диалог с
моделью — значит забить контекст и заплатить за это токенами.

Но вывод из неё сделан слишком широкий. MCP-сервер — это ЛОКАЛЬНЫЙ процесс на
машине пользователя. Он умеет читать файл с диска сам, и модель байтов не видит
вообще.

## Что делаем

Инструмент, принимающий ПУТЬ к файлу, а не его содержимое. Внутри:
`POST /receipts` → получить подписанную ссылку → залить байты напрямую в
хранилище → вернуть модели идентификатор чека и статус.

Модель получает на руки только идентификатор. Дальше он используется как обычно:
привязка к операции полем `receipt_id`, которое уже описано в инструментах.

Распознавание (`POST /receipts/{id}/parse`) — ОТДЕЛЬНОЕ решение, см. открытые
вопросы: оно требует ключа AI, которого у пользователя пока нет.

## Безопасность — главная часть скоупа

Инструмент, читающий произвольный путь на диске, — это новая поверхность.
Сервер работает от имени пользователя, значит технически может прочитать всё,
что доступно пользователю, и отправить это в хранилище. Модель может ошибиться
или получить инъекцию из чужого текста (например из описания в чужом документе).

Проработать и обосновать:
- ограничение по типу: только изображения, проверка по СОДЕРЖИМОМУ (магические
  байты), а не по расширению — расширение подделывается тривиально;
- потолок размера, согласованный с тем, что принимает хранилище;
- ограничение по расположению: разрешать только внутри каталога, заданного
  переменной окружения (например `BUDGET_UPLOAD_DIR`), либо явный список.
  Рекомендация: по умолчанию НЕ разрешать ничего, кроме явно настроенного
  каталога — пустая настройка означает «инструмент недоступен»;
- запрет на символические ссылки, ведущие наружу разрешённого каталога;
- курируемое описание должно объяснять модели, что путь берётся ИЗ ПРОСЬБЫ
  ПОЛЬЗОВАТЕЛЯ, а не подбирается и не угадывается.

Скоуп доступа: только `full`. Токену на чтение инструмент не публикуется.

## Открытые вопросы

1. **Распознавание через MCP** — давать ли `parse`? Без ключа AI он честно
   отвечает отказом; с ключом это трата денег по реплике в чате. Рекомендация:
   в этой версии НЕ давать, только загрузку и привязку.
2. **Каталог по умолчанию** — оставлять ли инструмент выключенным, пока
   пользователь не задаст каталог. Рекомендация: да, выключен по умолчанию.
3. **Идемпотентность** — повторный вызов с тем же файлом создаст второй чек.
   Нужна ли защита (например по хешу содержимого) или достаточно того, что
   лишний чек не портит деньги. Рекомендация: достаточно, чек без привязки к
   операции ни на что не влияет.

## Границы

- Контракт API менять НЕ требуется: все три эндпоинта уже есть.
- Мобилку не трогаем.
- Помнить правило от 2026-08-23: изменения в инструментах прогоняют тесты всех
  четырёх потребителей контракта.
