# QA Web checklist: recurring-book-now («+» списать сейчас)

Статус: **ГРУММИНГ, не прогон.** Все TC — ⏸ pending.

## Скоуп
Только то, что навязывает браузер: две точки входа («+» в виджете предстоящих на
/transactions и на строке /recurring), модалка BookNowModal с редактируемой
суммой, инвалидация после успеха БЕЗ перезагрузки, дизейбл кнопки в полёте,
маршрутизация 422 в ТОСТ (а не в поле формы), клавиатура/фокус, 375px, первый
браузерный вызов НОВОГО маршрута `POST /recurring/{id}/book` (CORS/preflight).

Вне скоупа (чужое): коды и тела ответов, идемпотентность, ватермарка, скоупинг,
границы `amount_minor` — секция qa-engineer (pytest + curl). Чистая логика
(деривация «кнопка есть/нет», prefill суммы, code→канал) — vitest фронта.

Бюджет: **4 живых сценария** (потолок скоупа 12–15 суммарно; ≤9–10 у
qa-engineer, одно место оставлено в запас). Живой прогон — ОДИН, в конце скоупа.

## TC-1 — сквозной happy path из виджета (главный сценарий)
- **Precondition**: /transactions, виджет предстоящих содержит `T-TODAY`;
  запомнить остаток счёта на /accounts и число строк списка.
- **Steps**:
  1. Открыть /transactions, нажать «+» на строке `T-TODAY`.
  2. Прочитать модалку: имя шаблона, дата срока, счёт — read-only; сумма —
     редактируемая, prefill из шаблона в ₽ с 2 знаками (не `12.500000001`).
  3. Изменить сумму на отличную от шаблонной, сохранить.
- **Expected**: `POST /recurring/{id}/book` из приложения → 201 **без
  CORS/preflight-ошибки** (обязательная браузерная проба нового метода/маршрута);
  БЕЗ F5: новая строка в списке транзакций с ПРАВЛЕНОЙ суммой и датой = сегодня
  (D3), строка `T-TODAY` ушла из виджета, месячная сводка и остаток счёта на
  /accounts обновились, на /recurring у шаблона `next_due_on` сдвинулся вперёд, а
  сумма шаблона осталась ПРЕЖНЕЙ (D4 — правка разовая). Ровно один POST book,
  никаких повторов/шторма рефетчей. Хвост: F5 на /transactions и /recurring —
  состояние восстанавливается, редиректа на логин нет.
- **Status**: ⏸ pending

## TC-2 — вход со строки /recurring + «+» нет у паузнутого + клавиатура + 375px
- **Precondition**: /recurring; в списке `T-SOON` (активен, есть `next_due_on`) и
  `T-PAUSED`.
- **Steps**:
  1. У `T-PAUSED` — убедиться, что кнопки «+» нет (D5/D9).
  2. Дойти до «+» строки `T-SOON` **только Tab**, открыть Enter'ом; поле суммы
     имеет связанный label; сохранить с клавиатуры; после закрытия проверить фокус.
  3. Переключить окно на 375×812 и повторить открытие модалки на `T-SOON`.
- **Expected**: букается `next_due_on` шаблона (та дата, что показана в строке);
  201; БЕЗ F5 строка `T-SOON` показывает следующий срок, а в виджете на
  /transactions ближайшая строка этого шаблона исчезла. Сценарий проходим
  клавиатурой целиком, фокус после закрытия — на триггере. На 375px модалка и
  кнопка «Сохранить» не уезжают за экран, суммы/даты не обрезаны (единственный
  скриншот прогона — здесь, проверяет обе поверхности разом).
- **Status**: ⏸ pending

## TC-3 — двойной клик не создаёт две операции
- **Precondition**: активный шаблон с pending-сроком (пере-создать `T-TODAY`
  curl'ом), число строк списка зафиксировано.
- **Steps**: открыть модалку, дважды быстро нажать «Сохранить».
- **Expected**: кнопка disabled в полёте; в network-логе РОВНО ОДИН
  `POST …/book`; в списке транзакций ровно одна новая строка; остаток счёта
  изменился один раз. (Серверную половину — второй запрос ждёт замок и получает
  422 — доказывает pytest, живьём не гоняем.)
- **Status**: ⏸ pending

## TC-4 — устаревший срок: тост, а не ошибка в поле; виджет самолечится
- **Precondition**: /transactions открыт, виджет содержит `T-STALE`.
- **Steps**:
  1. НЕ трогая вкладку, забукать этот же срок curl'ом (эмуляция второй вкладки /
     ночной джобы).
  2. Нажать «+» на устаревшей строке в виджете и сохранить.
- **Expected**: 422 `DUE_DATE_NOT_PENDING` показан **тостом** «срок уже
  списан/обновился», а не ошибкой под полем суммы; экран не пустой и не «белый»;
  после этого виджет сам делает refetch и устаревшая строка исчезает БЕЗ F5;
  вторая транзакция НЕ создана; повторное открытие «+» на другой строке работает
  (нет ловушки фокуса и залипшего disabled).
- **Status**: ⏸ pending

## Реестр вычеркнутого (чем закрыто)
- **Коды 422/404** `DUE_DATE_NOT_PENDING`, `RECURRING_TEMPLATE_PAUSED`,
  `ACCOUNT_ARCHIVED`, `RECURRING_TEMPLATE_NOT_FOUND`, тела и envelope — pytest
  B1 + curl-секция qa-engineer. Браузер проверяет ОДИН из них (TC-4) и только
  как канал доставки (тост vs поле).
- **Идемпотентность / ватермарка / замок / досрочное списание и `occurred_at`** —
  pytest B1 (D2, D3). Живьём недостижимо и деньги дублировать нельзя.
- **Границы `amount_minor` (0, отрицательное, int-переполнение)** — pytest +
  curl; в браузере это zod-схема формы → vitest фронта, не живой TC.
- **`amount_minor` не меняет шаблон (D4)** — утверждается внутри TC-1 (проверка
  суммы шаблона на /recurring), отдельного TC не заводим.
- **Паузнутый шаблон отвечает 422** — pytest; браузерная половина (кнопки нет) —
  ассерт внутри TC-2, не отдельный TC.
- **Архивный счёт → 422** — pytest/curl; в браузере не гоняем, пока PM не решит
  открытый вопрос №3 (показывать «+» или прятать); канал тоста уже доказан TC-4.
- **Скоупинг по user_id (чужой шаблон → 404)** — pytest; второго живого
  пользователя в прогоне нет.
- **Контрактный дрейф openapi.json ↔ schema.d.ts** — существующий drift-тест +
  typecheck.
- **Инвалидация виджета при pause/resume, кап 5 строк, пометка «сегодня»** —
  закрыто прошлым скоупом (LV-6/LV-7, V-4), не переигрываем.
- **Deep-link и F5** — сложены хвостом в TC-1, отдельного TC нет.

## Предлагается закрыть vitest'ом (фронт, не QA)
- `canBookNow(template)` / деривация видимости «+»: paused → нет; нет
  `next_due_on` → нет; активный → есть.
- prefill суммы: минорные единицы шаблона → строка формы и обратно (shared
  `parseMoney`), включая валюту с экспонентой 0.
- маршрутизация серверного кода: `DUE_DATE_NOT_PENDING` → канал «тост+refetch»,
  прочие → поле/баннер (`lib/errors.ts`).
- дифф i18n: ключи модалки есть в dict.en и dict.ru (страхуется typecheck).
