# AI-слой: LLM-категоризация + evals

Скоуп `ai-layer` (портфолио, пункты 1–2 из `.tasks/ai-portfolio.md`).

## Зачем
Показать управление качеством работы LLM: структурированный вывод, уверенность, ручная проверка, измеренная точность. Сейчас категории ставятся только правилами (карты продавцов и категорий банка).

## Как должно работать
- Интерфейс провайдера LLM: Anthropic (Claude API), Ollama (локально, проверим позже), и фейк/replay для тестов. Выбор провайдера и модели — настройкой; без ключа/без Ollama — честное «AI не настроен», ничего не ломается.
- `categorize(operation, categories)` → структурированный ответ по JSON-схеме: категория (только из категорий пользователя), уверенность 0–1, короткое обоснование. Ответ валидируется сервером; невалидный ответ = «не уверен».
- Где применяется: при импорте выписки — сначала существующие правила, LLM только для строк, которые правила не покрыли; низкая уверенность (порог — настройка) → строка помечается «проверь категорию» в превью импорта. Обоснование видно пользователю.
- Evals: набор из реальных операций владельца, обезличенный (имена людей, номера карт/счетов, заметки — вырезаны; продавцы-компании остаются), с эталонной категорией. Скрипт: точность, стоимость, задержка по провайдеру × модели × версии промпта → отчёт (markdown/json). Регрессия в CI без платных вызовов (replay записанных ответов) с порогом точности.
- Цифр в резюме не пишем, пока не будет реального прогона (ключ или Ollama — позже).

## Решения владельца
- Набор evals — из его операций с прода, обезличенный; сырой экспорт лежит локально `.tasks/ai-layer/real-eval-local.csv` (gitignored, 250 строк); в репозиторий — только обезличенный набор, владелец смотрит его до коммита.
