# QA Web Checklist: ai-layer W1 — AI suggestions on the statement-import preview

## Scope
Браузерные user-journeys ТОЛЬКО по тому, что W1 добавил на `/imports/:id` (`plan-web.md`):
AI-строка в шапке (`aiStatusLine`), источник «подсказка ИИ» + reason verbatim, бейдж
«Проверьте категорию», чип «На проверку · N» (toggle, AND со статус-чипами, скрытие при N=0,
скрытие блока группового решения), снятие флага при выборе категории, read-only сессия, F5,
RU/EN, тёмная тема, 375 px, консоль/сеть.

НЕ покрывается здесь (и почему):
- `aiStatusLine` как функция (пять арм, нули, плюралы) — закрыто `aiStatusLine.test.ts` (vitest),
  в браузере проверяется только РЕНДЕР тех арм, что стенд умеет выдать.
- Коды/валидация/скоупинг/квоты/`?needs_review=` на уровне API, выбор батчей, порог уверенности —
  pytest бэкенда + API-QA (`test_statement_imports_ai.py`, `test_categorize.py`).
- Путь загрузки файла (аккаунт → кнопка в шапке → `ImportUploadModal` → `/imports/:id`) — уже
  доказан вживую в `.tasks/statement-import/qa-web-checklist.md` (WJ-1); W1 его не трогает.
  Поэтому сессии для сценариев ниже готовятся curl'ом (политика «подготовка состояния — curl»),
  а браузер дёргает новое сам: GET rows c `needs_review`, PATCH строки.
- `ai_status = not_configured`: НЕ проверяемо в браузере на этом стенде — веб ходит только на
  :8021 (`LLM_PROVIDER=fake`), а API с выключенным ИИ стоит на :8022, куда веб не смотрит.
  Строка `imports.aiOff` закрыта юнит-тестом хелпера; живой рендер остаётся непокрытым.

## Данные и стенд
Стенд (поднят, не мой): веб `http://localhost:5199` → API `http://localhost:8021`
(`LLM_PROVIDER=fake`: имя категории как подстрока текста операции → эта категория + reason
`name match`; иначе `needs_review` без категории; `LLMFAIL` в тексте валит вызов).
Пользователь: `qa-web-ai-1@budgetqa.dev`. Фикстуры (cp1251, Приорбанк) — в scratchpad, не в репо:
`fixture-ai-ok.csv` (3 сматчено / 3 на проверку), `fixture-ai-failed.csv` (одна строка с LLMFAIL,
один батч → `failed`), `fixture-ai-partial.csv` (26 строк: батч 1 жив, во втором LLMFAIL →
`partial`, 20 suggested / 0 flagged). По сессии на свой счёт — вытеснение `parsed` идёт
по паре (user, account).

## Test cases

### TC-1: RU, сессия `ok` — что пользователь видит на готовом предпросмотре
- **Precondition**: сессия `ok` (3 llm-подсказки, 3 флага), язык RU.
- **Шаги**: открыть `/imports/:id` сессии `ok`, прочитать шапку, сматченную и флаговую строки.
- **Ожидаемое**: в шапке тихая строка «ИИ подсказал категорию для 3 строк · 3 на проверку»
  (без `role=status`); у сматченной строки категория подставлена, строка источника
  «подсказка ИИ» и ОТДЕЛЬНАЯ строка с серверным текстом `name match` дословно (не переведён);
  у флаговой строки «Без категории» + warning-бейдж «Проверьте категорию»; чип «На проверку · 3».
  Нигде нет числа уверенности (ни `0.9`, ни `90%`).
- **Status**: ✅

### TC-2: чип «На проверку» — сужение списка, подсказка, скрытый блок группового решения
- **Precondition**: TC-1.
- **Шаги**: включить чип → прочитать список, подсказку и наличие блока «групповое решение»;
  выключить чип.
- **Ожидаемое**: в списке ровно 3 флаговые строки; `aria-pressed=true`; под чипом подсказка
  `imports.needsReviewHint`; блок группового решения СКРЫТ, пока чип включён; выключение
  возвращает все 6 строк и блок.
- **Network**: GET rows уходит с `needs_review=true` (и без него после выключения).
- **Status**: ✅

### TC-3: AND со статус-чипами (не ИЛИ, не клиентское пересечение)
- **Precondition**: чип включён.
- **Шаги**: при включённом чипе выбрать статус-чип «Новые», затем «Совпадает точно».
- **Ожидаемое**: «Новые» + чип → те же 3 строки; «Совпадает точно» + чип → пустое состояние
  именно `imports.rowsEmptyNeedsReview`, а не общая «ничего не найдено»; счётчик на чипе
  остаётся 3 (сессионный, НЕ пересекается с фильтром на клиенте).
- **Network**: в одном запросе rows присутствуют ОБА параметра (`match_status=…&needs_review=true`).
- **Status**: ✅

### TC-4: выбрал категорию на флаговой строке — флаг снят, счётчик правдив, строка не прыгает
- **Precondition**: чип включён, 3 флаговые строки.
- **Шаги**: на одной флаговой строке выбрать категорию через `CategoryPickerModal`.
- **Ожидаемое**: бейдж «Проверьте категорию» с этой строки исчез, категория показана; строка
  ОСТАЛАСЬ в отфильтрованном списке (ACCEPTED в `plan-web.md`, не дефект); счётчик чипа
  3 → 2 и шапка пересчиталась (рефетч СЕССИИ после PATCH); rows не инвалидируются.
- **Network**: PATCH строки → 200, затем GET сессии; нет рефетча страниц rows.
- **Status**: ✅

### TC-5: чип исчезает, когда проверять больше нечего
- **Precondition**: TC-4.
- **Шаги**: снять флаг с оставшихся строк, затем выключить чип.
- **Ожидаемое**: пока чип включён, он виден со счётчиком 0 (иначе выключить его было бы
