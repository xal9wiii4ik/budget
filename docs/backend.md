# backend.md — apps/api map

Src root: `apps/api/src/budget_api/`. App factory `app.py:create_app` (engine/sessionmaker/settings/limiter on `app.state`, built in lifespan).

## Routers (`routers/`, mounted in app.py)
- `/health` — DB probe; 503 with HealthResponse body when DB down; never blocks boot.
- `/auth` — login/refresh/logout + fastapi-users register/reset-password; slowapi limits (login 10/min, register 5/h, forgot 5/h) via `prime_rate_limit` dep.
- `/users` — stock fastapi-users router: GET/PATCH `/me`; `/{id}` superuser-gated, dead-but-harmless (no superusers).
- `/categories` — list (archived-inclusive)/create/patch; seed system rows read-only (`SYSTEM_CATEGORY_READONLY`).
- `/transactions` — CRUD + `GET /summary` + `GET /export` (streaming CSV, BOM, content-disposition); `/summary` and `/export` declared BEFORE `/{id}` (route-order landmine). POST takes optional `client_id` (UUID): a replay with the same client_id returns the STORED row with 200, not a duplicate (B-1 idempotency: select-first + partial unique index + IntegrityError recovery). Every tx belongs to an account (`account_id` required); server STAMPS `currency` from the account, a disagreeing sent value → 422 `ACCOUNT_CURRENCY_MISMATCH`. Third kind `transfer` = ONE row with `counter_account_id`/`counter_amount_minor`/`counter_currency` (stamped from target); no category, base-snapshot pair NULL (CHECKs in 0008); read-only `transfer_rate` computed on read (Decimal string, major units, ROUND_HALF_UP; null when both legs same currency). PATCH `kind` to/from transfer → 422 `KIND_CHANGE_UNSUPPORTED`. Filter `?account_id=` matches EITHER leg (an account's history = both legs); `?kind=` works for transfer. S3 list filters: `?q=` — case-insensitive ILIKE substring over `merchant` OR `note` only (LIKE metachars escaped, so user input is never a wildcard; blank = filter absent); `?country=` — exact, `Query(pattern=COUNTRY_PATTERN)` → 422 before the DB; `?sort=` — `date_desc` (default, byte-identical to the pre-S3 ordering)|`date_asc`|`amount_desc`|`amount_asc`, all with `id` last so offset paging is total, amount sorts compare RAW `amount_minor` (no conversion: the base snapshot is NULL on transfers/no-rate rows). `services/tx_read_query.read_filters` is shared, so `/export` takes `q`/`country` too but NOT `sort` (oldest-first by D13). No pg_trgm/GIN index — DEFERRED until real volumes (grooming decision). CSV includes transfers: columns `account, counter_account, counter_amount` (counter formatted at TARGET currency exponent), base cells empty. Router = routes + HTTP only; the rest is split out (`services/tx_read_query.py` filters+ORDER BY, `services/tx_export_csv.py` CSV format, `transaction_guards.py` ref guards, `transaction_wire.py` row→wire) — the idempotency helpers (`_load_own`, `_load_by_client_id`, `_recover_replay_race`) deliberately stayed in the router. Handler docstrings ARE the OpenAPI descriptions: rewording one changes the contract.
- `/accounts` — list/create/patch (NO delete — archive only, like categories); archived-inclusive list, each row carries computed `balance_minor` (§2 of scope architecture: starting + income − expense − transfer-out + transfer-in, one grouped SQL, all terms already in the account's currency). `currency` immutable on PATCH → 422 `ACCOUNT_CURRENCY_IMMUTABLE`; writes to archived account (either leg) → 422 `ACCOUNT_ARCHIVED`; types `card|cash` (enums.py AccountType); a `type='deposit'` row is the hidden 1:1 ledger of a `deposits` row — filtered out of the list IN SQL, PATCH on it → 404 `ACCOUNT_NOT_FOUND` (there is NO GET/DELETE `/accounts/{id}` route at all — 405), POST with `type=deposit` → 422 schema error (see `/deposits`).
- `/deposits` (0012) — list/create/detail/patch; NO delete — archive only, and REVERSIBLE: the one write an archived deposit accepts is `PATCH {"archived": false}` ALONE (any field beside it → 422 `DEPOSIT_UNARCHIVE_ONLY`; every other PATCH → 422 `DEPOSIT_ARCHIVED`). POST creates TWO rows in one tx — the hidden ledger account + the deposit; `initial_balance_minor` lands on the account's `starting_balance_minor` (a setup fact, NOT a back-dated transfer). Nothing about money is patchable: the body moves only through POST /transactions transfers (`GET /transactions?account_id=<ledger>` IS the deposit's history); expense/income on a deposit ledger → 422 `DEPOSIT_ACCOUNT_TRANSFER_ONLY` (guards in transactions.py AND recurring.py); archive cascades to the account in the SAME tx, so the closed-money door is the EXISTING `ACCOUNT_ARCHIVED` guard. Read fields computed per request, stored nowhere (`services/deposit_reads.py` DepositView → `domain/deposits.py`): `balance_minor`, `accrued_minor`, `accrued_after_tax_minor` (null when no tax rate), `status` (`matured` once `term_end <= today`, accrual frozen ON term_end). The one user-writable interest number is the anchor `accrued_override_minor` — its `as_of` date is STAMPED by the server, `null` clears back to computed, omit = keep. Rates go out as normalized decimal STRINGS (`format(v.normalize(),'f')`: "10.00" → "10", never scientific notation). PAT allowlist: the two GETs only — POST/PATCH deliberately absent → 403 `TOKEN_ENDPOINT_FORBIDDEN` (pat_auth.py, PM 2026-08-27).
- `/debts` (0017) — list/create/detail/patch/DELETE + repayments CRUD (`POST`/`PATCH`/`DELETE /debts/{id}/repayments[/{rid}]`). A debt movement IS an ordinary `transactions` row (kind expense|income) carrying the trio `debt_id`/`debt_role`/`debt_amount_minor`, so balances move like real money while `tx_totals` cuts the rows out of every aggregate by `debt_id IS NULL` — lending is not spending (task.md §3). `debts` stores NO money: the principal IS the opening row (one per debt, partial unique index), repayments are more rows, and `remaining_minor`/`status`/`closed_on` are computed per read (`services/debt_reads.py` → `domain/debts.py`; deleting a repayment REOPENS a closed debt by arithmetic). `direction` (lent|borrowed) and `currency` are IMMUTABLE (absent from `DebtUpdate`): `domain/debts.movement_kind` derives each movement's kind from the direction (lent+principal=expense, lent+repayment=income, borrowed mirrored), so a direction change would retro-flip booked money — hence a REAL `DELETE` with `ON DELETE CASCADE` (movements go, balances revert). Wire naming: `amount_minor` = the DEBT currency, `account_amount_minor` (+`account_currency`) = what moved on the account; they map to `debt_amount_minor`/`amount_minor` in the DB. ONE currency rule for every movement: currencies differ → `account_amount_minor` REQUIRED (422 `DEBT_ACCOUNT_AMOUNT_REQUIRED`, no rate snapshot — the transfer precedent), equal → server copies, disagreeing value → 422 `DEBT_ACCOUNT_AMOUNT_NOT_APPLICABLE`; a PATCH moving a movement to a third currency → 422 `AMOUNT_REQUIRED_ON_CURRENCY_CHANGE`. Overpayment is refused under `SELECT … FOR UPDATE` on the debts row (`services/debt_writes.py`, the ONLY writer: lock → totals → refuse): 422 `DEBT_REPAYMENT_EXCEEDS_REMAINING` (also the answer on a closed debt — no `DEBT_CLOSED`) / `DEBT_PRINCIPAL_BELOW_REPAID`. Accounts resolve through the EXISTING `transaction_guards` trio; `GET /debts` is archive-inclusive style (ALL debts, no `?status=`) and carries `summary` (both sides Σ `remaining` of OPEN debts converted debt→base at TODAY's nearest-previous rate with per-side `*_unconverted_count`, per-call rate cache). Both POSTs take `client_id` (B-1 replay → 200 with the stored debt; the shared lookup is `services/tx_idempotency.py`). MCP: `list_debts`/`get_debt` (read), `create_debt`/`update_debt`/`record_debt_repayment` (write, managed `client_id`); the DELETEs and the repayment PATCH are `# MCP: no`.
- `/fx` — `GET /convert` preview (nearest-previous daily rate).
- `/goals` — CRUD + archive; `/{id}/contributions` CRUD; `/{id}/progress` series. List response carries `free_balance_basis` (`average|declared|none`) + `free_balance_months_with_data`: free balance = avg over the last-3-full-months window with the DENOMINATOR = months that HAVE data (income>0 or expense>0 or unconverted>0) → else the declared `monthly_income_minor` → else 0. Ladder + counter live in `domain/goals.py` (`months_with_data`, shared by the amount and the basis so they cannot disagree); assembler returns frozen dataclass `GoalPortfolio`.
- `/goals/{goal_id}/items` (goal-planner, 0011) — the plan tree. GET returns a FLAT list ordered (depth, sort_order, id) — the client builds the tree; every node carries SERVER rollups: `children_sum_minor` (sum of children bubbles up, own amount is only a ceiling — `ceiling_exceeded` is a FIELD, not an error), `paid_minor` (+`paid_unconverted_count`), `planned_unconverted_count` (no rate → counted, never summed as zero), `eff_deadline`+`deadline_inherited` (two-level COALESCE parent→goal computed on READ; the `deadline` column stays NULL, so moving the goal's deadline moves every inherited date), `files_count`/`subtree_files_count`. Limits in Settings: `goal_item_max_depth=6`, `goal_items_max_per_goal=500`, `goal_item_files_max_per_item=10`. Cycle/depth refused pre-write in ONE ancestor walk (`GOAL_ITEM_CYCLE`/`GOAL_ITEM_DEPTH_EXCEEDED`); the CONCURRENT re-parent race is held by DB trigger `trg_goal_items_no_cycle` (pg_advisory_xact_lock on goal id), whose check_violation maps to the SAME 422, never 500. `GET /goals/upcoming?days=1..90` is declared BEFORE `/goals/{goal_id}` (route-order landmine); rows are context-complete (goal, parent, currency, paid, reminder_date). Payment link lives on transactions: `goal_item_id` — expense-only (422 `GOAL_ITEM_EXPENSE_ONLY`, CHECK in 0011), foreign/missing node → 404 no-oracle, ON DELETE SET NULL (deleting a node UNLINKS payments, never deletes them); tx filter `?goal_item_id=` matches the node's SUBTREE.
- `/goals/{goal_id}/items/{item_id}/files` — receipts-style: POST presign PUT slot → POST confirm (server HEAD to MinIO: missing object → 409 `FILE_NOT_UPLOADED`, >5MB → 422 `IMAGE_TOO_LARGE`; MinIO down → 503 `STORAGE_UNAVAILABLE`) → `view_url` minted ONLY for `uploaded=true` and only in the files GET (the tree carries counters, not URLs — a 500-node plan must not mint thousands of presigned URLs). Node/subtree delete removes the objects from MinIO best-effort in a background task.
- `/profile` — GET (PAT-readable) / PATCH (JWT-only, per-field omit/null/value). PATCH takes `language`, `country`, and since base-currency scope `base_currency` (explicit null → 422 `BASE_CURRENCY_REQUIRED`; membership vs `SUPPORTED_CURRENCIES` → 422 `CURRENCY_NOT_SUPPORTED`, case-sensitive) + `monthly_income_minor` (null clears; ge 0, le MAX_MINOR_AMOUNT). A base switch is DISPLAY-only: no snapshot recompute, no data touched (`tx_totals` bucket order already prefers the stored snapshot); it also CLEARS `monthly_income_minor` in the same transaction — the client re-declares explicitly.
- `/recurring` — template CRUD (no pagination/filters by design, D10). `account_id` required (materializer books onto it); `kind` stays expense|income — recurring transfers unsupported in v1 (422). PATCH can MOVE a template to another account (B3): currency restamped from the new account, "new account + old currency" refused whole (`ACCOUNT_CURRENCY_MISMATCH`), watermark untouched. A move ACROSS currencies must carry `amount_minor` in the same PATCH — 422 `AMOUNT_REQUIRED_ON_CURRENCY_CHANGE`, checked BEFORE the currency-echo gate (the stored integer is minor units of the OLD stamp; restamping alone would silently redefine what the job books every period). `start_date` (0010, nullable): future start seeds the watermark to start−1 so nothing books earlier; too-early → 422 `START_DATE_TOO_EARLY` (floor: create < today-UTC; PATCH ≤ min(watermark, today) — no silent clamp); `START_DATE_AFTER_END_DATE` is the SAME string code on create and PATCH (effective pair vs stored values); explicit null clears with watermark = min(current, today); upper bound 2999-12-31 → 422, not a 500 from calendar math. `GET /recurring/upcoming` (`days` 1–90, default 30; PAT allowlisted): UNmaterialized charges with dates ≥ today-UTC only (booked-today rows excluded via the watermark), paused excluded, end_date cuts, sorted by date then created_at; same `domain/recurrence.py` helper as `next_due_on`, so the two can't diverge.
- `/limits` — `GET` (month-scoped, with spent), `PUT`/`DELETE` per category.
- `/stats` — `/summary`, `/monthly` (trailing window, NOT period-scoped), `/top-merchants`; period grammar in query (month|quarter|year|custom). AUTH-FIRST param order is load-bearing.
- `/receipts` — `POST` (presigned MinIO PUT, 201; 30/min per user), `GET /{id}` (poll), `POST /{id}/parse` (202, claim via UPDATE…RETURNING; 10/min;100/day per user). Both `ReceiptRead` responses carry `view_url`: a presigned GET minted per read (TTL `s3_presign_get_ttl_seconds`), null while `pending` — only a status past pending proves the object exists, since the parse claim is gated on a HEAD 200 (`_UPLOAD_PROVEN_STATUSES`); no read ever does a HEAD of its own.
- `/statement-imports` (0013, statement-import scope) — импорт выписки Приорбанка. POST multipart (file+account_id+format; ЕДИНСТВЕННЫЙ multipart-роут API, 10/min) — cp1251 декодирует сервер, парсит, матчит, 201 = сессия со счётчиками; GET `/{id}` — счётчики в ДВУХ разрезах (`by_match_status` = что нашлось, `by_decision` = что сделает apply); GET `/{id}/rows` (offset/limit ≤ 200, фильтр `match_status`; RowRead несёт деньги В ФОРМЕ ТРАНЗАКЦИИ (§10.1: amount_minor+currency+original_*), типизированный `fee_minor`, `merchant` ТРЁХЗНАЧЕН: имя, вырезанное парсером из описания | `""` — парсер посмотрел и мерчанта в строке нет (сбор, обмен: транзакция создастся БЕЗ мерчанта, предложение в имя не превращается) | null — формат имён не выделяет вовсе, описание и есть имя (весь Приорбанк), и ВСТРОЕННЫЕ `candidates`-мини-строки — ноль дозапросов с экрана); PATCH `/{id}/rows/{row_id}` → 200 с обновлённым RowRead (точечный кеш-апдейт клиента); POST `/{id}/rows/bulk-decision` (одно решение всем строкам статуса → сессия); POST `/{id}/apply` (решения строк, одна БД-транзакция, отчёт ТОЛЬКО в теле ответа — §10.6, персистентности нет); GET `/{id}/replace-preview?from=` (сервер считает удаляемое + гибнущие связи чек/цель/шаблон + «переводы останутся»); POST `/{id}/replace` (body: `from_date` + `confirm_deleted_total`); DELETE `/{id}` (только parsed, 204); GET `/formats` — ключи `FORMAT_IDS` (союз `PARSERS` + `EXTRACTORS`) в порядке реестра плюс `ai_formats` (= ключи `EXTRACTORS`) и `ai_available` (= `app.state.llm is not None`) — `StatementFormatsRead`, объявлен ДО `/{import_id}`: веб наполняет поле «Банк» с сервера, гейт AI-форматов берёт оттуда же (своей копии списка у клиента нет), новый банк не требует релиза клиента. Жизненный цикл: parsed → applied|replaced (дальше всё → 422 `IMPORT_FINISHED`); новая загрузка по тому же счёту вытесняет предыдущую parsed-сессию. Replace НИКОГДА не удаляет transfer-строки и движения долгов (`apply.DELETABLE_BY_REPLACE`: одна строка = история другой сущности; их числа в preview отдельно — `transfers_kept` + `debt_movements_kept`). MCP — НЕТ для всех одиннадцати маршрутов (две сверки — JWT-only через `current_active_user`, PAT отвечает 401 как у `/push`/`/tokens`, пары в `NEVER_PAT`), механикой fail-closed allowlist (маршруты без `@mcp_tool`/`@pat_reachable` недоступны токеном по построению): apply/replace — необратимые массовые мутации без экрана информированного подтверждения у агента, остальное — полу-flow, ведущий только к ним (архитектура §6). LLM-проход (ai-layer) идёт ПОСЛЕ правил и только по строкам, где правила ничего не нашли, `match_status != exact` и у пользователя ЕСТЬ видимая категория того же kind (иначе строку физически нечем ответить — она не в счёте статуса, а если таких все, то `skipped`): строка получает `ai_confidence`/`ai_reason`/`needs_review`, а при названной категории — третий `suggestion_source='llm'` и тот же сид, что у правил (`category_id` + `suggested_category_id`, `category_user_set` остаётся false, карты по-прежнему учатся только на PATCH пользователя); на сессии — `ai_status` (`not_configured|skipped|ok|partial|failed`), `ai_provider`/`ai_model`/`ai_prompt_version` и ДВА счётчика НА ЧТЕНИИ `ai_rows_suggested`/`ai_rows_flagged`. Импорт НИКОГДА не падает из-за AI: любая ошибка оставляет строки нетронутыми и двигает только `ai_status`, причина — в лог-строке `log_call`, не в поле. Проход считается ДО `try` аплоада, поэтому IntegrityError-ретрай не тратит ни токена. Фильтр `?needs_review=` комбинируется с `match_status` (отсутствие = все строки); PATCH с `category_id` — значением ИЛИ явным null — снимает `needs_review` («пользователь посмотрел»), PATCH только решения и bulk-decision — нет. Квота — прямой удар по лимитеру (`<scope>:categorize:<user_id>`, `cost=<строк>`) из `categorize_daily_row_quota`, без возврата за упавший батч.

Язык `explanation`/`summary` — `profile.language`, передаётся в документ промпта.

Все четыре с `# MCP: no — escalation surface` и в `NEVER_PAT`. RFC-эндпоинты (`/oauth/{authorize,token,register}`, `/.well-known/oauth-*`, `/mcp`) — Starlette-маршруты ВНЕ контракта (`oauth/routes.py`), пакет `oauth/` описан в `docs/mcp.md`.

## Top-level helpers
- `ai_gate.py` — `require_ai_configured`: 503 `AI_NOT_CONFIGURED` when `anthropic_api_key` empty. ONE key shared by receipts+advisor. Receipts call it INLINE (preserves 401-before-503 and quota counting); advisor uses `Depends` (unkeyed 503 consumes no quota).
- `rate_limit.py` — process-global slowapi limiter; per-app enable/limits via contextvar primed by `prime_rate_limit`; storage isolated per app by `rate_limit_scope` uuid key prefix; headers disabled; 429 body `{"detail": "RATE_LIMITED"}`.
- `category_access.py` — user-scoped category load; foreign/missing → one `None` path (no-oracle).
- `debt_access.py` — same pattern at BOTH levels: `load_own_debt` / `load_own_repayment` (the repayment load pins `debt_role='repayment'`, so the principal cannot be addressed there) → one 404 `DEBT_NOT_FOUND` for foreign, missing and wrong-debt alike.

- `0016` oauth connector: `oauth_clients` (DCR, `client_secret_hash` только SHA-256) + `oauth_authorization_requests` / `_codes` / `_access_tokens` / `_refresh_tokens` + ALTER `personal_access_tokens` (`token_hash` NULLABLE, `oauth_client_id` FK RESTRICT, CHECK `ck_personal_access_tokens_credential` = XOR «ровно один вид credential»; грант = строка этой таблицы, поэтому весь конвейер pat_auth→allowlist→scope→audit работает без второй ветки). Downgrade СИМметричен и УДАЛЯЕТ гранты (вместе с их audit-строками) — откат 0016 = отключение всех подключённых AI-приложений.
- `0017` debts: `debts` (metadata only — direction/counterparty/currency/due_on/note, two CHECKs, `ix_debts_user_id`) + `transactions` link trio `debt_id` (FK CASCADE) / `debt_role` / `debt_amount_minor` with NINE hand-written CHECKs (`debt_link_trio`, `debt_role_valid`, `debt_amounts_positive`, `debt_not_transfer`, `debt_no_category`, `debt_no_base_snapshot`, `debt_no_goal_item`, `debt_no_original`, `debt_no_recurring` — alembic cannot diff CHECKs on an existing table, the 0016 rule) + two PARTIAL indexes (`ix_transactions_debt_id`, `uq_transactions_debt_principal`) + `push_reminder_sends.debts`. No backfill. The downgrade is symmetric and KEEPS the rows: former movements stay plain expense/income, so balances stay right and the aggregates absorb them (unlike 0012/0016, where the row itself was unrepresentable).
- `0018` statement-ai: `statement_imports` + `ai_status` (String(16), NOT NULL, server_default `'not_configured'` — существующие сессии читаются честно) с CHECK `ai_status_valid` и трио `ai_provider`/`ai_model`/`ai_prompt_version`; `statement_import_rows` + `ai_confidence` Numeric(4,3) / `ai_reason` String(300) / `needs_review` Boolean NOT NULL false; CHECK `suggestion_source_valid` СНЯТ и создан под ТЕМ ЖЕ именем с добавленным третьим значением `llm` (прецедент 0012 `ck_accounts_type_valid`; alembic не диффит CHECK существующей таблицы, поэтому порядок значений в `StatementSuggestionSource` — единственная защита, пинится тестом). Downgrade симметричен и ОСТАВЛЯЕТ деньги: `llm`-подсказки обнуляются (`suggestion_source`/`suggested_category_id`), но `category_id` сохраняется — это то значение, которое пользователь видел в превью.
- `0019` pdf-reconcile: `statement_imports` + 16 columns in four families — anchors (`opening_balance_minor`/`closing_balance_minor`), self-check (`self_check_status` NOT NULL default `'not_available'` + `self_check_failed` + expected/actual, CHECKs `self_check_status_valid`/`self_check_failed_valid`/`self_check_detail`), post-import check (`balance_check` NOT NULL default `'not_available'` + `app_balance_minor_at_end`/`balance_diff_minor`, CHECKs `balance_check_valid`/`balance_check_pair`), agent (`reconciliation_status` NOT NULL default `'none'` + `reconciliation_started_at`/`reconciled_at`/`reconciliation` JSONB + provenance trio, CHECKs `reconciliation_status_valid`/`reconciliation_present` = `(status='ok') = (reconciliation IS NOT NULL)`). ## Remote MCP transport (lifespan)
- Only when `PUBLIC_BASE_URL` is set: `create_app` builds `(server, manager) = mcp.remote.build_remote(app)` → `app.state.mcp_manager`, and the lifespan enters `manager.run()` plus the ONE `httpx.AsyncClient(ASGITransport(app, raise_app_exceptions=False), base_url="http://budget.internal")` on `app.state.mcp_api_client` (an AsyncExitStack, so the transport is torn down before the client it borrows). Empty setting = both stay None, no `/mcp`, no OAuth routes — dev, the whole pytest suite bar its own tests, the contract export. Details: docs/mcp.md.

## Scheduler (lifespan, APScheduler)
- Built only if a gate is on; whole pytest suite runs with all three gates (fx/recurring/push) false (no scheduler object at all).
- fx: cron 17:30 UTC (`FX_SCHEDULER_ENABLED`, `fx_fetch_hour/minute_utc`), misfire grace 3600 coalesced; boot catch-up probe → run-now job; backfill 400 days on empty provider.
- recurring: cron 00:30 UTC (`RECURRING_SCHEDULER_ENABLED`), `materialize_due`; plus an UNCONDITIONAL run-now boot catch-up job (D5) — a restart materializes today's due occurrences immediately.
- push: cron 06:00 UTC (`PUSH_SCHEDULER_ENABLED`, `push_reminder_hour/minute_utc`), `send_daily_reminders`, grace 3600 coalesced, deliberately NO boot run-now job (a restart must not push; a late-evening catch-up would deliver a stale "morning" digest). Registered with the gate on even when VAPID is unset (the job no-ops).

## CORS (app.py, gotcha)
- `allow_methods` is a HAND-LISTED verb set — a new HTTP verb served to the browser MUST be added there or every preflight for it gets 400 (bit us live: `PUT /limits` shipped while the list ended at DELETE). Pinned by `tests/test_cors.py::test_preflight_allows_every_verb_the_api_serves`, which derives the verb set from the exported OpenAPI.

## Error envelope
- Domain errors: `HTTPException(detail="STRING_CODE")` — e.g. `CATEGORY_NOT_FOUND`, `CATEGORY_ARCHIVED`, `CATEGORY_NOT_EXPENSE`, `GOAL_NOT_FOUND`, `CONTRIBUTION_EXCEEDS_SAVED`, `RECEIPT_PROCESSING`, `IMAGE_TOO_LARGE`, `LOGIN_BAD_CREDENTIALS`, `REFRESH_TOKEN_INVALID`, `RATE_LIMITED`, `AI_NOT_CONFIGURED`, `STORAGE_UNAVAILABLE`, `TOKEN_INVALID` (401), `TOKEN_ENDPOINT_FORBIDDEN`/`TOKEN_SCOPE_READONLY` (403), `TOKEN_NOT_FOUND`, `ACCOUNT_NOT_FOUND` (404 no-oracle), `GOAL_ITEM_NOT_FOUND` (404 no-oracle), `GOAL_ARCHIVED`/`GOAL_ITEM_CYCLE`/`GOAL_ITEM_DEPTH_EXCEEDED`/`GOAL_ITEMS_LIMIT_EXCEEDED`/`GOAL_ITEM_PARENT_NOT_FOUND` (422 — body ref, not a path resource)/`GOAL_ITEM_EXPENSE_ONLY`/`GOAL_ITEM_REMIND_CONFLICT`/`GOAL_ITEM_CONVERTED_NOT_APPLICABLE`/`GOAL_ITEM_FILES_LIMIT_EXCEEDED`, `FILE_NOT_UPLOADED` (409), `ACCOUNT_ARCHIVED`/`ACCOUNT_CURRENCY_MISMATCH`/`ACCOUNT_CURRENCY_IMMUTABLE`/`SAME_ACCOUNT_TRANSFER`/`TRANSFER_FIELDS_REQUIRED`/`COUNTER_FIELDS_WITHOUT_TRANSFER`/`KIND_CHANGE_UNSUPPORTED` (422), `DEPOSIT_NOT_FOUND` (404 no-oracle, checked BEFORE archived so a foreign archived id never says `DEPOSIT_ARCHIVED`), `DEPOSIT_TERM_BEFORE_OPENING`/`DEPOSIT_ARCHIVED`/`DEPOSIT_UNARCHIVE_ONLY`/`DEPOSIT_ACCOUNT_TRANSFER_ONLY`/`DEPOSIT_<FIELD>_REQUIRED` (null sent to a non-nullable deposit field) (422).
- Debt codes: `DEBT_NOT_FOUND` (404 no-oracle, both levels), `DEBT_MOVEMENT_READONLY` (422 — PATCH/DELETE `/transactions` on a debt movement, `replace_own` on one, at both statement-import sites), `DEBT_REPAYMENT_EXCEEDS_REMAINING` / `DEBT_PRINCIPAL_BELOW_REPAID` / `DEBT_ACCOUNT_AMOUNT_REQUIRED` / `DEBT_ACCOUNT_AMOUNT_NOT_APPLICABLE` / `DEBT_DUE_BEFORE_OPENING` / `DEBT_<FIELD>_REQUIRED` (explicit null sent to a NOT NULL fact on a PATCH: `counterparty`/`amount_minor`/`account_id`/`opened_on`/`occurred_at`; `account_amount_minor` is NOT one of them — there null ≡ omitted and the server recomputes) / `CLIENT_ID_IN_USE` (a `client_id` already spent on a non-debt transaction, or — on `POST /debts/{id}/repayments` — on a DIFFERENT debt than the path's) (422).
- pdf-reconcile codes: 422 `STATEMENT_BALANCE_MISMATCH` (apply/replace on a `self_check_status='failed'` session — the numbers are on the session read, the body stays bare) / `RECONCILIATION_FAILED` / `RECONCILIATION_TOO_LARGE`; 409 `RECONCILIATION_RUNNING`; 503 `AI_NOT_CONFIGURED` (from `require_llm_provider`, same string as the key gate) / `AI_UNAVAILABLE`.
- Push codes: `PUSH_NOT_CONFIGURED` (503), `PUSH_ENDPOINT_INVALID` (422).
- OAuth codes: `OAUTH_REQUEST_NOT_FOUND`, `OAUTH_APP_NOT_FOUND` (404 no-oracle). RFC-эндпоинты отвечают НЕ этим конвертом, а конвертами RFC 6749/7591 (`{"error": ...}`) — они вне контракта.
- Statement-import codes: `IMPORT_NOT_FOUND` (404 no-oracle, оба уровня — сессия и строка), 422 `STATEMENT_TOO_LARGE` (гейт 1 МБ до чтения) / `STATEMENT_PARSE_FAILED` / `STATEMENT_FORMAT_UNKNOWN` / `STATEMENT_CURRENCY_MISMATCH` (тело несёт `statement_currency`+`account_currency` — §10.7) / `IMPORT_FINISHED` / `DECISION_NEEDS_MATCH` (replace_own без matched_tx_id) / `TRANSFER_REPLACE_FORBIDDEN` / `DEBT_MOVEMENT_READONLY` / `REPLACE_FROM_OUT_OF_RANGE` / `REPLACE_CONFIRMATION_MISMATCH` (тело несёт `confirm_deleted_total`+`deleted_total`) / `STATEMENT_EXTRACTION_FAILED` (pdf-reconcile: модель отдала непригодное, чанк потерян, бюджет времени вышел — «файл, попробуй ещё раз»); 503 `AI_NOT_CONFIGURED` (загрузка формата из `EXTRACTORS` на сервере без `app.state.llm`, гейт `ai_gate.require_llm_provider` ВНУТРИ хендлера — после account/size/format, чтобы 401/404/422 шли раньше) / `AI_UNAVAILABLE` (обрыв провайдера на чтении: 422 сказал бы, что плох файл); квота извлечения — `<scope>:extract:<user_id>`, `cost=<строк>` из `extract_daily_line_quota`, отказ = 429 до первого вызова.
- 422 pattern: routes declare `_UNPROCESSABLE` with raw `anyOf` [DomainError-schema, HTTPValidationError] — honest union without mangling the generated component.
- No-oracle 404s: foreign and missing ids share ONE code path and a byte-identical body; logout always 204; forgot-password never reveals account existence.
