# backend.md — apps/api map

Src root: `apps/api/src/budget_api/`. App factory `app.py:create_app` (engine/sessionmaker/settings/limiter on `app.state`, built in lifespan).

## Routers (`routers/`, mounted in app.py)
- `/health` — DB probe; 503 with HealthResponse body when DB down; never blocks boot.
- `/auth` — login/refresh/logout + fastapi-users register/reset-password; slowapi limits (login 10/min, register 5/h, forgot 5/h) via `prime_rate_limit` dep.
- `/users` — stock fastapi-users router: GET/PATCH `/me`; `/{id}` superuser-gated, dead-but-harmless (no superusers).
- `/categories` — list (archived-inclusive)/create/patch; seed system rows read-only (`SYSTEM_CATEGORY_READONLY`).
- `/transactions` — CRUD + `GET /summary` + `GET /export` (streaming CSV, BOM, content-disposition); `/summary` and `/export` declared BEFORE `/{id}` (route-order landmine). POST takes optional `client_id` (UUID): a replay with the same client_id returns the STORED row with 200, not a duplicate (B-1 idempotency: select-first + partial unique index + IntegrityError recovery). Every tx belongs to an account (`account_id` required); server STAMPS `currency` from the account, a disagreeing sent value → 422 `ACCOUNT_CURRENCY_MISMATCH`. Third kind `transfer` = ONE row with `counter_account_id`/`counter_amount_minor`/`counter_currency` (stamped from target); no category, base-snapshot pair NULL (CHECKs in 0008); read-only `transfer_rate` computed on read (Decimal string, major units, ROUND_HALF_UP; null when both legs same currency). PATCH `kind` to/from transfer → 422 `KIND_CHANGE_UNSUPPORTED`. Filter `?account_id=` matches EITHER leg (an account's history = both legs); `?kind=` works for transfer. S3 list filters: `?q=` — case-insensitive ILIKE substring over `merchant` OR `note` only (LIKE metachars escaped, so user input is never a wildcard; blank = filter absent); `?country=` — exact, `Query(pattern=COUNTRY_PATTERN)` → 422 before the DB; `?sort=` — `date_desc` (default, byte-identical to the pre-S3 ordering)|`date_asc`|`amount_desc`|`amount_asc`, all with `id` last so offset paging is total, amount sorts compare RAW `amount_minor` (no conversion: the base snapshot is NULL on transfers/no-rate rows). `services/tx_read_query.read_filters` is shared, so `/export` takes `q`/`country` too but NOT `sort` (oldest-first by D13). No pg_trgm/GIN index — DEFERRED until real volumes (grooming decision). CSV includes transfers: columns `account, counter_account, counter_amount` (counter formatted at TARGET currency exponent), base cells empty. Router = routes + HTTP only; the rest is split out (`services/tx_read_query.py` filters+ORDER BY, `services/tx_export_csv.py` CSV format, `transaction_guards.py` ref guards, `transaction_wire.py` row→wire) — the idempotency helpers (`_load_own`, `_load_by_client_id`, `_recover_replay_race`) deliberately stayed in the router. Handler docstrings ARE the OpenAPI descriptions: rewording one changes the contract.
- `/accounts` — list/create/patch (NO delete — archive only, like categories); archived-inclusive list, each row carries computed `balance_minor` (§2 of scope architecture: starting + income − expense − transfer-out + transfer-in, one grouped SQL, all terms already in the account's currency). `currency` immutable on PATCH → 422 `ACCOUNT_CURRENCY_IMMUTABLE`; writes to archived account (either leg) → 422 `ACCOUNT_ARCHIVED`; types `card|cash` (enums.py AccountType); a `type='deposit'` row is the hidden 1:1 ledger of a `deposits` row — filtered out of the list IN SQL, PATCH on it → 404 `ACCOUNT_NOT_FOUND` (there is NO GET/DELETE `/accounts/{id}` route at all — 405), POST with `type=deposit` → 422 schema error (see `/deposits`).
- `/deposits` (0012) — list/create/detail/patch; NO delete — archive only, and REVERSIBLE: the one write an archived deposit accepts is `PATCH {"archived": false}` ALONE (any field beside it → 422 `DEPOSIT_UNARCHIVE_ONLY`; every other PATCH → 422 `DEPOSIT_ARCHIVED`). POST creates TWO rows in one tx — the hidden ledger account + the deposit; `initial_balance_minor` lands on the account's `starting_balance_minor` (a setup fact, NOT a back-dated transfer). Nothing about money is patchable: the body moves only through POST /transactions transfers (`GET /transactions?account_id=<ledger>` IS the deposit's history); expense/income on a deposit ledger → 422 `DEPOSIT_ACCOUNT_TRANSFER_ONLY` (guards in transactions.py AND recurring.py); archive cascades to the account in the SAME tx, so the closed-money door is the EXISTING `ACCOUNT_ARCHIVED` guard. Read fields computed per request, stored nowhere (`services/deposit_reads.py` DepositView → `domain/deposits.py`): `balance_minor`, `accrued_minor`, `accrued_after_tax_minor` (null when no tax rate), `status` (`matured` once `term_end <= today`, accrual frozen ON term_end). The one user-writable interest number is the anchor `accrued_override_minor` — its `as_of` date is STAMPED by the server, `null` clears back to computed, omit = keep. Rates go out as normalized decimal STRINGS (`format(v.normalize(),'f')`: "10.00" → "10", never scientific notation). PAT allowlist: the two GETs only — POST/PATCH deliberately absent → 403 `TOKEN_ENDPOINT_FORBIDDEN` (pat_auth.py, PM 2026-08-27).
- `/fx` — `GET /convert` preview (nearest-previous daily rate).
- `/goals` — CRUD + archive; `/{id}/contributions` CRUD; `/{id}/progress` series. List response carries `free_balance_basis` (`average|declared|none`) + `free_balance_months_with_data`: free balance = avg over the last-3-full-months window with the DENOMINATOR = months that HAVE data (income>0 or expense>0 or unconverted>0) → else the declared `monthly_income_minor` → else 0. Ladder + counter live in `domain/goals.py` (`months_with_data`, shared by the amount and the basis so they cannot disagree); assembler returns frozen dataclass `GoalPortfolio`.
- `/goals/{goal_id}/items` (goal-planner, 0011) — the plan tree. GET returns a FLAT list ordered (depth, sort_order, id) — the client builds the tree; every node carries SERVER rollups: `children_sum_minor` (sum of children bubbles up, own amount is only a ceiling — `ceiling_exceeded` is a FIELD, not an error), `paid_minor` (+`paid_unconverted_count`), `planned_unconverted_count` (no rate → counted, never summed as zero), `eff_deadline`+`deadline_inherited` (two-level COALESCE parent→goal computed on READ; the `deadline` column stays NULL, so moving the goal's deadline moves every inherited date), `files_count`/`subtree_files_count`. Limits in Settings: `goal_item_max_depth=6`, `goal_items_max_per_goal=500`, `goal_item_files_max_per_item=10`. Cycle/depth refused pre-write in ONE ancestor walk (`GOAL_ITEM_CYCLE`/`GOAL_ITEM_DEPTH_EXCEEDED`); the CONCURRENT re-parent race is held by DB trigger `trg_goal_items_no_cycle` (pg_advisory_xact_lock on goal id), whose check_violation maps to the SAME 422, never 500. `GET /goals/upcoming?days=1..90` is declared BEFORE `/goals/{goal_id}` (route-order landmine); rows are context-complete (goal, parent, currency, paid, reminder_date). Payment link lives on transactions: `goal_item_id` — expense-only (422 `GOAL_ITEM_EXPENSE_ONLY`, CHECK in 0011), foreign/missing node → 404 no-oracle, ON DELETE SET NULL (deleting a node UNLINKS payments, never deletes them); tx filter `?goal_item_id=` matches the node's SUBTREE.
- `/goals/{goal_id}/items/{item_id}/files` — receipts-style: POST presign PUT slot → POST confirm (server HEAD to MinIO: missing object → 409 `FILE_NOT_UPLOADED`, >5MB → 422 `IMAGE_TOO_LARGE`; MinIO down → 503 `STORAGE_UNAVAILABLE`) → `view_url` minted ONLY for `uploaded=true` and only in the files GET (the tree carries counters, not URLs — a 500-node plan must not mint thousands of presigned URLs). Node/subtree delete removes the objects from MinIO best-effort in a background task.
- `/profile` — GET (PAT-readable) / PATCH (JWT-only, per-field omit/null/value). PATCH takes `language`, `country`, and since base-currency scope `base_currency` (explicit null → 422 `BASE_CURRENCY_REQUIRED`; membership vs `SUPPORTED_CURRENCIES` → 422 `CURRENCY_NOT_SUPPORTED`, case-sensitive) + `monthly_income_minor` (null clears; ge 0, le MAX_MINOR_AMOUNT). A base switch is DISPLAY-only: no snapshot recompute, no data touched (`tx_totals` bucket order already prefers the stored snapshot); it also CLEARS `monthly_income_minor` in the same transaction — the client re-declares explicitly.
- `/recurring` — template CRUD (no pagination/filters by design, D10). `account_id` required (materializer books onto it); `kind` stays expense|income — recurring transfers unsupported in v1 (422). PATCH can MOVE a template to another account (B3): currency restamped from the new account, "new account + old currency" refused whole (`ACCOUNT_CURRENCY_MISMATCH`), watermark untouched. A move ACROSS currencies must carry `amount_minor` in the same PATCH — 422 `AMOUNT_REQUIRED_ON_CURRENCY_CHANGE`, checked BEFORE the currency-echo gate (the stored integer is minor units of the OLD stamp; restamping alone would silently redefine what the job books every period). `start_date` (0010, nullable): future start seeds the watermark to start−1 so nothing books earlier; too-early → 422 `START_DATE_TOO_EARLY` (floor: create < today-UTC; PATCH ≤ min(watermark, today) — no silent clamp); `START_DATE_AFTER_END_DATE` is the SAME string code on create and PATCH (effective pair vs stored values); explicit null clears with watermark = min(current, today); upper bound 2999-12-31 → 422, not a 500 from calendar math. `GET /recurring/upcoming` (`days` 1–90, default 30; PAT allowlisted): UNmaterialized charges with dates ≥ today-UTC only (booked-today rows excluded via the watermark), paused excluded, end_date cuts, sorted by date then created_at; same `domain/recurrence.py` helper as `next_due_on`, so the two can't diverge.
- `/limits` — `GET` (month-scoped, with spent), `PUT`/`DELETE` per category.
- `/stats` — `/summary`, `/monthly` (trailing window, NOT period-scoped), `/top-merchants`; period grammar in query (month|quarter|year|custom). AUTH-FIRST param order is load-bearing.
- `/receipts` — `POST` (presigned MinIO PUT, 201; 30/min per user), `GET /{id}` (poll), `POST /{id}/parse` (202, claim via UPDATE…RETURNING; 10/min;100/day per user). Both `ReceiptRead` responses carry `view_url`: a presigned GET minted per read (TTL `s3_presign_get_ttl_seconds`), null while `pending` — only a status past pending proves the object exists, since the parse claim is gated on a HEAD 200 (`_UPLOAD_PROVEN_STATUSES`); no read ever does a HEAD of its own.
- `/statement-imports` (0013, statement-import scope) — импорт выписки Приорбанка. POST multipart (file+account_id+format; ЕДИНСТВЕННЫЙ multipart-роут API, 10/min) — cp1251 декодирует сервер, парсит, матчит, 201 = сессия со счётчиками; GET `/{id}` — счётчики в ДВУХ разрезах (`by_match_status` = что нашлось, `by_decision` = что сделает apply); GET `/{id}/rows` (offset/limit ≤ 200, фильтр `match_status`; RowRead несёт деньги В ФОРМЕ ТРАНЗАКЦИИ (§10.1: amount_minor+currency+original_*), типизированный `fee_minor`, `merchant` ТРЁХЗНАЧЕН: имя, вырезанное парсером из описания | `""` — парсер посмотрел и мерчанта в строке нет (сбор, обмен: транзакция создастся БЕЗ мерчанта, предложение в имя не превращается) | null — формат имён не выделяет вовсе, описание и есть имя (весь Приорбанк), и ВСТРОЕННЫЕ `candidates`-мини-строки — ноль дозапросов с экрана); PATCH `/{id}/rows/{row_id}` → 200 с обновлённым RowRead (точечный кеш-апдейт клиента); POST `/{id}/rows/bulk-decision` (одно решение всем строкам статуса → сессия); POST `/{id}/apply` (решения строк, одна БД-транзакция, отчёт ТОЛЬКО в теле ответа — §10.6, персистентности нет); GET `/{id}/replace-preview?from=` (сервер считает удаляемое + гибнущие связи чек/цель/шаблон + «переводы останутся»); POST `/{id}/replace` (body: `from_date` + `confirm_deleted_total`); DELETE `/{id}` (только parsed, 204); GET `/formats` — ключи реестра `PARSERS` в порядке реестра (`{"formats": [...]}`, `StatementFormatsRead`), объявлен ДО `/{import_id}` — веб наполняет поле «Банк» с сервера, новый банк не требует релиза клиента. Жизненный цикл: parsed → applied|replaced (дальше всё → 422 `IMPORT_FINISHED`); новая загрузка по тому же счёту вытесняет предыдущую parsed-сессию. Replace НИКОГДА не удаляет transfer-строки (одна строка = история двух счетов; их число в preview отдельно). MCP — НЕТ для всех девяти маршрутов, механикой fail-closed allowlist (маршруты без `@mcp_tool`/`@pat_reachable` недоступны токеном по построению): apply/replace — необратимые массовые мутации без экрана информированного подтверждения у агента, остальное — полу-flow, ведущий только к ним (архитектура §6).
- `/advisor` — `POST /ask` SSE stream (`response_class=StreamingResponse`, no JSON 200 arm — O-8); `Depends(require_ai_configured)`; 5/min;20/day per user (`user_rl_key`).
- `/tokens` — PAT management (5.6): POST mint (plaintext returned ONCE, only SHA-256 stored) / GET list (metadata only, never the string) / DELETE `/{id}` soft-revoke — all JWT-ONLY (`current_active_user` imported straight from auth.py: a PAT can never mint or revoke tokens). Single exception: `GET /tokens/self` is PAT-accessible, returns `{id, scope}` of the calling token (MCP startup introspection). NO rate limit on POST yet — backlog MINOR-2 (`.tasks/mcp-server/review-s1.md`).

## Top-level helpers
- `ai_gate.py` — `require_ai_configured`: 503 `AI_NOT_CONFIGURED` when `anthropic_api_key` empty. ONE key shared by receipts+advisor. Receipts call it INLINE (preserves 401-before-503 and quota counting); advisor uses `Depends` (unkeyed 503 consumes no quota).
- `rate_limit.py` — process-global slowapi limiter; per-app enable/limits via contextvar primed by `prime_rate_limit`; storage isolated per app by `rate_limit_scope` uuid key prefix; headers disabled; 429 body `{"detail": "RATE_LIMITED"}`.
- `category_access.py` — user-scoped category load; foreign/missing → one `None` path (no-oracle).
- `transaction_guards.py` — the transactions router's "resolve a referenced id or refuse" policies (category/receipt → 422, account/goal-item → 404 no-oracle, archived + deposit-spending refusals, `resolve_goal_item_subtree`); the ONE place those guard ORDERS are stated.
- `transaction_wire.py` — row → `TransactionRead` (pure, no session: the replay arm returns a stored transfer without re-reading accounts) + the two derived rate strings.
- `account_access.py` — same pattern for accounts: foreign/missing → 404 `ACCOUNT_NOT_FOUND`; guard ORDER load-bearing: not-found BEFORE archived (a foreign archived account must answer 404, never leak `ACCOUNT_ARCHIVED`).
- `goal_item_access.py` — `load_own_goal` / `load_own_goal_item`: user-scoped, foreign/missing → one 404 `GOAL_ITEM_NOT_FOUND` path; guard ORDER load-bearing: not-found BEFORE `GOAL_ARCHIVED` (a foreign archived goal answers 404, never leaks existence).
- `pat_auth.py` — ONE dependency `current_user_jwt_or_pat`, used by ALL data routers (categories/transactions/accounts/fx/goals/recurring/limits/stats + `GET /profile` ONLY — its PATCH and auth/users/tokens/receipts/advisor stay JWT-only); sniffs `Bearer bgt_pat_` else delegates to the stock JWT path. PAT-branch gate ORDER is load-bearing (review-s1 MAJOR-1): hash lookup (missing==revoked==inactive-owner → one 401 `TOKEN_INVALID`, no oracle; NOT audited — no token row to FK) → stash `request.state.pat` (so 403/429 refusals DO get audited) → per-token rate limit 429 (`pat_read_rate_limit` 60/min, `pat_write_rate_limit` 20/min; direct limiter-storage hit, NOT decorators) → fail-closed allowlist of (method, route.path_format) pairs → 403 `TOKEN_ENDPOINT_FORBIDDEN` (the ONLY DELETE pair is `/transactions/{transaction_id}`; accounts got exactly GET/POST/PATCH pairs — no DELETE exists to allow) → scope gate → 403 `TOKEN_SCOPE_READONLY` (GET=any scope, writes need `full`) → 60s-debounced `last_used_at` UPDATE.
- `pat_audit.py` — ASGI middleware: one `pat_audit_log` row for EVERY request carrying `request.state.pat`, including gate refusals; own short session, insert failure never fails the request; `entity_id` from the path param (PATCH/PUT/DELETE) or the POST 2xx response body (only case where the body is buffered); stores the route TEMPLATE, never the raw URL. Viewing is SQL-only in v1 (example query in packages/mcp-server/README.md).
- `auth.py` (fastapi-users wiring), `config.py` (Settings, all env), `db.py`, `enums.py`, `openapi_export.py` (contract exporter).

## services/
- `advisor.py` — Anthropic streaming ask (Sonnet `advisor_model`, 2048 tok, 120s).
- `advisor_context.py` — PURE context builder: 3-month aggregates + goals; never raw transactions.
- `fx_rates.py` — `FxRateFetcher`: frankfurter (EUR-cross) + NBRB (BYN/RUB); base URLs are settings (stub-able).
- `fx_jobs.py` — `fetch_daily_rates` job + `catch_up_needed` boot probe.
- `fx_lookup.py` — nearest-previous-date rate lookup.
- `receipt_parser.py` — Haiku OCR pipeline: size gate 5_000_000 B (`IMAGE_TOO_LARGE` 422 pre-claim), claim, parse, error taxonomy; stale re-claim after 300s > 90s timeout.
- `recurring_jobs.py` — `materialize_due` (idempotent daily materialization). Books onto `tpl.account_id` verbatim: the archived-account guard is CREATE/PATCH-time only, so a template whose account is archived AFTERWARDS keeps materializing onto it — a DECISION (B2/MINOR-1), not an oversight. Precedent: an archived category keeps receiving rows too; silently skipping in the scheduler would drop money with no user-visible refusal.
- `goal_plan_reads.py` — ALL recursive CTEs of the plan tree in one module: `read_goal_tree`, `read_upcoming_deadlines`, `paid_by_goal`, `goal_plan_totals`, `subtree_item_ids`, `ancestor_ids`, `subtree_height`. One query per screen (no N+1 over nodes); item-currency → goal-currency via nearest-previous rate with a per-call rate cache; a manual `converted_minor` WINS over auto-conversion, explicit null = clear+recompute, omit = keep.
- `statement_import/` — `priorbank.py` (cp1251, `;`, десятичная запятая, две секции контракт/карта, пропуск итогов, «Заблокированных» и нулевых оборотов), `credo.py` (xlsx через openpyxl read-only: деньги ТОЛЬКО из текстовых ячеек — числовая → отказ, даты — serial/datetime, знак = какая из колонок Turnover (DB)/(Cr) заполнена, САМОПРОВЕРКА по остатку `balance[i]=balance[i-1]−DB+Cr` + итоги листа, мерчант и пара `<amount> <CCY> <dd.mm.yyyy>` из описания — имя только после известного грузинского префикса, иначе `""` и НИКОГДА None; неизвестная грузинская фраза = данные, а не ошибка), `matching.py` (чистая: строки+кандидаты → exact/similar/new, без IO), `fingerprint.py`, `apply.py` (мерчант транзакции = колонка `merchant` строки; `""` → `clean_merchant` → NULL-мерчант, только NULL-колонка откатывается к описанию; та же пара читается `categories.py` как ключ merchant-карты — `types.display_name`, одна функция на оба конца, пустой ключ обе стороны карты пропускают), реестр `PARSERS` в `__init__.py` — второй банк = новый модуль + строка реестра, универсальный парсер не строим. Два инварианта дороже остального:
  - **Идемпотентность = отпечаток, и ничего кроме него.** `client_id` каждой строки = uuid5(замороженный `NS_STATEMENT_IMPORT`, канон `<версия>|…|occ_index`), где `occ_index` нумерует ОДИНАКОВЫЕ строки внутри файла (не номера строк — те ломались бы при перекрытии периодов). Повторная загрузка/apply не создаёт дублей ПО ПОСТРОЕНИЮ (B-1 replay транзакций + частичный уникальный индекс), а не потому что матчер угадал. Версия канона — свойство ФОРМАТА (`FINGERPRINT_VERSIONS`: `prior:v1`, `credo:v1`; ключи обязаны совпадать с `PARSERS`, пинится тестом): правка парсера, меняющая его канон, ОБЯЗАНА поднять свою версию — молчаливая смена переимпортировала бы всю историю как «новое», а общая версия дала бы это сделать чужому банку.
  - **Подтверждение replace сверяется с САМИМ удалением.** DELETE идёт с RETURNING, `confirm_deleted_total` сравнивается с реально исчезнувшими строками в той же транзакции — никогда со счётчиком, взятым раньше (его мог обесценить параллельный write). Расхождение → полный rollback (ничего не удалено и не создано) + 422 с ОБОИМИ числами. Replace игнорирует построчные решения (жест «заменить диапазон» целиком); отпечаточный проход идёт ПОСЛЕ удаления, выжившие вне диапазона строки отвечают `already_existed`, а не дублируются.
- `storage.py` — MinIO presign PUT/GET (bucket `receipts`).
- `tx_read_query.py` — read params → filters (`read_filters`, shared by list+export so they cannot drift; LIKE metachars escaped) + `ORDER_BY` map. Never raises: read filters match nothing, they do not refuse.
- `tx_export_csv.py` — the export file format: frozen column order (append-only), cells at each currency's own exponent, BOM+RFC-4180 batches over a server-side cursor; opens its OWN session (a streamed body outlives the request's).
- `goal_reads.py` / `profile_reads.py` / `tx_totals.py` — read helpers (progress, self-healing profile, summary math). `tx_totals.py` is THE single place transfers are excluded from money aggregates (`kind != transfer` in all three grouped series + `_bucket_three_rows`); every rider (stats, limits, tx summary, goals free balance, advisor context) is clean by construction — do NOT re-filter downstream.

## domain/ (pure, no IO)
- `money.py` — minor↔decimal at currency exponent; exponent table AND `SUPPORTED_CURRENCIES` (USD/EUR/RUB/BYN, base-currency membership gate) = SERVER TWINS of `packages/shared/src/currencies.ts`, drift pinned by `tests/test_currency_exponents_sync.py`.
- `goal_plan.py` — plan math: `effective_target` (no items → `target_minor` as today; `has_items` → sum of items; `final_cost_override_minor` wins, the disagreement with `planned_total_minor` stays VISIBLE — both are response fields on GoalRead), `remaining_to_find` (= effective − paid − saved, served NEGATIVE when overshot, never clamped; paid and saved are NEVER summed into one number), `ceiling_exceeded`, `reminder_date` (intent is stored: `remind_on` is a fixed date, `remind_days_before` rides the EFFECTIVE deadline; exactly-one-or-none CHECK, both in one request → 422 `GOAL_ITEM_REMIND_CONFLICT`).
- `deposits.py` — interest math over a transfer TIMELINE (principal segments seeded by `starting_balance_minor` + transfers, built in `services/deposit_reads.py`): actual/365, Decimal, `_quantize` ROUND_HALF_UP; capitalization `none|monthly|quarterly|at_maturity` (interest joins the body at boundaries; `principal = max(body + capitalized, 0)` — a negative body earns nothing). Manual anchor: accrual restarts FROM `(override_as_of, override_minor)` — the anchor value is returned unchanged when no time has passed; ends at `min(as_of, term_end)` (maturation freeze). `after_tax_minor` = gross − ROUND_HALF_UP(gross × rate/100), `None` without a rate — the client never computes it.
- `periods.py` — /stats period grammar (year envelope); `fx.py` conversion math (Decimal); `goals.py` progress; `merchant.py` normalization; `recurrence.py` due-date math.

- `0006` recurring_templates + category_limits.  `0007` personal_access_tokens (SHA-256 `token_hash` unique, `scope` CHECK read|full, soft `revoked_at`) + pat_audit_log (append-only BigInt PK, composite ix (token_id, occurred_at)) + `transactions.client_id`.
- `0008` accounts (user-owned, NOT NULL user_id, boolean `archived`) + transactions `account_id` NOT NULL / counter-triple nullable + rebuilt `kind_valid` (expense|income|transfer) + transfer CHECKs (counter pair present iff transfer, no category, no base pair, counter != account, counter_amount > 0) + recurring_templates `account_id` NOT NULL. Tables were EMPTIED before this migration (PM decision) — no history backfill exists.
- `0009` tx original-amount pair + profile `country`/`language` (i18n scope).  `0010` recurring_templates `start_date` (nullable, no server_default, NO backfill — legacy rows stay NULL, watermarks untouched).

- `0011` goal-planner in five blocks: `goal_items` tree (COMPOSITE FK `(parent_id, goal_id)→(id, goal_id)` — a parent is provably in the same goal; ON DELETE CASCADE over the subtree) + `goal_items_no_cycle()` trigger (advisory lock, see routers) + `goal_item_files` + goals `initial_budget_minor`/`final_cost_override_minor` + `transactions.goal_item_id` (expense-only CHECK, partial index, ON DELETE SET NULL). NO backfill: existing goals get no items, manual `target_minor` behaviour unchanged until the first item.
- `0012` deposits: `deposits` table (1:1 FK `account_id`, ix on `user_id`; CHECKs: rate ≥ 0, tax 0..100, `term_end > opened_on`, override pair both-NULL-or-both-set) + `ck_accounts_type_valid` DROPPED and recreated under the SAME NAME as `type IN ('card','cash','deposit')` — enums.py `AccountType` order must emit byte-identical SQL; downgrade restores the two-value CHECK.

- `0013` statement-import: `statement_imports` (сессия предпросмотра: счёт, период, статус parsed|applied|replaced, счётчики) + `statement_import_rows` (разобранные строки: решение, матч, `fee_minor`, `raw` JSONB, candidate-ids) + `bank_category_map` (user-scoped «категория банка → наша», learning при apply — прецедент `merchant_category_map`).
- `0014` `statement_import_rows.merchant` (nullable String(255), без backfill и server_default): имя магазина, вырезанное парсером из описания-предложения. Колонка обязана пронести ТРИ значения (`types.display_name`): имя | `""` («мерчанта в строке нет», хранится пустой строкой и НЕ схлопывается в NULL) | NULL = «описание и есть имя» (все строки Приорбанка) — прежнее поведение не двигается. Колонка, а не ключ в `raw`: значение решает, под каким именем apply создаст транзакцию и по какому ключу читается merchant-карта, поэтому оно ОБЯЗАНО быть видимым в предпросмотре (`RowRead.merchant`).

## Scheduler (lifespan, APScheduler)
- Built only if a gate is on; whole pytest suite runs with both gates false (no scheduler object at all).
- fx: cron 17:30 UTC (`FX_SCHEDULER_ENABLED`, `fx_fetch_hour/minute_utc`), misfire grace 3600 coalesced; boot catch-up probe → run-now job; backfill 400 days on empty provider.
- recurring: cron 00:30 UTC (`RECURRING_SCHEDULER_ENABLED`), `materialize_due`; plus an UNCONDITIONAL run-now boot catch-up job (D5) — a restart materializes today's due occurrences immediately.

## CORS (app.py, gotcha)
- `allow_methods` is a HAND-LISTED verb set — a new HTTP verb served to the browser MUST be added there or every preflight for it gets 400 (bit us live: `PUT /limits` shipped while the list ended at DELETE). Pinned by `tests/test_cors.py::test_preflight_allows_every_verb_the_api_serves`, which derives the verb set from the exported OpenAPI.

## Error envelope
- Domain errors: `HTTPException(detail="STRING_CODE")` — e.g. `CATEGORY_NOT_FOUND`, `CATEGORY_ARCHIVED`, `CATEGORY_NOT_EXPENSE`, `GOAL_NOT_FOUND`, `CONTRIBUTION_EXCEEDS_SAVED`, `RECEIPT_PROCESSING`, `IMAGE_TOO_LARGE`, `LOGIN_BAD_CREDENTIALS`, `REFRESH_TOKEN_INVALID`, `RATE_LIMITED`, `AI_NOT_CONFIGURED`, `STORAGE_UNAVAILABLE`, `TOKEN_INVALID` (401), `TOKEN_ENDPOINT_FORBIDDEN`/`TOKEN_SCOPE_READONLY` (403), `TOKEN_NOT_FOUND`, `ACCOUNT_NOT_FOUND` (404 no-oracle), `GOAL_ITEM_NOT_FOUND` (404 no-oracle), `GOAL_ARCHIVED`/`GOAL_ITEM_CYCLE`/`GOAL_ITEM_DEPTH_EXCEEDED`/`GOAL_ITEMS_LIMIT_EXCEEDED`/`GOAL_ITEM_PARENT_NOT_FOUND` (422 — body ref, not a path resource)/`GOAL_ITEM_EXPENSE_ONLY`/`GOAL_ITEM_REMIND_CONFLICT`/`GOAL_ITEM_CONVERTED_NOT_APPLICABLE`/`GOAL_ITEM_FILES_LIMIT_EXCEEDED`, `FILE_NOT_UPLOADED` (409), `ACCOUNT_ARCHIVED`/`ACCOUNT_CURRENCY_MISMATCH`/`ACCOUNT_CURRENCY_IMMUTABLE`/`SAME_ACCOUNT_TRANSFER`/`TRANSFER_FIELDS_REQUIRED`/`COUNTER_FIELDS_WITHOUT_TRANSFER`/`KIND_CHANGE_UNSUPPORTED` (422), `DEPOSIT_NOT_FOUND` (404 no-oracle, checked BEFORE archived so a foreign archived id never says `DEPOSIT_ARCHIVED`), `DEPOSIT_TERM_BEFORE_OPENING`/`DEPOSIT_ARCHIVED`/`DEPOSIT_UNARCHIVE_ONLY`/`DEPOSIT_ACCOUNT_TRANSFER_ONLY`/`DEPOSIT_<FIELD>_REQUIRED` (null sent to a non-nullable deposit field) (422).
- Statement-import codes: `IMPORT_NOT_FOUND` (404 no-oracle, оба уровня — сессия и строка), 422 `STATEMENT_TOO_LARGE` (гейт 1 МБ до чтения) / `STATEMENT_PARSE_FAILED` / `STATEMENT_FORMAT_UNKNOWN` / `STATEMENT_CURRENCY_MISMATCH` (тело несёт `statement_currency`+`account_currency` — §10.7) / `IMPORT_FINISHED` / `DECISION_NEEDS_MATCH` (replace_own без matched_tx_id) / `TRANSFER_REPLACE_FORBIDDEN` / `REPLACE_FROM_OUT_OF_RANGE` / `REPLACE_CONFIRMATION_MISMATCH` (тело несёт `confirm_deleted_total`+`deleted_total`).
- 422 pattern: routes declare `_UNPROCESSABLE` with raw `anyOf` [DomainError-schema, HTTPValidationError] — honest union without mangling the generated component.
- No-oracle 404s: foreign and missing ids share ONE code path and a byte-identical body; logout always 204; forgot-password never reveals account existence.
