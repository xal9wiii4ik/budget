## Screens (`app/`, expo-router groups)
- `app/index.tsx` — `/` → redirect to `/transactions`.
- `(auth)/` — login, register (+ group layout).

Every form's Save/Delete/Archive lives in `KeyboardAwareForm`'s `footer` (pinned above the home indicator, D-4); the host `SafeAreaView edges=['bottom']` owns the inset — the footer must NOT add it again.
- Transaction form (mobile-catchup-2) = web's `TransactionFormModal` decisions, minus the converted-to-base section (`base_amount` stays "" → server owns the snapshot). KIND segment FIRST, every label below worded by `features/transactions/kindCopy.ts` (mobile keys; web has its own table). Two amounts: `original_amount`/`original_currency` (spent) and `amount` (charged, optional in pair mode = server converts); the pure rules `isPairMode/spendPrefill/spendCurrencyOptions/migrateAmounts` are `@budget/shared` `originalPair.ts`, the create body is `@budget/api-client` `buildCreateBody` (both moved from web in this scope; web re-exports). Charge ESTIMATE = `GET /fx/convert` (`data/fx.ts`, `qk.fxConvert`) rendered as TEXT with the server's `rate` string — never written into the field; `chargePreview.ts::chargePreviewRequest` returns null while the charged field holds anything (a typed charge always wins, pinned by test). 422 `FX_RATE_UNAVAILABLE` → `originalPairError.ts` → manual-charge mode (`rateGap` remembers the three inputs, derived not synced). `merchant` is diffed EXPLICITLY in onSubmit (`buildTransactionPatch` deliberately emits no merchant key); `receipt_id` likewise (attach/replace/detach → null). Country: folded `CountryField` (filter + 30-chip cap); `lib/countryLabel.ts` is the Hermes seam — `Intl.DisplayNames` is ABSENT on device (probe-confirmed), so labels are "🇬🇪 GE"; sorting uses `Intl.Collator` (present).
- Photo (`features/transactions/AttachPhotoField.tsx`, `data/receipts.ts`): expo-image-picker (`~57.x`, plugin in app.json; Expo Go bundles it and overrides the usage strings) → `POST /receipts` → RAW `fetch` PUT of `fetch(asset.uri).blob()` to the presigned URL (no bearer, `upload.headers` verbatim) → `receipt_id` on the row. KNOWN SERVER GAP: a never-parsed receipt stays `pending` and `view_url` is null → only the in-session local preview shows a picture; a reopen shows a text line (`follow-ups.md` E-1). Detach = native `confirmAction`, link only, no delete endpoint.
- `(app)/recurring` (PUSHED off "More", native header) + `(app)/recurring-form` (modal, `MODAL_PARENT_TAB` → `/recurring`): every template incl. paused/ended, amount signed by kind in the TEMPLATE's own currency, `next_due_on`/`end_date`/a future `start_date`, pause/resume per row; the form is web's TemplateFormModal minus its currency picker — §4 makes the currency the ACCOUNT's, so it follows the picked account and is read-only (web offers a control the server can only 422). Pure modules (`periodicity`/`templateStatus`/`firstCharge`/`upcomingRows`) are verbatim copies of web's, tests left on web's side. `features/recurring/UpcomingCharges.tsx` is the self-contained 30-day widget for the transactions tab (no book-now "+", that is its own scope).
- Transactions tab (catch-up 3 line A): the whole selection is SCREEN state (there is no URL to be the source of truth) — search + category / country / sort + period mode month|all-time|custom, grammar in `features/transactions/txFilters.ts`. `TxSearchField` (350 ms debounce, owns its own text), `TxFiltersSheet` (an RN `Modal` holding a DRAFT applied on "Apply", so a half-composed custom range never becomes a query key; its country list reuses `CountryField`'s filter + 30-chip cap), `TxFilterChips` (per-chip clear; search is not chipped, the box shows it). `SummaryHeader` renders ONLY in month mode — `GET /transactions/summary` is a MONTH aggregate and over an all-time list its totals would read as their sum. Under an amount sort the day headers go (`showsDayGroups`) and each row prints its own date. Editing from a filtered/all-time list passes the ROW's month, so the form finds its row in that month's cached slice (there is no `GET /transactions/{id}`).
- `(app)/category-transactions?id=` (line A) — web's `CategoryTransactionsModal` as a PUSHED screen: it is a place you navigate to and read, so pushing buys iOS swipe-back and Android back for free. Header title = the category's name (set from the screen); it is in `MODAL_PARENT_TAB → /categories` for the same reason the forms are — `usePathname()` drops the `?id=` and the screen without one has nothing to show. Headline = `/stats/summary`'s own `by_category` total, picked by id AND kind (`features/categories/categoryDrilldown.ts`, copied from web — a refund books income against an expense category); that is also why the period is month|custom with NO all-time: the stats period grammar has no all-time unit. Rows are the SAME key and page size the tab builds for {category, period}, so tab and screen share one cache entry.
- Widgets on the transactions tab (wired by line A after B and C landed): `GoalDeadlines` then `UpcomingCharges` (web's order), handed to `TransactionList` as `header` → `ListHeaderComponent`, so they scroll away instead of pinning two cards over a phone viewport. The gate is `isNarrowed`: both read templates and plan items, which carry no account, category, country or note, so a filtered list's widget would lie; all-time and a mere re-sort keep them. `StateShell` repeats the header above the pending / error / empty arms (which render outside the SectionList) — a widget that vanished while the list loaded is the worse behaviour.
- Goals (line C): `(tabs)/goals` — card list headed by `FreeBalanceSummary` (exhaustive switch on `free_balance_basis`; the `none` arm routes to "More", where declared income lives on this client). No progress bars and no charts — deliberate: a bar would force picking one of the three figures. `(app)/goal-plan?id=` PUSHED — `useGoal` + `useGoalItems`, both per-goal so a deep link is self-sufficient; ONE `FlatList` over two datasets behind a segment (plan items | contribution ledger), because a phone cannot nest a second unbounded list inside a scroll view and the summary above is context for both. Modals `(app)/goal-form`, `goal-cost-form`, `goal-item-form`, `contribution-form` (all `KeyboardAwareForm` + footer); every goals route incl. `goal-plan` sits in `MODAL_PARENT_TAB → /goals` — each carries its subject in an `?id=` a pathname drops, and the tab is where a goal is picked again; moving an item is a native `Modal` (`ItemMoveSheet`), not a route — it is a choice about the row underneath, with no text field, and a route would refetch the same tree. Deviations from web, reasons in `plan-mobile-C.md`: goal currency read-only after create (it re-denominates the whole ledger — a decision you read, not tap), item conversion shown as TEXT and sent only if TYPED (D8, same as the tx form), one input per link, row actions inside the expanded details (six ≥44pt targets do not fit across a phone), and item photos WITHOUT `expo-image-manipulator` (no native module without senior-lead) — picker `quality: 0.6` + the same 5 MB pre-check, an oversized original REFUSED in words rather than silently shrunk.

- Root `app/_layout.tsx` — splash held (`SplashScreen.preventAutoHideAsync`) until `coordinator.ready` resolves; guard NEVER evaluates a pre-hydration snapshot. `useAuthListener` clears Query cache on sign-out edge. `runDevProbes()` logs Hermes seam probes (`src/lib/probes.ts`, __DEV__ only, out of vitest graph).

## DI coordinator (`src/auth/coordinator.ts`)
- COPY of web's pattern, not shared (O1/S5): single-flight refresh, reactive-only 401→refresh→retry; all cross-tab machinery deleted (one RN process).
- Imports ONLY `@budget/api-client` — whole core vitest-testable under Node. Platform seams INJECTED: `AsyncTokenStorage` (secure store), `ResumeSubscribe` (AppState), `TimerSeam`.
- Async-hydrate: `hydrate()` once into an in-memory mirror behind the splash gate; after that reads are sync.
- Resume handling (O5/R3): on AppState foreground-resume, a suspended in-flight refresh is waited ≤4000ms then abandoned so the next 401 starts a FRESH flight (the MAJOR stale-flight race fix from 1.8 review: never rebuild state from a captured stale in-flight promise).
- Wiring in `src/lib/api.ts`: two clients — plain `authClient` (auth endpoints, no bearer) and `apiClient` (fetch = `coordinator.authFetch`); baseUrl resolved once at init.

## Secure store (`src/auth/secureStore.ts`)
- ONLY file importing expo-secure-store; key `budget.auth`, JSON TokenPair in OS keychain (never AsyncStorage); corrupt value → logged-out, not crash. Tests inject in-memory fake.

## Base URL (`src/lib/baseUrl.ts`)
- Precedence: `EXPO_PUBLIC_API_URL` override → __DEV__ derive host from Metro hostUri + port 8010 → throw (release without override). No secrets in bundle.

## Data / UI
- `src/data/` mirrors web (queryKeys, categories, transactions, errors, profile, fx, receipts, recurring, plus catch-up 3's `stats` — ONE query, the category headline, since the stats SCREEN does not exist here — and `goals`/`goalItems`/`goalDeadlines`, copies of web's minus the progress SERIES (no chart library); fx is no longer trimmed — `fxConvertQueryOptions` is back for the settings screen's imperative conversion, receipts still have no parse/poll). `recurring` (mobile-catchup-3 line B) is web's module verbatim, invalidation matrix included: writes hit the bare `['recurring']` root that `recurringList`/`recurringUpcoming` deliberately SHARE, and DELETE also invalidates tx lists (the server drops the attribution off rows it already created). `useUpdateProfile` invalidates per changed field: base → summaries + bare `['goals']` + `['stats']`, income → `['goals','list']`. shared patch builders/`buildCreateBody`/ApiError from `@budget/api-client`; HEX pattern etc. from `@budget/shared`. `describeTransactionError` routes `merchant` too; the transfer form sends it to root.
- i18n (`src/i18n/`, mobile-catchup-1): mobile's OWN ~90-key dict (`dict.en.ts` is the key set, `dict.ru.ts` a mapped type over it); `types.ts`/`context.ts` are copies of web's, and so is `t.ts` EXCEPT the plural seam: Hermes has NO `Intl.PluralRules` (D-1 red-screened the accounts+categories tabs), so `selectForm` takes the LANG and calls hand-written CLDR `src/i18n/plural.ts` (a third language must extend it; pinned by `plural.test.ts`). `Intl.NumberFormat`/`Intl.Collator` do work in Hermes and are untouched. Screens use only `useT()`/`useLang()`/`useLocale()`; EVERY formatter and `Intl.Collator` takes `useLocale()` — the device locale is the "English UI, Russian dates" defect. Language = `profile.language` → device (`expo-localization`, isolated in `src/lib/deviceLang.ts`, out of the vitest graph) → 'en'; NO local cache. The PICKER is `features/settings/LanguageSection` (mobile-catchup-3 line B): `useUpdateProfile` seeds `['profile']` from the response and I18nProvider derives `lang` from that query during render, so a switch made HERE applies with no cold restart (device-confirmed). A language changed on WEB still reaches a running app only on the next cold start — nothing invalidates `['profile']` from outside and there is no focus refetch (staleTime 60s). Server-error copy stays shared (`errorMessage()`, @budget/shared) and `describe*Error(error, lang)`; `auth/errors.ts` returns dictionary KEYS. KNOWN GAP: zod messages in `@budget/shared/schemas.ts` are still English.
- MOVED vs COPIED (the standing rule this client follows): `packages/api-client` is where client-shared PURE decisions live — catch-up 3 moved `rowDisplay` (line A) and `buildTree` / `moveTargets` / `goalItemField` / `goalItemPatch` (line C) out of web WITH their tests, and web left re-export files at the old paths, so not one web import line changed (`buildCreateBody` was the precedent). COPIED instead, on purpose: anything that takes a client's own `Translate` (its dictionary is not shared) or whose rule a web test already pins — `realism`, `freeBalanceWindow`, `remindPreview`, `goalItemFileError`, the goal zod schemas, `categoryDrilldown`, `categorySearch`, the four recurring modules. Every copy's header names its original; `touchesGoalPlan` is not even a copied file, it is the one expression it is (`before !== null || after !== null`), inlined next to its reason in `data/transactions.ts`.
- `features/transactions/txFilters.ts` is pure and vitest-tested, but it lives under `features/`, not `data/`, and it OWNS `TX_LIST_LIMIT` (re-exported by `data/transactions` under its shipped name `MONTH_LIMIT`): importing `data/*` would pull React Query — and with it react-native — into the test graph, which the constraint below forbids. One shared limit, because the tab, the category screen and the form's edit-row lookup describe the same slices and two values would silently split every cache entry. Its ONE test pins only what breaks caches: the omit-don't-undefined rule and `toTxSort('date_desc') === null` (the default order is never sent).
- Cache families added in catch-up 3: `['stats']` (line A) — every tx write BLANKET-invalidates it, because any write can move any cached period (an `occurred_at` edit moves a row between two, a category change between two buckets of one) and the client will not re-derive the server's aggregation; it is a no-op until the category screen has been opened. Goal keys are copied WORD FOR WORD from web's `queryKeys.ts`, or the invalidation copied with them would stop hitting the prefixes: item writes → `['goals', goalId]` + `['goals','list']` + `['goals','upcoming']` (a delete also → tx lists), and a TX write that touched a plan → the BARE `['goals']`, because `paid` on the node, its ancestors, the goal and the deadlines widget are server rollups that `['goals','list']` does not cover. Otherwise a tx write invalidates `['goals','list']` alone (free balance is a 3-full-month window; deciding client-side whether a write fell inside it would re-implement the server). `previousGoalItemId` is a REQUIRED mutation variable — the transfer form passes `null`, a transfer is never attached to an item.
- Transfer amount mirror: `mirrorDecision` lives in `@budget/shared` (`amountMirror.ts`) and is wired identically in both transfer forms; mobile mirrors the RAW typed string (`100,5`), normalisation stays in the resolver.
- Components in `src/components/` (LabeledInput — passes `accessibilityLabel ?? label` to its TextInput (D-3), KindSegmented, KeyboardAwareForm (+`footer`), confirm.ts…); features mirror web's transactions/categories lists. SCROLL-TO-FIRST-ERROR (N-1/N-2, mobile-catchup-3 line B) lives in `KeyboardAwareForm`: every rendered `FieldError` registers itself with the wrapper, and a NEW registration (a resolver failure or a `setError` from a 422 — no form calls anything) scrolls the topmost error into view unless it is already visible. Prefilled amounts go through `lib/amountInput.ts::toLocalInputString`, which writes ',' on ru — the mirror of `normalizeAmountInput`, because a ru decimal-pad cannot type the '.' `@budget/shared` emits (N-5).

## Constraints
- Testing: vitest-only under Node — NO react-native/expo import may enter the test graph (DI seams exist for this). No RN component tests.
- Hermes seams, the whole list in one place: `Intl.PluralRules` ABSENT (→ `i18n/plural.ts`), `Intl.DisplayNames` ABSENT (→ `lib/countryLabel.ts`), `Intl.NumberFormat` / `Intl.Collator` / `Intl.DateTimeFormat` present (probes W11 etc., `lib/probes.ts`). Catch-up 3 found NO new one — the filter sheet's country list and the recurring weekday labels go through the two seams above rather than adding a third.
- The `(app)` guard resolves the intended route ONCE per guard mount and latches it (O-1 below). Consequences for any new route inside the group: if its subject lives in a param `usePathname()` drops, add it to `MODAL_PARENT_TAB`; and never infer a route from the GROUP's own `params` — after logout they are the payload of the navigate that created the group.
- Simulator QA via idb + Expo Go (see infra.md); full Xcode absent on this machine — manual checklist in `.tasks/mobile-mvp/qa-mobile-checklist.md`.

## Recent defect fixes (all pinned by tests)
- TC-8 (deep-linked `next` across login) — THREE layers, all needed: (1) `src/auth/intendedRoute.ts`: `usePathname()` is WRONG at redirect time (router store written post-commit; cold start holds `/`); resolve from `useRootNavigationState()` — committed chain when it enters `(app)`, else the pending navigate payload in `__root.params` (warm arm). (2) Module-level latch (`captureIntendedRoute`/`releaseIntendedRoute`): expo-router's `<Redirect>` re-issues `router.replace` every render, and the teardown render sees an empty `(app)` — unresolvable renders keep the last answer; released on the authenticated edge. (3) `app/(auth)/_layout.tsx` bounce honors `safeNextRoute(next)` instead of hardcoding `/transactions`, so its replace and login's converge (race made harmless). Side effect: logout returns you to the screen you were on.
- O-1 (a deep-linked `next` leaking into a LATER login, and logout landing on Transactions) — ONE cause, found on the simulator: logging out renders the guard twice, and in the second render `(app)`'s children are gone while its own `params` survive — the payload of the navigate that CREATED the group, i.e. the deep link. That shape is identical to the cold-start arm's, so the walk cannot reject it; the LATCH was changed instead (`intendedRoute.ts`): the FIRST resolved answer of an EPISODE wins, an episode being one mount of the guard (`app/(app)/_layout.tsx` hands in a per-mount token). Both device captures are fixtures in `intendedRoute.test.ts`.
- `src/lib/amountInput.ts` (F-1): ru-RU decimal-pad only types ','; `normalizeAmountInput` maps EXACTLY one ','/'.' to '.'; two-plus separators pass through untouched for the shared parser to reject (never guess thousands separators). Field shows what was typed; only the validated value is normalized.
