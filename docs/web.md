## Routes (`src/App.tsx`, pages in `src/routes/`)
- `/login`, `/register` — public (AuthLayout); `/` → redirect `/transactions`.
- Under `ProtectedLayout` (token guard + nav — persistent sidebar from 900px, burger drawer below it whose open state is DERIVED from `location.key`, so a navigation closes it without an effect): `/transactions`, `/categories`, `/accounts` (W1: CRUD + archive + server-computed balances), `/deposits` (deposits W1 — its own screen: deposit money is deliberately NOT among accounts), `/debts` (debts W1, Money group after Deposits — DebtsPage: two open groups by `direction` + a collapsed Closed `<details>`, summary header from the SERVER `summary`), `/recurring`, `/goals`, `/goals/:goalId` (GoalPlanPage — the plan tree), `/imports/:importId` (ImportPage, statement-import S4 — one statement preview session; NO navbar item, entry is a header button on /accounts; F5/deep-link-proof — everything re-read from the server), `/stats`, `/advisor`, `/settings` (PAT tokens, 5.6; Connected AI apps, mcp-remote).
- `/oauth/consent?req=<uuid>` (mcp-remote W1, `routes/ConsentPage.tsx`) — the OAuth consent dialogue: a LEAF route OUTSIDE ProtectedLayout wrapped in `<RequireAuth>` (session required, no nav shell — a third party opened it mid-flow). `GET /oauth/requests/{id}` → app name (self-declared text, React-escaped, labelled as the app's own claim), redirect host, loopback warning, mode radio (default `read`), Allow/Deny → `POST …/decision` → `{redirect_to}` → `window.location.replace` in the mutation `onSuccess` (never an effect: StrictMode would double-fire) and ONLY after the pure `features/oauth/redirectGuard.ts::isAllowedRedirect` (claude.ai origin+path exact, or http loopback by hostname) — a refusal renders the "you can close this tab" arm. 404 `OAUTH_REQUEST_NOT_FOUND` = expired/consumed → "start again in Claude", no Retry. Deny navigates too (`error=access_denied`).
- `*` → NotFoundPage.

## Design system (web-redesign, `src/styles/` + `src/theme/` + `src/components/`)
- **The ONE place a colour value is written is `packages/shared/src/palette.ts`** (`LIGHT_PALETTE` / `DARK_PALETTE`, shared with the phone; dark is NOT an inversion: own surfaces, borders by alpha) — `renderPaletteCss()` turns it into the raw `--l-*` / `--d-*` declarations, which reach the bundle as the virtual module `virtual:palette.css` (a ~15-line plugin in `vite.config.ts`; nothing generated is committed). `src/styles/tokens.css` keeps what is CSS syntax rather than colour — the shadows, the semantic `--color-*` remaps, the scales, the ring, the chart aliases — and its header explains the layout; the contrast table for every pair lives in `.tasks/web-redesign/plan-web.md` and is pinned as thresholds by `packages/shared/src/palette.test.ts`. The theme blocks only REMAP the semantic `--color-*` onto one palette. The dark remap is written TWICE, for `[data-theme='dark']` (explicit pick) and inside `@media (prefers-color-scheme: dark) { :root:not([data-theme='light']) }` (system default), because a media query cannot join a selector list; the two bodies are identical by construction and a token forgotten in one of them shows up immediately as a light-coloured patch in dark mode — and now also as a failure of `src/styles/tokens.test.ts`, which reads the file and asserts every `PALETTE_KEY` in all three blocks plus that every `var(--l-*)`/`var(--d-*)` it references is actually declared; there is still no stylelint. `main.tsx` imports fonts → palette → tokens → global, in that order.
- **Theme**: `data-theme` on `<html>` is the user's explicit `light|dark`; NO attribute = follow the OS — `system` deliberately removes the attribute instead of resolving it, so an OS switch while the app is open is free. The pick lives in `localStorage` under `budget.theme` (`theme/theme.ts` — pure storage + DOM, no React); `theme/useTheme.ts` is `useSyncExternalStore` over one module snapshot plus the `storage` event (cross-tab, the auth channel). The inline anti-flash script in `index.html` reads the SAME key and writes the SAME attribute before first paint (the module bundle loads far too late to avoid a white flash) — keep the two in step. `ThemeToggle` (segmented light/system/dark, `aria-pressed`) sits with `LanguageToggle` in the ProtectedLayout panel footer (the drawer on a phone — the narrow top bar is only brand + burger) and on AuthLayout. On `(pointer: coarse)` every text control is forced to 16px in `global.css`: below that iOS Safari zooms in on focus and leaves the page panning sideways.
- **Primitives** (`src/components/`): Button, Card, Field (+ styled natives Input/Select/Textarea), Badge, PageHeader, Toolbar, EmptyState — thin class-map over tokens plus `...rest`, typed `ComponentProps<'x'>` and NOT `…WithoutRef`: `register()` hands in a `ref` as an ordinary prop under React 19 and it must pass through. Props are one line each in plan-web.md; do not re-derive them from the modules.
- **When NOT to use a primitive**: `Card` renders a `<div>`, so anything that must be a `<section>`/`<article>`/`<li>` (e.g. `features/goals/GoalCard.module.css` — the /goals list is a real list) carries the card metrics in its own module rather than nesting a box that means nothing to a screen reader. `Field` is for the shipped order label → control → hint → error only; a composite whose DOM is not that order (AttachPhotoField, MonthPicker, StatsTotals) writes its own `.label`/`.hint` off the same tokens.
- **Rules that hold the system together**: no hex/rgb and no `px` font size anywhere outside `tokens.css` (a grep over `*.css` is the whole enforcement); amounts carry `className="tnum"` (global `font-variant-numeric: tabular-nums`) and are coloured by MEANING — `--color-income` / `--color-expense` / `--color-transfer`, a neutral total stays `--color-text` — never by the sign of the number; focus is NEVER styled locally (one global `:focus-visible` outline, `--ring`, an outline precisely so no ancestor's overflow clips it); `overflow: hidden` must not go on a surface holding focusable children — it cuts the focus ring (GoalCard, PlanNodeRow say so in place); a DOUBLED class (`.header.header` in the page modules, `.input.input`) is how a screen overrides a primitive by SPECIFICITY, because CSS-module stylesheet order is not a guarantee. Depth is border + surface tone; `--shadow-md` is for things that genuinely float (modal, drawer).
- **Charts** (`features/stats/chartColors.ts`): Recharts puts colours on SVG presentation attributes, which do NOT accept `var(--token)` — so `--color-chart-*` are read with `getComputedStyle(document.documentElement)` and cached per RESOLVED theme (`useTheme` + a `matchMedia` subscription; the attribute is applied synchronously, so the read never returns the outgoing theme). The chart tokens are ALIASES of the semantic ones declared ONCE outside both dark blocks, so a chart follows the theme for free and cannot be forgotten in one of them. They are text-grade colours on purpose: Recharts paints a legend's LABEL with its series colour, and a pastel fill would ship 2:1 text.
- **Font**: Inter Variable, SELF-HOSTED — `apps/web/public/fonts/*.woff2` taken from `@fontsource-variable/inter`, four subsets with that package's unicode-ranges (`src/styles/fonts.css`), so the Cyrillic file downloads only when a Cyrillic glyph is painted. No CDN request in any environment; latin + cyrillic are preloaded in `index.html`, both `-ext` subsets stay lazy (user text only). Licence: SIL OFL 1.1, `/fonts/LICENSE-Inter.txt`.

## Install surface — PWA (web-pwa)
- The site installs to the Home Screen as a standalone app; it needs HTTPS (or `localhost`), so on phones it starts working on the day of the deploy. iOS: Safari → Share → Add to Home Screen (no install button on iOS); Chrome/Android/desktop offer their own prompt. Checked in headless Chrome over CDP: manifest parses, `getInstallabilityErrors` empty, worker `activated`, and with the static server killed a navigation renders `/offline.html`.
- Everything that carries a COLOUR is rendered from `packages/shared/src/palette.ts`, never typed twice: `pwa.ts` (`renderManifest`, `themeColorMetas`, `renderOfflineHtml`) is wired by the `pwaAssets` plugin in `vite.config.ts` — emitted as files at build, answered by a dev middleware, nothing generated is committed. Icons are art and ARE committed: `scripts/make-icons.py` (stdlib only) reads the same palette and writes `public/icon.svg` + `public/icons/*` (192/512 any, 512 maskable, 180 apple-touch). `pwa.test.ts` pins that the manifest names only icons that exist.
- `public/sw.js` is the whole worker. Its fetch side does ONE thing: a failed NAVIGATION gets `/offline.html` (since web-push it also handles `push` / `notificationclick`). It caches nothing else — not the bundle, not the API, not fonts — because a cached bundle that outlives a deploy is the worse failure; network first, always. Registered in `main.tsx` in production only (under `vite dev` only on demand — see Dev experience below). `nginx.conf` serves `sw.js`, `offline.html` and the manifest `no-cache` and gives `.webmanifest` its MIME type (stock nginx would send octet-stream and Chrome would refuse it).
- **Dev experience**: `vite dev` serves `public/sw.js` as-is at `/sw.js` and `pwaAssets` answers `/offline.html`, so the worker installs; `localhost` is a secure context. Nothing registers it on page load in dev — the Settings Enable button registers it on demand, after which it controls dev pages (navigations only, never HMR/modules). Actual delivery needs the VAPID trio in `apps/api/.env`; without it the section shows its server-off arm.
- `theme-color`: two build-time metas gated by `prefers-color-scheme`, which is right while the app follows the OS and wrong after an explicit pick — so `theme.ts::syncThemeColor` writes the computed `--color-surface` into both on a pick and restores the build values on `system`. Status bar on iOS is `default` (its own strip above the page); `viewport-fit=cover` is paid back by `env(safe-area-inset-*)` padding on `.shell`, the top bar, the drawer and the import screen's sticky footer.

## Data layer (`src/data/`, keys in `data/queryKeys.ts` — `qk`)
- One module per API area: transactions, categories, fx, goals, limits, recurring, receipts, stats, advisor.
- Key families (top-level roots are DISJOINT by design — new features get new roots so old predicates never touch them):
  - `['transactions', filters]` list vs `['transactions','summary', month]` — key[1] disambiguation.
  - `['categories', {includeArchived:true}]` — single archived-inclusive source; views filter client-side.
  - `['fx','convert', params|null]` — every input in the key; null = disabled state.
  - `['goals','list',{includeArchived}]` / `['goals', goalId, 'contributions'|'progress'|'detail'|'items', …]` / `['goals','upcoming',{days}]` (the /transactions deadline widget — the same deliberate root-sharing as `recurring/upcoming`, so plan writes and plan-touching tx writes refresh it for free).
  - `['stats','summary'|{monthly:months}|'top-merchants', …]` — period object IS the key member (`StatsPeriodQuery`, exactly one anchor per unit).
  - `['recurring','upcoming',{days}]` (`useUpcomingCharges`, /transactions widget) — the ONE deliberate exception to "new feature = new root": it shares the recurring root so the existing `invalidateTemplates()` (bare `['recurring']`) already refreshes it on create/PATCH/pause-resume/delete, incl. a paused template vanishing from the widget with no reload. Tx mutations deliberately do NOT invalidate it (the endpoint reads templates + `last_materialized_on`); the 00:30 UTC materializer stays unobserved, as on `/recurring`.
  - `['recurring','list']`, `['limits',{month}]` (month-scoped: limit is a calendar-month budget), `['receipts', id]` (no list endpoint; cache removed on modal close).
  - `['tokens','list']` (`data/tokens.ts`) — new disjoint root; no existing mutation invalidates it.
  - `['oauth-request', id]` (`data/oauthRequest.ts`, staleTime Infinity, invalidated by nothing — single-use row) and `['oauth-apps','list']` (`data/oauthApps.ts`) — two NEW disjoint roots (mcp-remote W1). The consent decision invalidates NOTHING on purpose: the grant row is created at CODE EXCHANGE (inside Claude's token request), so at decision time there is no connected app to refresh. Revoke (`DELETE /oauth/apps/{id}`, 204 unwrapped by hand) invalidates `['oauth-apps']` only, also on a 404 (revoked elsewhere); never `['tokens']` — a grant and a PAT are separate rows the server refuses to cross-list.
  - `['push','config']` (`data/push.ts`, web-push W1) — the ONLY cached push entry (server VAPID availability + public key, 1h stale); the browser's own subscription is BROWSER state (`pushManager.getSubscription()`), never cached. The three writes invalidate nothing on success; a 503 `PUSH_NOT_CONFIGURED` invalidates bare `['push']` so the refetched `enabled:false` flips the section to server-off.
  - `['accounts','list']` (`data/accounts.ts`, W1) — ONE archived-inclusive entry feeds the /accounts screen AND every account selector; balances are server fields, so EVERY tx mutation also invalidates the bare `['accounts']` prefix (a money write moves a balance).
  - `['debts','list']` / `qk.debt(id)` (`data/debts.ts`, debts W1) — new disjoint root; ONE status-inclusive entry (`GET /debts` = `{items, summary}`, no `?status=`) feeds /debts, the /transactions deadline widget (`features/debts/debtDeadlines.ts`, the `depositDeadlines` twin — pure date window over the cache, no `/debts/upcoming` endpoint) and the `debt_id` row badge's counterparty index. EVERY debt/repayment write invalidates bare `['debts']` + bare `['accounts']` (a movement IS a transaction row on a real account) + the tx LISTS (`invalidateTxLists`); deliberately NOT summaries/stats/limits (excluded server-side at `tx_totals`), deposits or goals. Nothing outside the family invalidates it: `/transactions` refuses PATCH/DELETE on a movement (422 `DEBT_MOVEMENT_READONLY`) and `TransactionCreate` carries no debt field. No optimistic updates — `summary` is a cross-currency aggregate the client must not recompute. 204s unwrapped by hand (limits/tokens precedent); a 404 on a write also invalidates (gone elsewhere).
  - `['deposits','list']` (`data/deposits.ts`, deposits W1) — new root, DISJOINT from `['accounts']` on purpose (a deposit's hidden ledger never appears in `GET /accounts`, so the two lists never describe the same rows); one archived-inclusive entry feeds /deposits, the transfer form's deposit legs and the deadline widget. `qk.deposit(id)` exists to fix the sub-family shape; `GET /deposits/{id}` has no consumer yet. Deposit mutations invalidate only their own family; EVERY tx mutation blanket-invalidates bare `['deposits']` (`data/transactions.ts` — `balance_minor` is a server rollup over transfers on the hidden ledger, and a PATCH can move a transfer OFF a deposit, so "only when it touched a deposit" is unknowable client-side; a no-op until the list is first fetched).
  - `['imports', importId, 'session'|'rows'|'replace-preview']` (`data/imports.ts`, statement-import S4) — new disjoint root. `rows` carries `{match_status, needs_review}` (BOTH chip filters are data in the key; `offset` stays the pageParam) — they are independent, the server ANDs them, and each combination is its own entry; `useImportRows(importId, {matchStatus, needsReview})` sends `needs_review` only when TRUE (`false` = the absence of the filter, not "the rows AI was sure about"). `replace-preview` carries `{from}` — a moved date is a DIFFERENT entry, never an invalidation of the old answer. Row PATCH answers the updated RowRead and is written IN PLACE into every cached page (`setQueriesData`, untouched rows keep identity so row `memo` works); only the session is invalidated — invalidating an infinite query refetches every loaded page per click. `bulk-decision`'s response IS the session; the rows family refetches wholesale there (one deliberate action). apply/replace go through `invalidateAfterBulkTxWrite` (data/transactions.ts: tx lists + summaries + stats + limits + accounts + `['goals','list']`; deposits deliberately OUT — a statement row is never a transfer) plus bare `['imports', id]`. Cancel (DELETE) REMOVES the family — a refetch would only 404. `['imports','formats']` (bank-format-from-server) sits BESIDE the sessions, not under one: the server's parser registry, 1h staleTime, invalidated by nothing — every bare invalidation/removal in the family is `['imports', <uuid>, …]`, so cancelling an import cannot drop the list of banks.
  - Account filter (W2) is DATA IN THE KEY of transaction lists — a transfer legitimately appears under both of its accounts' filtered keys.
- Invalidation rules (`data/transactions.ts` helpers): tx mutations invalidate lists via predicate `key[0]==='transactions' && key[1] !== 'summary'` PLUS the affected month's summary; plus blanket `['stats']`, blanket `['limits']` (an occurred_at edit can move spent in two months), and the goals family — `['goals','list']` as before, but the BARE `['goals']` when the write touched a plan item (`touchesGoalPlan(previousGoalItemId, responseGoalItemId)`, goal-planner W2): `paid` on the node, its ancestors, the goal and the deadline widget are server rollups over the attached rows, and none of them live under `['goals','list']`. The "before" value is a REQUIRED mutation variable (`previousGoalItemId`), read off the row in hand exactly like `previousOccurredAt` — a detach or a move leaves the OLD node stale and the response cannot say where the row used to be.
- `offset` is the useInfiniteQuery pageParam, NEVER a key member (AM-1.6-a).

## Query client (`lib/query.ts`)
- staleTime 30s, no refetchOnWindowFocus, retry: never 4xx / transient ×2, `networkMode:'always'` for queries AND mutations (navigator.onLine is not evidence about our API; paused=silent-forever-skeleton bug).
- `ApiError`/`throwOnError` re-exported from `@budget/api-client`.
- `lib/queryPhase.ts` — `queryPhase()` → 'loading' | 'unreachable' (fetchStatus 'paused') | 'error' | 'ready'; every screen renders 4 arms; 'unreachable' gets an actionable network alert instead of an eternal skeleton. Do NOT branch on isPlaceholderData (period steps keep dimmed previous data).

## Auth (`src/auth/`)
- `RequireAuth.tsx` (mcp-remote W1) — the ONE session gate, extracted from ProtectedLayout (which is now `<RequireAuth><ProtectedShell/></RequireAuth>`): synchronous token presence → else `/login?next=<pathname+search>` (+`&reason=expired`). `?next=` now also travels through the login page's "create one" link and RegisterPage's "sign in" link, so a brand-new Claude user who lands on `/oauth/consent?req=…` keeps the request across registration.
- `coordinator.ts` — two-client design: plain authClient for `/auth/*` (no bearer/retry), protected client via `authFetch` (bearer + single-flight 401→refresh→retry). Refresh under navigator.locks (`locks.ts`) — cross-tab single flight. AUTH_PATHS never trigger refresh (belt-and-suspenders).
- `storage.ts` — one localStorage key `budget.auth` (JSON TokenPair); XSS exposure = recorded accepted tradeoff. Runtime-narrowed on read; corrupt value → logged out.
- `next.ts` — `safeNextPath`: local absolute path only; rejects `//`, backslash (WHATWG `\`→`/` open-redirect), else `/transactions`.
- `wasSessionExpired()` drives `?reason=expired` on redirect; `useAuthListener` clears Query cache on signed-out edge; `useMe`/`useAuth` hooks.

## Patch-builder discipline
- PATCH bodies are DIFFS vs output-shaped initial values: unchanged → OMIT key, cleared → `null`, changed → value. Builders (`buildTransactionPatch`, `buildCategoryPatch`, `buildRecurringTemplatePatch`) + `emptyToNull` live in `@budget/api-client` (shared with mobile).
- `emptyToNull` at every optional text/select boundary (note, merchant, icon, color, category_id).
- Converted-amount snapshot (`features/transactions/convertedSection.ts`): unchanged→omit, value→number, cleared→null; currency change invalidates the stood converted value.

## i18n (`src/i18n/`, transaction-details-and-i18n W5)
- `dict.en.ts` IS the key set; `dict.ru.ts` is a mapped type over it — a missing key or a plural written as a plain string fails `pnpm typecheck`. Plurals go through `Intl.PluralRules` (ru one/few/many, the 21-vs-11 trap pinned in `t.test.ts`).
- Components use ONLY `useT()` / `useLang()` / `useLocale()` (`i18n/context.ts`); nothing imports the dictionaries directly.
- Language resolves as explicit pick → `profile.language` → `budget.lang` cache → browser (`I18nProvider`). `LOCALE_BY_LANG` (lang.ts) is the ONE lang→locale map.
- **Every** `formatMoney/formatAmount/formatApiDate/formatMonth*/formatQuarterLabel/formatTimestamp` call site passes `{ locale }` from `useLocale()`, as do `Intl.Collator` (`sortForDisplay`), `Intl.DisplayNames` (country list) and `weekdayLabels`. Host-default locale = the shipped "English UI, Russian dates" defect.
- `todayApiDate()` is LOCAL and is for the user's own calendar (default date on a form); anything compared against a date the SERVER decided (recurring `start_date` floor, "due today" in the upcoming widget) uses `todayApiDateUtc()` — `routers/recurring.py:_today()` is UTC, and a local compare disagrees with it for hours around midnight.
- PURE modules stay language-free and return KEYS, not sentences: `originalPair.describeOriginalPairError().messageKey`, `period.unitLabelKey()`, `auth/errors.describeAuthError().messageKey`; `rowDisplay.rowTitle()` takes its two fallback LABELS as an argument; `periodicity.periodicityLabel(template, t, locale)`.

- Server errors stay CODES: `lib/errors.ts` routes code → field, copy comes from `ERROR_MESSAGES` (@budget/shared, shared with mobile). Screen copy lives in `apps/web/src/i18n`.
- KNOWN GAP: zod messages in `@budget/shared/schemas.ts` are still English (changing them touches the frozen mobile client — cross-package call). `features/tokens/tokenFormSchema.ts` is web-only and IS translated (factory over `t`).
