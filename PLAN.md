## Этап 0 — Фундамент

- ✅ **0.1 Монорепо.** pnpm workspaces + Turborepo; каркасы `apps/api`, `apps/web`, `apps/mobile`, `packages/shared`, `packages/api-client`.
- ✅ **0.2 Каркас API.** FastAPI, SQLAlchemy 2.0 async, Alembic, конфиг через env, Dockerfile, `make test` / линтеры.
- ✅ **0.3 Контракт фронт↔бэк.** Генерация типизированного TS-клиента из OpenAPI (`openapi-typescript`) в `packages/api-client`; скрипт регенерации в CI/Makefile.
- ✅ **0.4 Shared-пакет.** Форматирование денег (минорные единицы) и дат, список валют, zod-схемы форм.

## Этап 1 — MVP (веб первым)

- ✅ **1.1 Auth.** `fastapi-users`: register / login / refresh (JWT ~15 мин + refresh ~30 дней в базе), argon2; схема с заделом под OAuth (`oauth_accounts`).
- ✅ **1.2 Модели и миграции.** `users`, `profiles`, `categories`, `transactions` + индекс `(user_id, occurred_at)`; все суммы — `amount_minor` (int).
- ✅ **1.3 API категорий.** Системные (`user_id = null`) + пользовательские; создание, переименование, иконка/цвет, архивирование (не удаление); тип расход/доход.
- ✅ **1.4 API транзакций.** CRUD в одной валюте, фильтры по периоду/категории, сводка за месяц.
- ✅ **1.5 Веб: auth-флоу.** Вход/регистрация, хранение токенов, refresh, защищённые роуты.
- ✅ **1.6 Веб: транзакции и категории.** Список с фильтрами, форма добавления/редактирования, управление категориями, сводка за месяц.
- ⬜ **1.7 Деплой.** API — Docker на Railway/Fly/Render; веб — Vercel/Netlify; CORS только на домены приложения.
- ✅ **1.8 Мобильный клиент MVP.** (симуляторный/ручной QA отложен: нет Xcode; мобилка заморожена до деплоя) Экраны auth, списка/формы транзакций, категорий, сводки — на готовом API; сборка EAS → TestFlight / Internal Testing.

## Этап 2 — Чеки и AI

- ✅ **2.1 Хранилище.** (локальный MinIO; переезд в облако — конфигом) R2/MinIO, приватный bucket, `POST /receipts` → статус `pending` + presigned URL (`{user_id}/{uuid}.jpg`, короткий TTL).
- ✅ **2.2 Распознавание.** (бэкенд готов; живой Haiku-вызов отложен — гейт перед 2.3) `POST /receipts/{id}/parse` → BackgroundTask → Claude (строгий JSON: total, currency, merchant, date, items, suggested_category_id) → Pydantic-валидация → `parsed` / `failed`; поллинг `GET /receipts/{id}`.
- ✅ **2.3 Веб: загрузка чека.** (две кнопки: сохранить без AI / распознать; без ключа — честное «нет ключа») Input / drag-and-drop, загрузка по presigned URL, поллинг, форма подтверждения (молчаливая автозапись запрещена).
- ⏸ **2.4 Мобайл: фото чека.** (мобилка заморожена до деплоя) `expo-image-picker`, сжатие до ~1500px (`expo-image-manipulator`), загрузка, поллинг, форма подтверждения.
- ✅ **2.5 Автокатегоризация.** `merchant_category_map`: запоминание пар «мерчант → категория» из подтверждённых транзакций; ручной выбор перекрывает автоматику.

## Этап 3 — Валюты и цели

- ✅ **3.1 Курсы валют.** (frankfurter + НБРБ, 6 пар, ежедневно + догонка) Таблица `exchange_rates`, ежедневный fetch APScheduler'ом (frankfurter.app и т.п.), конвертация по курсу на дату операции, `Decimal` для курсов.
- ✅ **3.2 Мультивалютность в API.** (снапшот на транзакции, правка пользователя побеждает) Транзакции в своей валюте, агрегаты в базовой валюте пользователя; смена базовой валюты — только отображение.
- ✅ **3.3 Цели: домен.** Чистые функции в `domain/goals.py`: `monthly_needed`, проверка реалистичности против фактического свободного остатка (3 мес.), обратный расчёт дедлайна, приоритеты между целями — с юнит-тестами.
- ✅ **3.4 Цели: API.** CRUD целей, `goal_contributions`, прогресс по месяцам.
- ✅ **3.5 Клиенты: цели и валюты.** (веб готов; мобайл заморожен до деплоя) UI целей с калькулятором и «честным» сообщением о нереалистичности; выбор валюты в форме транзакции (веб + мобайл).

## Этап 4 — Статистика и советник

- ✅ **4.1 API агрегатов.** Расходы по категориям за период, динамика по месяцам, сравнение с прошлым периодом, доходы vs расходы, топ-мерчанты, прогресс целей — SQL-агрегаты, готовые к отрисовке ряды.
- ✅ **4.2 Веб: графики.** Recharts поверх готовых рядов; экраны статистики.
- ⏸ **4.3 Мобайл: графики.** (мобилка заморожена до деплоя) Victory Native XL, те же данные.
- ✅ **4.4 AI-советник.** (веб; без ключа — честный «нет ключа», оживёт с ANTHROPIC_API_KEY) `POST /advisor/ask`: компактная сводка (агрегаты, без сырых транзакций) → Claude → SSE-стриминг; дневной rate-limit (slowapi); чат-UI на обоих клиентах.
- ✅ **4.5 Экспорт CSV.**

## Этап 5 — Полировка

- ⬜ **5.1 OAuth.** Вход через Google/Apple поверх `fastapi-users`.
- ⬜ **5.2 Push-напоминания.**
- ✅ **5.3 Повторяющиеся операции.** (скоуп recurring-and-limits: шаблоны, материализация по watermark, экран /recurring, бейдж на транзакциях)
- ✅ **5.4 Лимиты по категориям.** (скоуп recurring-and-limits: лимит на строке категории с индикацией потраченного, секция бюджетов на /stats, честный разрыв при смене базовой валюты)
- ⬜ **5.6 MCP-сервер.** Доступ AI-клиентов (Claude Desktop/Code и др.) к данным бюджета через MCP. Состав: (a) PAT-бэкенд — таблица personal_access_tokens (user_id, token_hash, scope, revoked_at), POST/GET/DELETE /tokens, выпуск только живой сессией (FULL-tier); (b) веб-«Настройки» с управлением токенами — кнопка «Создать токен», показ строки ОДИН раз с копированием, список с last_used и отзывом (STANDARD); (c) пакет packages/mcp-server — гибрид: динамическая генерация read-инструментов из закоммиченного openapi.json + allowlist + модельные описания + лимиты объёма (STANDARD/FAST); (d) конфиг-докстраница для Claude Desktop/Code. Write-инструменты и HTTP-транспорт — фаза 2 (с деплоем). НЕ отгруммлено.
- ⬜ **5.5 Офлайн-режим** (скоуп mobile-offline: отгруммлен полностью, ждёт старта по команде; Xcode установлен — верификация на симуляторе доступна). expo-sqlite + очередь синхронизации, идемпотентность по client_id.

## Команда агентов

| Агент | Модель | Зона | Когда |
|---|---|---|---|
| `senior-lead` | fable | Оркестрация + обязательное ревью каждого диффа | /groom, /implement, /review_senior |
| `architect` | fable | Схема БД, границы модулей, контракты | Новые таблицы/модули, структурные изменения |
| `backend-engineer` | opus 5 | `apps/api` | Любая задача с изменением бэкенд-кода |
| `frontend-engineer` | opus 5 | `apps/web`, shared-пакеты | Задачи с веб-UI |
| `mobile-engineer` | opus 5 | `apps/mobile` | Задачи с мобильным UI |
| `qa-engineer` | opus 5 | API-тестирование (pytest-список + curl) | Всегда для задач с эндпоинтами |
| `web-qa` | opus 5 | Браузерные пользовательские сценарии | Всегда для задач с веб-UI |
| `mobile-qa` | opus 5 | Симулятор + ручной чеклист для устройства | Всегда для задач с мобильным UI |

Оркестратор — основная сессия (fable): запускает /groom и /implement через senior-lead и дополнительно сам ревьюит итоговый код поверх ревью senior-lead. Код не принимается слепо ни на одном уровне: инженер → ревью senior-lead → QA → code-reviewer → мета-ревью → ревью оркестратора.

Кандидаты на добавление позже: `ui-ux-designer` (общие спеки экранов), `devops-engineer` (CI/CD, когда деплой станет регулярным).
